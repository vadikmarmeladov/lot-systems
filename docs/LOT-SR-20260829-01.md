## 3. PERFORMANCE ANOMALIES

### Bundle Size Risk — Monolithic Components

The following source files exceed safe single-component thresholds:

| File | Size | Risk |
|---|---|---|
| `src/server/scheduled-jobs.ts` | **5,633 lines** | Long init time, no lazy loading |
| `src/server/routes/api.ts` | **~5,617 lines** | Monolithic route handler |
| `src/client/utils/badges.ts` | **8,043 lines** | Loaded client-side on every page |
| `src/client/stores/intentionEngine.ts` | **6,503 lines** | Evaluated at store init |
| `src/client/components/About.tsx` | **~4,889 lines** | Single component, full parse on mount |
| `src/client/components/Logs.tsx` | **~4,506 lines** | Large render tree |

esbuild bundles these as a single `.js` file with no code-splitting configured. For a top-tier SaaS product this creates:
- Initial load penalty (large JS parse + eval time on mobile)
- No tree-shaking of unused widget code on pages that don't need it

**Recommendation:** Enable esbuild `splitting: true` with dynamic `import()` boundaries around heavy widgets and the `About.tsx` / `Logs.tsx` pages.

### Widget Mount Performance

`WidgetErrorBoundary` logs a console warning when any widget exceeds 50ms mount time, but this data is stored only in `window.__LOT_WIDGET_PERF__` — ephemeral and never collected. No baseline or regression tracking exists.

### 5.3 QUALITY IMPROVEMENTS — COMPONENT LEVEL

#### Button.tsx
**Current:** Hardcoded hex colors in the primary button variant.
```tsx
// ❌ Current — brittle, no design token
'bg-[#0080FF] hover:bg-[#0066CC] active:bg-[#004C99] disabled:bg-[#80BFFF]'
```
**Recommendation:** Move to CSS custom properties and map to Tailwind theme tokens. This enables single-source theming across the entire system.
```css
/* Add to index.css */
:root { --color-action: 0 128 255; }
```
```tsx
// ✅ Token-driven
'bg-action hover:bg-action-hover active:bg-action-active disabled:bg-action-disabled'
```

#### Missing Accessibility Attributes
- `Button.tsx` has no `aria-disabled` (relies on `disabled` prop, which removes the element from tab order but should also have `aria-disabled` for explicit screen reader signaling)
- No `aria-busy` / `aria-live` support for loading states
- Loading state pattern is absent from the button API — no `isLoading` prop

**Recommendation:** Add:
```tsx
type CommonProps = {
  size?: ButtonSize
  kind?: ButtonKind
  isLoading?: boolean  // shows spinner, sets aria-busy
}
```

#### WidgetErrorBoundary — No Error Reporting
```tsx
// ❌ Current — errors vanish
componentDidCatch(error: Error, info: React.ErrorInfo) {
  console.error(`[WidgetErrorBoundary] ${this.props.name} crashed:`, error)
}
```
**Recommendation:** Wire to a structured error log endpoint:
```tsx
componentDidCatch(error: Error, info: React.ErrorInfo) {
  fetch('/api/client-error', {
    method: 'POST',
    body: JSON.stringify({ widget: this.props.name, message: error.message, stack: info.componentStack }),
  }).catch(() => {})
}
```
