## 2 // ERRORS & WARNINGS — FINDINGS AT SESSION START

### CRITICAL — `Math.random()` called inside JSX render (System.tsx)

| | |
|---|---|
| File | `src/client/components/System.tsx` |
| Lines | 890 (Intentions cooldown), 939 (Subscribe gate) |
| Severity | HIGH |
| Status | **FIXED** |

Both `Math.random()` calls lived inside IIFEs in the JSX return path. In React 18 concurrent mode, renders can be retried — each retry drew a fresh random value, making `IntentionsWidget` and `SubscribeWidget` visibility non-deterministic. On a fast device, the Subscribe widget could visibly flicker in and out during rapid state updates.

**Fix:** Moved both values into `React.useRef` initialized at mount. The random seed is now stable for the component's lifetime.

```tsx
const intentionsCooldownRef = React.useRef(2 * 24 * 60 * 60 * 1000 + Math.random() * (24 * 60 * 60 * 1000))
const subscribeShouldShowRef = React.useRef(Math.random() < 0.2)
```

### LOW — TypeScript deprecation warnings (TS5101, TS5107)

| | |
|---|---|
| File | `tsconfig.json` (root) |
| Severity | LOW |
| Status | **PARTIALLY FIXED** |

`tsc --noEmit` emits TS5101 (`baseUrl` deprecated) and TS5107 (`moduleResolution=node10` deprecated) — both will stop functioning in TypeScript 7.0. `tsconfig.server.json` already had `"ignoreDeprecations": "5.0"` to suppress these. Root `tsconfig.json` was missing the flag.

**Fix applied:** Added `"ignoreDeprecations": "5.0"` to root `tsconfig.json`.

**Remaining work (future session):** Migrate `moduleResolution` to `"Bundler"` (client) and `"NodeNext"` (server) per TypeScript 5.x best practice, which removes the need for the suppression flag entirely.
