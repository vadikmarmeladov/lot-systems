## WHAT WAS BUILT

### 1. `/email` Log trigger — `src/client/utils/logTriggers.ts`

New pure trigger `email-compose`, keywords `email` / `mail`, envelope emoji
`✉️` — same detector shape as the existing `/prayer`, `/story`, `/qi` triggers.
Fires once per fresh appearance in the log text (existing debounce-by-ref
behavior, unchanged).

### 2. Compose handling — `src/client/components/Logs.tsx`

`/email to <Name>` is parsed out of the live log text with
`/\/e?mail\s+to\s+([a-z][a-z'-]*)/i`; everything else in the entry (minus the
command and the envelope glyph) becomes the letter body. Mirrors the existing
`submitPrayer` / `submitStory` mutation pattern exactly — same loading state,
same inline result panel (`MAIL:` block), same `/system` help-line
convention. No new state-management pattern introduced.

### 3. `POST /api/email` — `src/server/routes/api.ts`

Resolves `<Name>` to a `User` by case-insensitive first-name match (exact,
then prefix) among LOT Community members, excluding self, preferring the
most recently seen match on ambiguity. Delivers by creating a `DirectMessage`
row with the body prefixed `✉️ ` — no schema change, the envelope glyph is
the entire "is this Email vs. a plain DM" signal. Emits on the existing
`direct_message` SSE channel so it rides the same real-time pipe
`DirectMessageThread` already listens on. Logs `email_sent` the same way
`/direct-messages` already logs `direct_message_sent`, for signal parity.
404s with `No one named "X" found in LOT Community.` when no match exists.

### 4. Sync surfacing — `src/client/components/Sync.tsx`

Sync now also listens on `direct_message` and — client-side only, never
broadcast — renders a compact mail notice (`✉️ <sender> <snippet>`) for any
envelope-tagged DM addressed to the viewer. Click-through opens the existing
`/dm/:userId` thread. Regular (non-Email) direct messages are deliberately
left out of this list; Sync gains an ambient "mail arrived" signal, not a
second inbox.

### 5. Cohort / Community wiring — `src/client/components/CohortConnectWidget.tsx`

"Send message" on a cohort match previously routed to the generic Sync tab
with no target user attached — effectively a dead end. It now opens
`/dm/:userId` directly, the same thread a Log-composed `/email` to that
person lands in. One conversation, reached from either surface.

### Data flow

```
Log entry: "...body text... /email to Hitomi"
   │  detectNewTriggers → email-compose
   ▼
Logs.tsx: parse name + body → POST /api/email
   ▼
api.ts: resolve "Hitomi" → User row → DirectMessage.create(✉️ body)
   │  sync.emit('direct_message', {...})
   ▼
   ├─▶ DirectMessageThread (if either party has it open) — existing, untouched
   └─▶ Sync.tsx (receiver only) — new ✉️ notice, click → /dm/:userId
```
