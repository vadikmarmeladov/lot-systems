## WHAT WAS BUILT

### Time tracking on Calendar entries

`CalendarEntry` gained an optional `time: string | null` field (HH:mm),
persisted in the same `calendar_entry` log's `metadata` bag the widget
already wrote (`{ date, time, text, entryType }`) — no server route or
schema change needed, since `Log.metadata` is an open `Record<string, any>`
JSONB column and `calendar_entry` was already allow-listed for display.

- Add-entry form gained a `<input type="time">` next to the text field,
  optional — untimed entries still work exactly as before ("all day").
- Entries now sort date-then-time everywhere (month grid selection list,
  upcoming list) instead of date-only.
- Time renders using the app's existing `isTimeFormat12h` nanostore, so a
  Calendar entry respects the same 12h/24h preference as the Time widget
  and Logs timeline.
- On successful save, a terse inline acknowledgement (`CAL: ENTRY LOGGED`)
  flashes in the widget for ~2.2s — visible confirmation that the entry
  reached the Log, in the same uppercase/tracking-widest idiom as the
  Logs.tsx field-report renderers.

### Calendar Event Toast — military-grade due-time notification

New component `src/client/components/CalendarEventToast.tsx`, mounted in
`System.tsx` next to the existing `EvolutionMilestoneToast`. Forks that
component's shell (fixed-position, self-injected keyframes, visible-tab +
active-route gated 30s poll) but speaks in the Terminal Grid readout
voice used throughout `Logs.tsx` / `SystemProgressWidget.tsx`
(`font-mono text-xs`, `uppercase tracking-widest`, layered opacity,
`tabular-nums`) rather than the softer milestone-toast copy.

```
CAL: EVENT DUE
{ENTRY TYPE}
{entry text}
{date} {time}
```

- Fires when a today-dated, timed `calendar_entry` enters its 10-minute
  due window (now − due-time is in [0, 10] minutes).
- Deduplicated via `localStorage` (`calendar_notified_v1`, capped at the
  200 most recent keys) — a reminder never re-fires once acknowledged.
- Auto-dismisses after 9s or on manual close; positioned top-right so it
  never collides with the bottom-center Evolution Milestone Toast.
- Self-contained: injects its own `@keyframes` under a guarded element ID
  rather than depending on another component having mounted first — a
  reliability fix in kind, even though it's new code, not a regression.
- No new Log event type, no server change, no new DB migration — reads
  the same `/api/logs` feed the widget already subscribes to.

### Logs.tsx — CAL: renderer

The existing `CAL:` field-report block in the Log timeline now shows the
time alongside the date when present (`tabular-nums`), so a scheduled
entry with a time reads identically wherever it surfaces — widget, toast,
and Log archive.

### Docs

`docs/technical/WIDGETS.md` gained two entries in the Core Widgets
section — Calendar Widget and Calendar Event Toast — since the widget
reference guide had no entry for either, despite Calendar already being
mounted in `System.tsx`.
