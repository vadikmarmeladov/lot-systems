## BUILD — Astrology Widget v2 (Personalization + QIE Pattern 152)

### astrology.ts — getWallClockDate() (client-side timezone parity)

```
Client-side equivalent of the server's toWallClockDate() (getLogContext(),
src/server/utils/logs.ts): builds a Date whose getHours()/getMonth()/getDate()
reflect wall-clock time in a given IANA timeZone regardless of runtime clock.
Server uses dayjs().tz(timeZone) (timezone plugin loaded server-side only);
client reads the same six fields via Intl.DateTimeFormat(..., { timeZone })
.formatToParts() — no new dependency, isomorphic behavior, same output shape.
Falls back to device-local `new Date()` when no timeZone is known.
```
