03 // BUILD
--------------------------------------------------------------------------------
COMMAND:    npm run build  (yarn run client:build && yarn run server:build)
RESULT:     OK
NOTES:      Implemented LOT Email as an addressing layer on the existing
            ChatMessage model/table/SSE-channel/Sync UI rather than a new
            messaging subsystem:
              - migrations/20260810120000_add-chat-message-recipient.cjs adds
                nullable recipientUserId + kind ('chat'|'email', default
                'chat') to chat_messages.
              - POST /api/email-messages resolves "to <name>" against "LOT
                Community" (defined here as the existing Lot-Chat-eligible
                membership — Usership/Onyx/Legacy/RND/Admin — since no
                separate Community directory exists), creates a ChatMessage
                with kind:'email', emits the same 'chat_message' SSE event
                Sync already listens for, and writes a Log row
                (event:'email_sent') exactly like POST /chat-messages does.
              - Logs.tsx evaluates "/email to <name>" against the entry's
                DEBOUNCED text (not raw keystrokes) — the existing
                logTriggers.ts instant-fire model was found to race ahead of
                the recipient-name argument for a command shaped like this
                one; documented the deviation inline rather than force-fitting
                it. Seeded the dedupe ref from the log's already-saved text so
                a page reload cannot re-send a command that was already sent
                in a prior session.
              - Sync.tsx renders "✉ TO <NAME>:" ahead of an email message's
                body; Logs.tsx renders a "MAIL:" block for the audit-trail Log
                row, matching the existing "COMM:" pattern used for
                chat_message logs.
            No new table, no new SSE channel, no new UI surface.
