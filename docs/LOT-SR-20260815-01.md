## BUG FOUND AND FIXED DURING PORT

```
ChatCatalystWidget.tsx handleEmail() called `stores.goTo('log')`. The
router's Routes type (src/client/stores/router.ts:11-20) only defines
`logs` (path /log), not `log` — a stale reference from when the source
branch was written in June, silently wrong because `goTo` is generically
typed `<P extends keyof Routes>` and esbuild does not typecheck. Fixed to
`stores.goTo('logs')`. Root cause class: source branch predates months of
route/type churn; this port is the reason `npx tsc --noEmit` was run
against the full client tree in addition to the repo's own build script
(see CHECK B) — the standard `npm run build` alone would not have caught it,
since tsconfig.server.json only typechecks src/server + src/shared.
```

## COMPONENTS BUILT

```
✉ /email to [Name] [message]  — also /mail, and emoji triggers ✉️ ✉ 📧
  Detected by the existing pure logTriggers.ts detector (same mechanism as
  /qi, /assembly, /prayer — no new parsing infrastructure). Regex extracts
  a 1-2 word name and a free-text body; renders an inline "✉ MAIL:" Block
  directly under the Log composer with an editable body, Send, and Cancel.

Sync inbox — Sync.tsx gained a Chat | Mail(N) tab strip. Mail tab renders
  EmailInbox.tsx: 50 most recent messages, unread rendered at full opacity/
  bold, click expands the body and marks read. New arrivals stream in via
  the existing SSE bus (sync.listen('lot_mail', ...)) — the server routes
  the event to the recipient only (api.ts:390-395, checked against
  req.user.id before broadcast).

Cohort integration — ChatCatalystWidget (the "Connect:" widget that
  surfaces a suggested cohort member — this repo's actual LOT Community/
  cohort-matching layer; there is no separate "dating" feature to wire
  into, confirmed by research this session) gained a ✉ Mail button beside
  its existing connect action. Clicking it navigates to Log, pre-fills
  the textarea with "/email to <Name> ", and fires a QIE signal
  (recordSignal('journal', 'connection_accepted', {type:'email', ...}))
  so the interaction feeds the same behavioral-pattern engine as every
  other cohort touchpoint.

Recipient resolution — POST /api/mail resolves the typed name via
  case-insensitive first/last-name match (Op.iLike) against User, not a
  user-ID picker — matching the "/email to Hitomi" example literally: type
  a first name, LOT Community resolves it. 404 with a human-readable hint
  if no match; 400 on self-send.

Access — gated behind the same canAccessChat check as the rest of Sync
  (Usership / Onyx / Legacy / R&D / Admin, non-suspended) — consistent with
  the "uniform participation gate" doctrine folded in SR-20260719-01 (R9).
```
