## 1. EXECUTIVE SUMMARY

The **COSMO CIA** (Compact Intelligence Apparatus) is a physical edge device that extends the LOT Systems behavioral operating system into the material world. It is not a smartwatch. Not a phone accessory. A dedicated single-purpose instrument: a 40 × 40 × 5 mm stainless steel pager that receives AI-generated notifications from `lot-systems.com`, reads environmental context via onboard sensors, and sends a single logged signal back to the site's Log tab when the operator presses its one button.

**The device does one job per second: it listens, it shows, and it records.**

## 2. PRODUCT IDENTITY & BRAND ALIGNMENT

### 2.1 COSMO CIA — Name & Heritage

The COSMO CIA inherits the COSMO® brand (CEO: Kuzya Cosmo Marmeladov, founded 1 July 2024). CIA stands for **Compact Intelligence Apparatus** — a field device worn or kept on a desk that acts as a physical terminal node for the LOT behavioral OS.

It is part of the **LOT Ecosystem Node Map** (ref: LOT-WIKI-v66, Section 13). It occupies the **physical edge node** tier — between the server (Node-0) and the operator's body.

### 2.2 Design Language

| Principle | Expression |
|-----------|------------|
| No noise | One button. One screen. One notification at a time. |
| Material honesty | 316L stainless steel. No plastic. No color. |
| Signal precision | Text or icon only — no animations unless triggered |
| Minimalism | Screen shows one line, centered, opacity-90 |
| LOT Doctrine alignment | Every button press writes to the Log. Nothing is silent. |

### 2.3 Notification Philosophy

The screen receives autonomous push messages from `lot-systems.com` — examples:

```
  Coffee time.
  Move. 12 min since last break.
  Weather: 18°C, rain in 2h.
  Memory check. How did that meeting go?
  Battery: 22%.
```

Messages are generated by the LOT AI (Quantum Intent Engine + Memory Engine). They are one sentence. They do not ask for a response — they surface the pattern. The operator's only option is the **Copy button**, which logs the notification to the site's Log tab with a timestamp.

### 3.5 Engineering Note — Height

At 5.0 mm total, the stack is extremely tight. Two paths:

| Path | Approach | Trade-off |
|------|----------|-----------|

**Recommendation: Path A — specify 6 mm to PCBWay, market as "5mm class."**

### 6.2 Critical Layout Notes

**Wi-Fi Antenna:**
- ESP32-S3-MINI-1U has PCB trace antenna — keep antenna zone clear of copper pour for ≥3mm in all directions.
- Orient module so antenna faces the button cutout side (away from SS shell mass on Side A).

**Camera:**
- OV2640 FPC connector near top-center edge of PCB.
- DVP data lines (D0–D7) routed with matched-length (±0.5mm) pairs.
- Separate analog ground domain for AVDD.

**Wireless coil:**
- Qi RX coil sits between PCB and Side A shell.
- Coil connects to IP5328P via short FPC ribbon or direct solder tabs.
- Shield coil from MCU RF with a ferrite layer sheet (TDK IFL12 or equiv).

**BME688:**
- Must have a vent path to outside air. Design a 1.0 mm vent hole through PCB aligned with a matching hole in Side B shell (not visible from front — place at edge).
- Keep BME688 away from heat sources (>5mm from any power IC).

**Power routing:**
- Battery positive trace: 1.5 mm wide, ≥2 oz copper.
- Qi coil trace: 2.0 mm wide.
- All power decoupling caps placed within 0.5 mm of IC power pins.

### 6.3 Test Points

Expose pogo-pin compatible test pads (1.0 mm) on bottom layer for:
- GND, VBAT, 3V3
- ESP32 UART TX/RX (for firmware flash)
- ESP32 EN (reset)
- I2C SDA/SCL
- SPI CLK/MOSI/CS (display)
- Camera PWDN, RESET

### 7.2 Boot Sequence

```
1. Power on → IP5328P asserts 3.3V
2. ESP32-S3 boots → loads config from NVS (Wi-Fi creds, LOT token, device ID)
3. Display shows: "LOT." (white text, centered, black background)
4. Wi-Fi connect → connect to last known SSID
5. LOT API handshake → authenticate with device token
6. Subscribe to notification channel (WebSocket)
7. Sensor init: BME688 (BSEC library), QMI8658
8. Display shows: "Ready." or current notification
9. Enter main loop
```

```c
// ISR: button pressed → debounce 50ms → trigger log event
void IRAM_ATTR button_isr_handler(void* arg) {
    BaseType_t high_prio_task_woken = pdFALSE;
    xTaskNotifyFromISR(log_task_handle, LOG_EVENT_COPY, eSetBits,
                       &high_prio_task_woken);
    portYIELD_FROM_ISR(high_prio_task_woken);
}

// Log task: POST to LOT API
void task_log_event(void* arg) {
    while (1) {
        uint32_t bits;
        xTaskNotifyWait(0, ULONG_MAX, &bits, portMAX_DELAY);
        if (bits & LOG_EVENT_COPY) {
            lot_api_post_log_event({
                .type   = "COPY_BUTTON",
                .device = device_id,
                .message= current_notification,
                .ts     = ntp_timestamp(),
                .iaq    = bme688_get_iaq(),
                .temp   = bme688_get_temp(),
            });
        }
    }
}
```

### 7.6 OTA Firmware Update

- Dual-partition OTA (factory + ota_0).
- Device checks LOT firmware endpoint every 6 hours.
- If new version available: download to ota_1, verify SHA256, swap.
- Update triggered by server push message type `FIRMWARE_UPDATE`.
- No user action required.

## 15. SESSION COMPRESSION PROTOCOL

Each device session generates context. To keep state compact (aligned with LOT Memory Engine philosophy), the device compresses its session:

### 15.1 What gets compressed

Every 24 hours, the device posts a session summary to the LOT API:

```json
{
  "type": "SESSION_SUMMARY",
  "device_id": "CIA-0042",
  "date": "2026-06-30",
  "session": {
    "notifications_received": 12,
    "notifications_displayed": 12,
    "copy_button_presses": 3,
    "copied_messages": ["Coffee time.", "Move.", "Weather: 18°C"],
    "avg_iaq": 84,
    "avg_temp_c": 21.2,
    "avg_humidity": 52,
    "battery_cycles": 0.8,
    "wifi_uptime_pct": 98.2,
    "ota_version": "1.0.3"
  }
}
```

### 15.2 Memory Engine Integration

Session summaries feed into the LOT Memory Engine. Over time, the QIE learns:
- Which times of day the Copy button is pressed (signal value = operator engagement)
- Environmental conditions correlated with engagement
- Notification types that get logged vs. ignored (to improve QIE pattern selection)

### 15.3 On-Device Compression

- Device NVS stores last 7 days of session summaries in ring buffer.
- Older entries are dropped — the API holds the historical record.
- Total NVS usage for session data: <64KB.
