01 // WHAT v1.0 IS AND WHAT IT IS NOT
--------------------------------------------------------------------------------

COSMO® Terminal, model T-1, is a small physical object that sits on a desk,
receives one class of signal — a short text notification generated by the AI
running lot-systems.com — and displays it the way a pager displays a message:
briefly, legibly, without asking for a reply.

  v1.0 IS:
    - A two-piece stainless-steel body: one face a mirror-polished plate, the
      opposite face a matte instrument panel carrying a camera, a round
      display, and one physical button.
    - A companion flat charging Dock — a 40mm x 40mm x 5mm brushed/polished
      steel square that is both the Qi wireless charging pad and the object
      the Terminal rests on.
    - A pager, not a computer in the general sense implied by the repository
      name. It runs one first-class function (receive + display + one-button
      acknowledge) on top of a general-purpose SoC, the same way LOT® CUBIQ™
      runs one function (haptic notification) on top of a general-purpose
      actuator stack.
    - Built from off-the-shelf, AI-capable modules (Section 03) and a
      contract-manufactured stainless enclosure (Section 05), not custom
      silicon. Nothing here requires inventing a chip.

  v1.0 IS NOT:
    - A general-purpose PC, phone, or tablet. No app store, no browser, no
      multi-app OS. One job: LOT's signal, shown on a desk object.
    - A two-way conversational device. The Copy button (Section 06) is the
      only input path back to LOT — a single, unambiguous acknowledgment
      signal, not a keyboard.
    - The COSMO® Cube named in LOT-CUBIQ-QUANTUM-CUBE-v0.md. That object
      moves (jumps, eventually walks). This object does not move. It sits,
      shows, and listens for one button.

  THE PRINCIPLE
    Ship the smallest true computer first. A stainless object that reliably
    shows a message pushed from lot-systems.com, and reliably reports back
    when its one button is pressed, is a complete v1.0 — before camera vision,
    before weather-driven notifications, before a second unit ships.

02 // PHYSICAL FORM
--------------------------------------------------------------------------------

  TERMINAL BODY      Two-part stainless steel shell, press-fit + 4 M2 screws,
                       gasket-sealed at the seam (IP54 target — desk object,
                       not outdoor-rated).
  DIAMETER / HEIGHT   70mm diameter puck, 22mm height (fits the round display
                       + camera + battery stack; final number confirmed at
                       prototype, Section 08).
  FACE A — POLISHED   Mirror-finish 316 stainless. No electronics, no seams
                       visible from this side. This is the side shown when the
                       Terminal sits idle, display-down, on a shelf — LOT's
                       "closed door" object language, same anti-feed thesis as
                       CUBIQ (LOT-CUBIQ-QUANTUM-CUBE-v0.md, Section 04).
  FACE B — MATTE      Bead-blasted matte 316 stainless bezel. Carries, center-
                       out: camera (Section 03), 1.28" round display (Section
                       03), and one physical button labeled COPY (Section 06).
  DOCK (CHARGER)      40mm x 40mm x 5mm flat stainless square. Doubles as: Qi
                       wireless charging transmitter, weighted base so the
                       Terminal is stable resting face-B-up, and the physical
                       anchor point of the desk setup — same "table is the
                       power surface" design decision CUBIQ made for its own
                       charging pad.
  WIRED CHARGE        USB-C port on the Dock (not the Terminal body) for
                       initial charge, firmware flashing, and wired fallback
                       if Qi alignment fails. The Terminal body itself has no
                       exposed port — sealed shell, charges only via the Dock.
  MASS TARGET         <95g Terminal, <180g Dock (Dock mass is intentional —
                       it should not slide when the Terminal is set down).

03 // ELECTRONICS + SENSOR STACK — "AI-GRADE, OFF-THE-SHELF"
--------------------------------------------------------------------------------

"AI-grade off-the-shelf" means: every part is a shipping, sourceable module
already used in production AI-camera / edge-vision products — nothing bespoke,
nothing requiring an ASIC. Full sourcing and pricing lives in the companion
BOM (Section 09, LOT-COSMO-COMPUTER-BOM.md). Architecture:

  COMPUTE      Espressif ESP32-S3 (dual-core, AI vector instructions, 8MB
               PSRAM class) — the same silicon family Espressif ships in its
               own ESP32-S3-EYE reference AI-camera board. Runs the firmware
               (separate document, Section 09).
  DISPLAY      1.28" round IPS LCD, GC9A01 driver, 240x240 — chosen because
               round-display + ESP32-S3 is already a shipping reference
               design (Waveshare ESP32-S3-LCD-1.28), which de-risks the
               display/compute pairing before the stainless shell is cut.
  CAMERA       2MP OV2640 DVP module — presence/QR/ambient-light sensing for
               v1.0 (Section 04), not a general imaging feature. Selected
               because it is the de facto standard ESP32 camera sensor with
               mature open drivers (esp32-camera).
  WEATHER      Bosch BME280 (temperature / humidity / barometric pressure),
               I2C/STEMMA QT. Cross-checked, not duplicated, against LOT's
               existing server-side weather service (src/server/utils/
               weather.ts) — see Section 04.
  CHARGE       Qi receiver (BQ51013B-class, 5V/500mA out) inside the Terminal
               body; matching Qi transmitter inside the Dock.
  POWER        Single 3.7V LiPo cell, small enough to clear the 22mm height
               budget; USB-C charge management lives in the Dock, not the
               sealed Terminal shell.
  BUTTON       One tactile switch under the stainless bezel, labeled COPY
               (Section 06) — the only physical input.

04 // THE PAGER — NOTIFICATION FROM AN AI-POWERED SITE
--------------------------------------------------------------------------------

Core function. The Terminal is a physical extension of the same signal system
that already writes to a LOT user's Log — not a separate notification channel
invented for hardware.

    lot-systems.com (AI engine, ai-engines.ts)
              │
              │  decides WHAT/WHEN/HOW — e.g. "Coffee time!",
              │  a memory-question-ready ping, a weather-crossover note
              ▼
    LOT API Connector (Section 06)  ─── device-paired channel, not a
              │                          browser session
              ▼
    Terminal firmware — renders text on the round display,
              short and legible (pager-length, not paragraph-length)
              │
              ▼
    Operator glances at the desk object. No push banner on a phone,
    no browser tab. The message sits until acknowledged or replaced.

The BME280 (Section 03) supplies one input class into this loop: local
temperature/pressure/humidity readings that LOT can compare against its own
weather service (src/server/utils/weather.ts, already live) to detect
divergence — e.g., the room is colder than outdoor conditions predict, worth a
"draft near your desk?" notification. This is the "weather sensor" requirement
resolved as a real signal source feeding the existing AI engine, not a
decorative gauge.

05 // THE COPY BUTTON — SIGNAL BACK TO THE LOG TAB
--------------------------------------------------------------------------------

The one physical input the Terminal has is the button on Face B, labeled
COPY. Its behavior is deliberately narrow:

    Operator presses COPY while a notification is showing
              │
              ▼
    Firmware timestamps the press + the currently-displayed message text
              │
              ▼
    LOT API Connector issues the SAME call the web client already makes —
    POST /api/logs  { text, event, metadata }
    (src/client/queries.ts, useCreateLog — this is the live endpoint,
    not a new one invented for hardware)
              │
              ▼
    A new entry lands in the operator's Log tab (/log route,
    src/client/stores/router.ts line 31) — event: "cosmo_terminal_copy",
    text: the notification that was on the display, metadata: { deviceId,
    displayedAt, pressedAt }

The name is literal: pressing COPY copies the physical moment — a message
that existed only on a desk object — back into the durable digital Log. It is
the inverse of the notification path in Section 04: Section 04 is
site-to-object; COPY is object-to-site. Together they close the same kind of
loop LOT-CUBIQ-QUANTUM-CUBE-v0.md Section 05 describes for the Cube (haptic
telemetry feeding back into calibration) — here the telemetry is a single
explicit human acknowledgment, not continuous sensor data.

06 // LOT API CONNECTOR — AUTHENTICATION ARCHITECTURE
--------------------------------------------------------------------------------

The live web app authenticates via JWT cookies (per docs/corporate/
LOT_Autonomous_AI_Server.md, "Session management: OPERATIONAL, JWT, cookies,
expiry"). A $10 microcontroller cannot hold a browser cookie jar or complete a
TLS+session login flow the way a browser does. The Connector is therefore
split into two halves — this is also why "software to connect with firmware"
(Section 09) is a separate deliverable, not a firmware feature:

  DEVICE PAIRING TOKEN   Issued once, from the operator's logged-in LOT
                          account (Settings), long-lived, revocable, scoped
                          to POST /api/logs only — never a full session token.
  BRIDGE SOFTWARE         Small companion app (phone or desktop) that already
                          holds the operator's real LOT session. It talks to
                          the Terminal locally (BLE or local Wi-Fi), and to
                          lot-systems.com using the Device Pairing Token. The
                          Terminal firmware never speaks directly to the
                          public internet.
  DATA FLOW               lot-systems.com <-> Bridge (has real auth) <-> BLE/
                          local Wi-Fi <-> Terminal firmware (has no auth,
                          trusts only its paired Bridge)

This mirrors the existing security posture already documented for LOT's own
server (docs/corporate/LOT_Autonomous_AI_Server.md, Section 04 — irreversible
and notify-class actions are gated) rather than inventing a new one: the
notify-class action here ("write to a person's Log") is gated behind a scoped,
revocable token instead of the device holding a master credential.

07 // MANUFACTURING — PCBWAY, STAINLESS BODY, 100-UNIT PILOT
--------------------------------------------------------------------------------

  PCB              PCBWay standard PCB fab + SMT assembly service for the
                    Terminal's carrier board (ESP32-S3 module, camera FPC
                    connector, BME280, Qi receiver, button, battery/USB-C
                    charge circuit on the Dock board).
  STAINLESS BODY   PCBWay's CNC machining service, 316 stainless steel
                    material option, for both Terminal shell halves and the
                    Dock plate — one supplier for board fab, assembly, AND
                    metal enclosure, which is the whole point of choosing
                    PCBWay over splitting the job across a PCB house and a
                    separate machine shop.
  FINISH           Face A: mirror polish pass (PCBWay CNC surface-finish
                    option). Face B + Dock: bead-blast matte pass.
  PILOT RUN        100 units. Sized to: (a) clear most CNC/PCB house
                    per-unit-cost cliffs (small-batch pricing improves sharply
                    above ~50-100 pcs), (b) stay inside a single pilot budget
                    without committing to injection-molded tooling, (c) match
                    LOT's existing "smallest true thing first" build doctrine.
  COST MODEL       Full BOM, per-unit and 100-unit totals, and the PCBWay/
                    vendor links for every line item are in the companion
                    document: docs/corporate/LOT-COSMO-COMPUTER-BOM.md
                    (Section 09).
  ASSEMBLY         PCBWay SMT assembly for the board; final mechanical
                    assembly (board into shell, battery, gasket, screws)
                    done in-house for the 100-unit pilot — not yet
                    outsourced. Revisit at the v1.1 gate (Section 08) if
                    volume grows past pilot scale.

08 // ROADMAP — v1.0 → v1.1 → v2.0
--------------------------------------------------------------------------------

  v1.0 — THE PAGER (THIS DOCUMENT)
    Stainless two-part body + Dock, round display, one button, Qi charge,
    BME280 weather cross-check, LOT API Connector (Bridge-mediated), Copy
    button wired to /api/logs. 100-unit pilot run.
    GATE: 100/100 units pass a bench test — receive a pushed notification,
    display it legibly, register a Copy press back to /api/logs — before any
    unit ships to an operator.

  v1.1 — CAMERA-DRIVEN PRESENCE
    Activate the OV2640 camera (present in hardware from v1.0, dormant in
    firmware): presence detection (is the operator at the desk) gates WHEN a
    notification is shown vs. queued, and a QR-scan pairing flow replaces
    manual Bridge pairing.
    GATE: presence detection reduces missed-then-late notification acknowl-
    edgment (measured via Copy-press latency) by a defined margin across a
    10-operator pilot cohort, without a false-negative rate that suppresses
    real notifications.

  v2.0 — MULTI-UNIT / FLEET
    Move past the 100-unit pilot's in-house assembly to a contracted
    mechanical-assembly line; Bridge software gains multi-Terminal pairing
    (one operator, several rooms). Requires a device-management surface on
    lot-systems.com (out of scope for this document; opens a new INTAKE).
    GATE: not scheduled. Recorded so v1.0/v1.1 firmware and Connector
    decisions (Section 06's Bridge-mediated auth in particular) are made with
    a fleet future in mind rather than foreclosing it.
