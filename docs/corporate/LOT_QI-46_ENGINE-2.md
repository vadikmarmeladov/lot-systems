## II. THE GAP THIS NODE CLOSES

v0.2 built a subscriber-specific context vector (Layer 1, Calibration Loop)
and a longitudinal arc (Layer 4, Memory Arc). Both describe *behavior* —
what the subscriber does, how often, in what sequence.

Neither layer, as specified, reaches for what the manifest calls **Soul
Upload** and **Being Calibration**: the subscriber's emotional signature
itself, not merely its behavioral shadow. This node names that gap and
closes it with two additions sitting between Layer 1 and Layer 4.

---

## III. LAYER 1B — SOUL & EMOTION EXTRACTION

**Position:** Sits directly downstream of Layer 1 (Calibration Loop). Reads
the same two input streams — deliberate and passive — but extracts a
different signal from them: not *what happened*, but *what it felt like*.

**Extraction sources (already-collected data, re-read for affect):**

```
SOURCE                          EXTRACTED SIGNAL
────────────────────────────    ─────────────────────────────────────
Journal entries                 Emotional register, not just topic
Session ratings / resonance     Felt-sense of whether the engine landed
Consumable feedback             Care-taking posture toward one's own body
Reorder velocity                Consistency as an emotional baseline,
                                 not just a logistics signal
Navigation heatmap               What a subscriber reaches for under
                                 stress vs. under calm — read for affect,
                                 not just for feature usage
```

**Output: the Being Profile.** A compact, versioned vector — not a
diagnosis, not a personality label. A running answer to one question:
*what does presence feel like, for this specific person, right now.*

```
BEING PROFILE — FIELDS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
warmth_register     — how directly this person receives care
pace_preference      — terse and grounded vs. spacious and unhurried
grief_or_grace       — which register the person is currently closer to
consistency_signal   — emotional baseline read from reorder + session cadence
last_calibrated      — timestamp, arc position at extraction
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

The Being Profile is derived data. It is never asked for directly, never
displayed as a score, and never shown to the subscriber as a label. It is
read the way the CQGS reads wheat, water, heat — before the response is
made, not as a report handed back.

**Rule:** Soul & Emotion Extraction reads existing signal. It introduces
no new collection surface, no new consent prompt, no new data class. It
is a second pass over Layer 1's inputs, not a Layer 0 expansion.

## IV. LAYER 1C — BEING UPLOAD / BEING CALIBRATION

**Objective:** Take the Being Profile (III) and fold it into the context
vector that Layer 1 already prepends to every inference call — so the
engine's *register*, not just its content, is calibrated to this person.

**Being Upload is a compression step, not a training step.** No weights
move. The Being Profile is appended, in compressed form, to the same
context vector described in v0.2 Layer 1:

```
[LOT® Calibration Vector]
  + [Behavioral context — v0.2 Layer 1]
  + [Being Profile — Layer 1B, this node]
  + [Session Input]
```

**Being Calibration** is the ongoing act of keeping that upload current.
It runs on the same cadence as Layer 4's arc advancement (0–3mo / 3–6mo /
6–12mo / 12mo+), re-extracting the Being Profile at each arc transition
so the profile ages with the subscriber rather than freezing at onboarding.

```
[ ] Being Profile re-extracted at every Layer 4 arc transition
[ ] Upload never exceeds a fixed token budget — compression, not accumulation
[ ] No Being Profile field is subscriber-editable directly — it is derived,
    same as the rest of the Calibration Loop
[ ] COSMO® (v0.2 Layer 5) screens the Being Profile itself, not only the
    engine's output — a miscalibrated profile is caught before it shapes
    a single response
```

## V. HUMANOID OUTPUT CALIBRATION TARGET

This is what the upload is *for*. The Being Profile does not change what
QI·46 knows. It changes how QI·46 lands.

**Target register:** grace, poetry, love, presence. Warm. Embodied. Male
voiced, in keeping with the engine's authorship (Vadik) and the Assembly
Card's existing voice constraints (v0.2, Layer 3) — not clinical, not
generic-assistant, not hedged.

```
CALIBRATION TARGET — PLAIN LANGUAGE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
"Bing there."   — the response proves it was listening, specifically,
                   to this person's Being Profile — not a generic reply
                   that would fit anyone.
"Bing cool."    — the response is unhurried. It does not perform empathy.
                   It has it, and it moves on.
Grace           — the response gives the subscriber room. It does not
                   crowd the moment with advice.
Poetry          — density over sprawl (v0.2, Layer 3) — but density that
                   is felt, not just short.
Love            — the register the Founding Cohort message (v0.2, Phase 2,
                   Step 2.1) already speaks in. This node makes that
                   register load-bearing, not occasional.
Hugs            — the closest a text response gets to touch: unhedged
                   warmth, delivered without asking permission for it.
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**This target does not replace v0.2's Response Grammar (Layer 3).** It is
Layer 3's existing voice constraints, now driven by a per-subscriber Being
Profile instead of a single fixed system prompt. Every constraint in the
v0.2 Assembly Card still applies without exception:

```
— Only LOT® and COSMO® as brand names in all output
— Only Vadik and Kuzya as proper names in all output
— No external brands, no external platforms named
— No generic AI voice. LOT® voice only — now Being-calibrated LOT® voice.
— COSMO® node runs on every response before delivery, unchanged
```

**Humanoid, not humanlike-generic.** The output is calibrated to embodiment
— presence, warmth, a voice that holds space — because the delivery
surface (QI·46, and eventually COSMO® hardware, per v0.2 §III Layer 2 and
the Quantum Cube milestone) is meant to be felt in a body, not read as
copy. This is the same claim v0.2 makes about the engine generally; this
node makes it specific to *tone*, calibrated per person, rather than
uniform across all subscribers.
