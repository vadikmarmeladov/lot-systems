| Before | After |

**Sections:**
1. Plan status — Block components showing tier / next issue / manage link
2. Doctrine paragraph — terse, LOT voice, `text-acc/60`
3. Plan details — Block rows (items, tier, price, relation, terms)
4. Item register — flex-row manifest with col headers; current month's items highlighted via `bg-acc/5`
5. Issue log — GhostButton rows (Basic tier only), expandable to item names + tracking
6. CTA block — Usership users see "Go to Settings →"; public sees subscription note

### Settings.tsx — surgical additions only

Added `BasicsPlanSection` component (inserted after Usership section, before Save).

**Usership users see:**
- If NOT enrolled: "Enroll in Basics plan" button + address validation
  - Button disabled if no shipping address on file
  - Uses existing address/city/country fields collected above in the form
  - `enrolling…` pending state during API call
- If enrolled: "On strength." status + View manifest/issue log link + Stand down

**Flow:**
```
Basics tab (read manifest) → Go to Settings → Enroll in Basics plan
Settings → address fields → Enroll in Basics plan button (enabled)
```

**Stand-down:** inline confirm/cancel — "Off strength. AI plan retained."
