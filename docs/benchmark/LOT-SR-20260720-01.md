C1 TIME-TRACK        CalendarEntry gains optional `time` (HH:mm, <input
                     type=time>, opt-in). getEntryStatus(entry, now) ->
                     scheduled | due (<=15min out) | overdue (past target).
                     Status renders as a plain uppercase tag (no color, no
                     icon) next to the entry in both the selected-date detail
                     list and the upcoming-entries list. Untimed entries carry
                     no tag — nothing renders without cause.
C2 CALM NOTIFY       In-widget toast fires once when a timed entry's moment
                     arrives (0 to 30min past target, first check to catch
                     it wins). Presence-gated: !document.hidden &&
                     isRouteActive('system') — silent off-tab/off-page, still
                     catches up within the 30min window on return. Fired keys
                     persisted to localStorage (capped 300) so a reload never
                     re-shows a seen event. Fixed-position, opacity/translate
                     transition in/out over 0.5s, auto-dismiss at 6s. No OS
                     Notification API, no permission prompt, no sound — this
                     is the existing EvolutionMilestoneToast pattern applied
                     to calendar events, formalized in DOCTRINE this session.
C3 CAL: LOG HANDLER  Logs.tsx CAL: military block now renders time next to
                     date when present (tabular-nums, same instrument style).

                     time (was date-only sort).

Design note: the scheduled routine's ask ("military-grade event
notifications") reads, taken literally, in tension with the Field Manual's
existing Context Over Notification principle ("no push, no alert, no
interruption"). Resolved by building the notification as an in-page, calm,
presence-gated, once-only toast (military PURITY in style: no decoration, no
emoji, no color) rather than an OS-level push/alert — satisfying the literal
request without violating the documented design constraint. Flagged to S-2
for review; not a unilateral doctrine override, an interpretation made
explicit in both DOCTRINE and the Field Manual so it can be checked.
