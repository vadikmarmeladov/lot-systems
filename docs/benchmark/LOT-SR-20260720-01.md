Design, unchanged from SR-20260719-01 (ported, not redesigned):
  - "/email to <name>" is detected wherever it appears in a Log entry's text
    (Logs.tsx trigger list + server-side maybeSendLotEmail, called from both
    POST and PATCH /logs). Single-token recipient name only, optional
    trailing punctuation stripped. Message body is the entry's text with the
    command substring removed.
  - Recipient resolved by case-insensitive exact firstName match. No match ->
    row is still written (status 'unresolved', recipientId null) instead of
    rejected, so a later-joining "Hitomi" or a future LOT Community / Cohort
    Dating persona can still be the eventual recipient without any rework —
    neither "LOT Community" nor "Cohort Dating" nor a "Hitomi" user exist
    anywhere in the current codebase (verified repo-wide again this session;
    unchanged since SR-20260719-01).
  - Delivery is the existing Sync SSE channel: sync.emit('email', payload) on
    successful resolve, forwarded only to the matching recipientId inside the
    /sync SSE handler's existing per-connection switch (Backend Whitelist
    Hygiene doctrine clause — the case was added correctly the first time,
    verified present).
  - GET /api/emails returns the current user's last 50 received emails,
    joined with sender firstName/lastName. Sync.tsx renders them in a "EMAIL"
    section above Lot Chat, merging fetched + live-SSE items by id.
  - Inbox visibility inherits Sync's existing tag gate (Admin/RND/Usership/
    Onyx/Legacy) — unchanged scoping decision from SR-20260719-01, still the
    right call for a first slice: no new access surface opened.
