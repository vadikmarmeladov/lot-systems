WHAT CHANGED
- POST /api/story now accepts `period: 'day'|'week'|'month'|'year'` (default
  day). Each period maps to a lookback window (24h / 7d / 30d / 365d), a
  per-category sample size (6/10/14/20), and a target word count
  (100-200 / 150-250 / 200-300 / 250-350) — a year-story reads as a longer
  arc than a day-story, not the same prompt with a bigger number attached.
- Added `sampleEvenly()`: picks entries spaced evenly across the DESC-ordered
  window instead of "most recent N," so a month/year story actually draws
  from across the span rather than clustering on the last active day.
- Sparse-history fallback preserved: if a user has <3 logs inside the chosen
  window (new or lightly-used account), the route falls back to the prior
  flat last-200-logs behavior rather than returning an empty story.
- Client: `/story week` (or day/month/year) is parsed from the Log input,
  stripped from the text sent as context, and threaded through to the AI
  call. `/system` help text now documents the `[period]` argument. The
  story result block now labels itself with the period (📖 WEEK, etc.).
- `useStoryGeneration` (queries.ts) and the `/story` response both carry
  `period` through so client and server agree on what was generated.

WHAT WAS VERIFIED, NOT REBUILT
