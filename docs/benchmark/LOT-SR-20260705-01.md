FIX LOG:
  - node_modules was absent in this environment; installed via `npm ci
    --legacy-peer-deps` (registry.yarnpkg.com is proxy-blocked here;
    registry.npmjs.org is allow-listed — used npm instead of yarn).
  - src/client/utils/dayjs.ts was missing the customParseFormat plugin.
    getEventDayjs() parses `"${date} ${time}"` against `'YYYY-MM-DD HH:mm'` —
    without the plugin that format string is silently ignored and dayjs falls
    back to native Date parsing of a non-ISO string, which is undefined
    behavior across engines (verified fine in this Node/V8 build; historically
    unreliable on WebKit/Safari). Added the plugin — cheap, correct, no
    behavior change where it already worked.
  - Ported alert-overlay markup used `bg-base`, which is not a real utility
    class in this project's Tailwind config (colors key is `bac`, not `base` —
    confirmed by grep across the codebase, zero other `bg-base` usages exist).
    The overlay would have rendered with no background. Fixed to `bg-bac`.
  - Ported overlay also used `max-w-64`, which resolves to 64px under this
    repo's custom pixel-based Tailwind spacing scale — too narrow to hold
    "CAL [EXECUTE]" without near-unreadable wrapping. Widened to `max-w-320`
    (320px), still expressed on the same numeric scale used throughout the
    rest of the file.

CALENDARWIDGET.TSX — reliable time-tracking upgrade
  - Live HH:mm:ss clock (1s tick) driving all countdown/status computation.
  - Optional HH:MM on entry creation — entries can now anchor to a real time,
    not just a date. Untimed entries anchor to end-of-day so same-day items
    never read as elapsed before the day is over.
  - Status ladder per entry: EXECUTE (≤15min) → ALERT (≤60min) → STANDBY
    (≤24h) → ELAPSED (past) → null (>24h out or >2h stale, not worth showing).
  - "Today" panel: every entry due today with live per-entry countdown.
  - Military-grade fixed-position alert overlay: fires once per timed entry
    when it crosses the 60-minute horizon, labelled `CAL [EXECUTE]` /
    `CAL [ALERT]`, ACK button to dismiss, 30s auto-dismiss, T±HH:MM:SS
    countdown. Dedup via a ref-held Set keyed on date|time|text so an entry
    never re-alerts.
  - Source: hand-ported from gifted-lovelace-cZOWR (978cf52, "Calendar
    Alerts" BEST candidate), with the bg-base/max-w-64/customParseFormat
    fixes above folded in during the port.

LOGS.TSX — CAL: renderer upgrade + new CAL-RMD: handler

                     status line. Was: bare entryType + date, no status.

  existing calendar_reminder logs before writing, so a reminder fires exactly
  once per entry per kind, never repeats across days.
  33 → 34 background jobs total.
