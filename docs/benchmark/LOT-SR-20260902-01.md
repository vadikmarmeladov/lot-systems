--------------------------------------------------------------------------------
R1 CHANNEL COLUMN    Migration adds direct_messages.channel STRING default
                     'chat' ('chat'|'email'). DirectMessage model + shared
                     DirectMessage type updated. One column, no new table —
                     an email IS a direct message with a tag.
R2 POST /email       New route: body {toName, message}. Resolves recipient
                     by firstName ILIKE (excludes self); 404 no match, 409
                     ambiguous match (returns candidates). Creates the
                     DirectMessage(channel:'email'), emits the existing
                     'direct_message' SSE event (now carrying channel), logs
                     an email_sent Log row. moduleMap gained email_sent ->
                     'community' so LOT Email counts toward the silent-
                     module community signal alongside chat_message.
R3 /email TRIGGER    logTriggers.ts: new 'email-compose' trigger, keyword
                     'email' + ✉️ emoji. Logs.tsx: `/email to <Name>` strips
                     the command from the log text, sends the remainder as
                     the email body via useSendEmail; inline result block
                     (✉️ EMAIL: sent/failed, same pattern as /qi, /story);
                     added to /system help.
R4 SYNC SURFACING    Sync.tsx now also listens for 'direct_message' SSE
                     events; channel:'email' events involving the current
                     user render as a live "LOT Email" list above the
                     public chat feed, linking to the /dm/:userId thread.
                     Session-only (SSE), by design — Sync is a live feed,
                     not a mailbox; the durable record is the /dm thread.
R5 COHORT TIE-IN     CohortConnectWidget.tsx gained an "✉️ Email" action
                     next to "Send message", routing straight to
                     /dm/:userId for that match — Cohort Dating (LOT
                     Community) is one click from a LOT Email thread.
                     Works today because a cohort match is already a User
                     with a resolvable id — no new lookup needed.
