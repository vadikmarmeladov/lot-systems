  correct, so this is a background-tab battery/CPU cost, not a lag bug.
  Cheap per-tick (single setState), but it is the one interval-bearing
  widget that never adopted the hidden-tab gate the SR-20260719-01 fix
  applied elsewhere. Candidate for the same one-line guard next touch.

DEFECT (pre-existing, surfaced by this scan, NOT fixed this session — scope
and blast-radius reasons below):
- src/client/utils/badges.ts: two badge IDs are each declared TWICE, both in
  the type union and in the definition object — `quarter_drop` (L3214 "first
  easter egg unlocked" vs L5501 "midnight check-in, RARE") and `elixir_found`
  (L4825 "'elixir' in text" vs L6883 "'elixir/gift/treasure/boon', RARE").
  JS object-literal semantics mean the SECOND definition silently wins; the
  first is dead and can never surface its own copy/rarity to the user. This
  is a real correctness bug feeding the Badge Unlock Feed and Evolution
  widgets (wrong badge text/rarity shown for one of the two triggers).
  NOT fixed here: renaming an id is not locally safe — badge ids persist in
  user unlock history/analytics, and unlock-trigger logic elsewhere in the
  codebase must be re-pointed in lockstep with any rename. That is a scoped
  ENGINEERING fix, not an audit action; flagging for a dedicated session.
