05b // WHAT WAS BUILT
--------------------------------------------------------------------------------
Soul Upload is a subscriber-typed log entry (`/soul` or 🫂, same LOG-terminal
convention as `/prayer` and `/story`). Being Calibration runs three pure
layers, kept separate on purpose (see LOT-DOCTRINE.md for the full breakdown):

  1. computeCalibration() — LOCAL, no AI call. Blends deliberate input
     (keyword scan of the soul text: love, hug, alone, poem, afraid,
     grateful, lost...) with passive input (last 5 emotional_checkin states,
     most-recent-weighted) into a 5-axis vector: GRACE · POETRY · LOVE ·
     WARMTH · PRESENCE (0-100 each).
  2. buildCalibratedPrompt() — renders that vector into tone directives
     prepended to the QI46_SYSTEM_PROMPT (Layer 3 voice grammar, taken
     verbatim from the spec's system-prompt seed) and calls
     aiEngineManager (Together AI primary, same fallback chain as
     Memory/Prayer/Story).
  3. cosmoScreen() — Layer 5. Runs on the raw completion before delivery;
     holds unsafe or over-length responses, falls back to a static QI·46
     line, and logs every hold to a new `cosmo_audit` Log event. Clear
     responses are logged as `soul_upload` with the full calibration vector
     in metadata — the audit trail the spec calls for.

This is Node 1: Phase 0/1 territory in the spec's timeline (corpus +
voice), delivered as working code against the live user base rather than a
separate training run — the calibration loop and COSMO® gate are real from
the first request, not simulated.
