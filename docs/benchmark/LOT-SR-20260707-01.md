LOT EMAIL v1 — design notes (COCKPIT-RULE observed throughout)

  LOG TRIGGER (logTriggers.ts)
    email-send   keyword "email"   /email to <Name> <message>
    Whole-token match via existing detectTriggers() word-boundary regex —
    "/emailing" does not false-positive. No emoji shortcut (deliberately —
    email is a directed act, not a mood toggle).

  LOG HANDLER (Logs.tsx)
    Parses recipient with /\/email\s+to\s+([A-Za-z][\w'-]*)/i, strips the
    command from the log text, sends the remainder as the message body.
    Empty body after stripping -> "ADD A MESSAGE BEFORE SENDING", no request
    fired. Result surfaces as EMAIL: block (cockpit label, no narration) —
    "SENT TO <NAME>" or the server's rejection reason, uppercased.
    /system help updated with the new command line.

  SERVER (api.ts)
    POST /api/email    { recipientName, message } -> resolves recipient by
                       first name (exact case-insensitive match first, prefix
                       match fallback; suspended accounts filtered; picks the
                       most recently active match on ambiguity), then creates
                       a DirectMessage row and emits the SAME 'direct_message'
                       SSE event Sync's DM thread already listens for. Logs
                       an email_sent event for the pattern engine.
    GET  /api/inbox    Latest DirectMessage per correspondent for the caller,
                       newest-first, capped at 20 threads. Feeds Sync's inbox
                       strip.
    No new model, no new migration — LOT Email is a view onto DirectMessage,
    not a parallel data store. A Log-composed email and a Sync DM are the
    literal same row.

  SYNC (Sync.tsx)
    New "Email" strip between the compose box and the public feed: partner
    name, latest message preview, relative time, click -> /dm/:userId. Backed
    by GET /api/inbox on mount; a 'direct_message' SSE event involving the
    current user invalidates the query (same idiom Sync already uses for
    chat_message_like) so a new LOT Email appears in Sync live, no refresh.

  COHORT DATING (CohortConnectWidget.tsx)
    "Send message" on a cohort match went to the generic Sync tab despite a
    working /dm/:userId route already existing in router.ts and being wired
    in app.tsx's DynamicRoutes. One-line fix: goTo('dm', { userId }). Cohort
    Dating and LOT Email now open the exact same thread.

  DIRECT MESSAGE THREAD (DirectMessageThread.tsx)
    Added "← Back to Sync" (GhostButton, existing component) — the full-page
    /dm/:userId view previously had no way back except the browser button.

  Net effect: three entry points — Log's /email, Sync's inbox, Cohort
  Connect's "Send message" — and one full-page thread view all resolve to the
  same DirectMessage row and the same SSE event. No forked messaging system.
