FIX LOG:
  1. src/client/utils/badges.ts — removed 2 dead/shadowed duplicate object
     keys (`quarter_drop`, `elixir_found`), each defined twice in the same
     literal. JS object-literal semantics meant the later definition always
     won at runtime; the earlier one was unreachable dead code. Confirmed via
     grep that the surviving definitions are the ones actually referenced by
     award/trigger logic in easter-eggs.ts. Zero behavior change; removes an
     esbuild warning and a tsc TS1117 error. (pushed separately, commit 3c23899,
     ahead of this report)
  2. src/client/stores/intentionEngine.ts:3332 — CRITICAL. `analyzeIntentions()`
     (Pattern 147, "quantum-presence-field") referenced `dayMs`, a name never
     declared in that function's scope (only a same-named local existed in two
     unrelated functions). Result: `ReferenceError: dayMs is not defined` on
     EVERY call to analyzeIntentions() for any user with >=1 recorded signal —
     100% of active users, every time. Because the cooldown gate reads
     `state.lastAnalysis`, which is only advanced by code AFTER the crash
     point, the cooldown itself never engaged, so the function has been
     throwing on every invocation since Pattern 147 was added. Some call
     sites swallow it in try/catch (Logs.tsx, MemoryWidget.tsx); others call
     it unguarded inside useEffect (System.tsx:268, SystemProgressWidget.tsx),
     surfacing as an uncaught React effect error. Net effect: the QIE's
     recognizedPatterns/userState never advanced past 'unknown' defaults —
     QuantumStateWidget, getOptimalWidget(), and the full 148-pattern
     detector were effectively dead for real users. FIX: scoped a local
     `dayMs147 = 24 * 60 * 60 * 1000` at the point of use, matching the
     file's existing per-pattern local-constant convention. Verified the
     specific tsc error is gone post-fix; full build green.
  3. src/client/components/MicroGameWidget.tsx:779 — `recordSignal('micro_game',
     ...)` passed a signal source not in IntentionSignal['source']'s union
     type, silently polluting the QIE signal store with an untyped source the
     pattern engine never checks. FIX: added 'micro_game' to the union in
     intentionEngine.ts (additive, no exhaustive switch depends on this union
     — verified via grep — so this is a safe, non-breaking extension,
     consistent with how 'badges'/'astrology' were added previously).
  4. docs/technical/WIDGETS.md — corrected 10 stale API endpoint paths
     (/api/os-status -> /api/os/status, /api/growth-stats -> /api/stats/growth,
     etc. — full list in block 05); merged a duplicate "System Progress
     Widget" section left over from doc appends instead of edits; corrected
     the Quantum Engine Connect device count (doc said 3 devices / "all three
     devices," code implements 6 — Car/Home/Computer/Phone/Watch/Robot,
     TOTAL_DEVICES=6 in QuantumEngineWidgets.tsx) and added the 3 undocumented
     Phone/Watch/Robot Connect widgets; corrected Memory Widget's logging
     mechanism description (docs said /api/logs, code actually posts to
     /api/memory/answer which writes the Log row server-side directly).
