## KEY DESIGN DECISIONS

```
- Device named "COSMO® Computer" — kept textually and functionally
  distinct from CUBIQ (LOT®'s notification cube). Computer = general-
  purpose hardware client of the LOT API; CUBIQ = single-purpose
  haptic actuator. No shared enclosure, no shared actuator stack.
- Copy button maps to a NEW Log event type ('hw_copy'), additive to
  the existing Log model rather than repurposing 'note' — rendered in
  Logs.tsx as a new military-format handler (HWCOPY:), consistent with
  the existing MCOHERE: / CEXP: / BIOARC: handler family.
- Camera is scoped to a single explicit trigger (long-press) with a
  hard firmware-level power gate and a server-side enforcement backstop
  (camera-policy endpoint) — no code path exists for continuous
  recording. This follows LOT_ROBOTICS_COSMO.md's ethical framework
  directly rather than inventing new privacy language.
- New device endpoints (/api/device/cosmo/*) extend the existing
  Fastify api.ts / os-api.ts surface rather than standing up a parallel
  service — the Copy endpoint is a thin wrapper around the existing
  POST /logs handler (api.ts line 1563).
- Session compression (build brief item 8) specified at two layers:
  on-device (firmware doc §03.4, RAM-only accumulator) and in-transit
  (software doc §05, one compressed record per session, not per-event).
```
