06a // WHAT WAS BUILT
--------------------------------------------------------------------------------
CalendarWidget.tsx — time tracking:
  - "Track time" control sits beside the existing "Add date" button. Click
    reveals a session-label input; Enter or Start begins the session.
  - While a session runs, the widget shows TRACKING · <label> · HH:MM:SS,
    ticking once per second, with a Stop control.
  - RELIABILITY: the active session (startedAt + label) is persisted to
    localStorage on start and restored on mount, so a page refresh or tab
    close/reopen does not lose or reset an in-progress session — the elapsed
    clock picks up exactly where it left off. This was the concrete gap
    implied by "reliable... track time": an in-memory-only timer loses state
    on any reload.
  - STALE-SESSION GUARD: on restore, if the persisted session has been running
    longer than 12h (crashed tab, closed laptop), it is not silently resumed —
    it is auto-finalized as a completed log entry tagged autoStopped: true and
    a visible "AUTO-TERMINATED" note, rather than either resuming a runaway
    multi-day timer or losing the record entirely.
  - Two log events per tracked session: calendar_timer_start (session open,
    terse pulse) and calendar_time_log (session close, canonical record with
    label / startedAt / endedAt / durationSeconds / date). The existing
    calendar_entry note/task/call flow is untouched.

Logs.tsx — military-grade rendering (COCKPIT-RULE, existing house style):
  - TRK-INIT: block for calendar_timer_start — label + date, terse pulse.
  - TRK: block for calendar_time_log — label, DUR: HH:MM:SS (tabular-nums,
    instrument-reading style matching MER:/MULTI:/QOS-COHR: blocks), date,
    and an "Auto-terminated" marker when the stale guard fired. No narration
    in the body — label names the event, body is instrument readings only,
    per the existing COCKPIT-RULE convention already governing all 150+
    other log handlers in this file.

routes/api.ts — displayableEvents whitelist:
  - Added 'calendar_timer_start' and 'calendar_time_log'. Per the existing
    Widget->Memory Compression Loop doctrine note in LOT-DOCTRINE.md: an
    event type absent from this whitelist is silently invisible in the Log
    field even though it was written to the DB. Both new event types are
    registered so nothing is silently erased.
