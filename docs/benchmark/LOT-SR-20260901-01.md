DESIGN:
  /email to <Name>[.,:!] <body>   (also /mail, or ✉️ to <Name> <body>)
  detected as a new LogTrigger ('email-compose') the same way /prayer,
  /story, /scan etc. already are (src/client/utils/logTriggers.ts).
  parseMailCommand() pulls the recipient (word after "to") and treats
  everything else in the log entry — before and after the command — as
  the body. On fire, Logs.tsx tags the text with a MAIL_HEADER_PREFIX
  ("✉ MAIL → ") and posts it through the existing useCreateChatMessage
  mutation → POST /api/chat-messages, the same call Sync's own compose
  box makes. That single existing endpoint already: persists a
  ChatMessage row, emits SSE 'chat_message' (Sync updates live for every
  Usership/Onyx/Legacy/R&D/Admin cohort member watching — this IS "new
  messages appear in Sync" and "incorporate with LOT Chat"), and writes a
  Log record with event 'chat_message' (this IS the compose-in-Log
  round-trip — the sent mail reappears in the operator's own Log tab).

  Cohort Dating / LOT Community: Sync is the shared cohort channel gated
  to Usership/Onyx/Legacy/R&D/Admin. Addressing "/email to Hitomi" inside
  that shared channel — rather than a private 1:1 DM to a resolved user
  ID — is the simplest honest form of cohort-community messaging this
  session could ship without inventing a matching/resolution service that
  doesn't exist yet (no user directory, no dating-match algorithm is
  present anywhere in the codebase — confirmed by search). The whole
  cohort sees who mail is addressed to, exactly like calling out a name
  in a shared room. A future session can layer real recipient resolution
  (DirectMessage to a matched user, src/server/routes/api.ts already has
  the full send/thread pipeline) on top of this same MAIL_HEADER_PREFIX
  tag without touching the Log-side compose code.

  Rendering: Sync.tsx recognizes the prefix and shows a "✉ MAIL → NAME"
  tag ahead of the body instead of plain chat text. Logs.tsx's existing
  'chat_message' case (label "COMM:") now checks the same prefix and
  relabels mail entries "MAIL:" — no new Log event type, same idiom the
  Calendar widget already uses for its [SCHEDULE] tag (no schema change).
  /system help gained one line: "/email to X   Dispatch LOT Mail to a
  cohort member — appears in Sync".

  Failure path: chat is gated server-side to Usership/Onyx/Legacy/R&D/
  Admin. A 403 is caught and shown in the Log compose panel as "DISPATCH
  FAILED / REASON SYNC REQUIRES USERSHIP, ONYX, LEGACY, R&D, OR ADMIN"
  rather than failing silently or crashing.
