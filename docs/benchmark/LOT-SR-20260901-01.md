05 // FINDINGS BY AREA
--------------------------------------------------------------------------------
05.1 WIRING / DATA / TESTING
All 39 *Widget*.tsx render as direct JSX children of System.tsx (no registry
or grid layer). No automated test exists for any widget — zero *.test.ts(x)
files, no jest/vitest config. "Data storing": widget interactions split
across two disjoint systems — useCreateLog() (server-persisted, feeds
useLogContext) is called by only 4/39 widgets (Recipe, SelfCareMoments,
Planner, Calendar); the other 35 emit recordSignal()/record*Signal() into
the client-only intentionEngine atom instead, or nothing at all (TimeWidget,
QuantumRandomWidget, MicroImageWidget). Any "usage" metric read from
useLogContext therefore undercounts most widget activity.

05.2 SYSTEM TAB / LOT AI / PORTRAIT (Public Profile)
PublicProfile.tsx (Portrait) is a fully separate tree from System.tsx — no
Widget component is reused, and it fetches /api/public/profile/:id directly
rather than through queries.ts. This is a clean privacy boundary (raw QIE
signals and log history never cross to the public page), at the cost of
duplicated component code for anything shared (badges via
getBadgeProgressionDisplay, ProfileQRCode).

05.3 QUANTUM INTENT ENGINE / MEMORY / STORY
intentionEngine.ts's WIDGET_DEPENDENCY_MAP (~30 widget IDs mapped to
upstream signal sources) is hand-maintained and has drifted: the 'system'
entry lists 'qos' and 'astrology' as upstream sources, but no widget in this
pass was found calling a record*Signal for either — a dependency the graph
still trusts for cascade-invalidation. MemoryWidget and NarrativeWidget
(Story) both record signals correctly and are wired end-to-end.

05.4 INTERACTIVE / CONTEXT SYNC (weather, time, users online)
Framing does not match wiring: useWeather and useVisitorStats (queries.ts)
have no staleTime and no refetchInterval — they fetch once per mount and
never refresh, so "weather" and "online users" are static snapshots, not
live sync, despite the ambient framing. Genuinely live: 8 widgets poll via
setInterval/refetchInterval. TimeWidget ticks every 1s for an hour-
granularity value (3600 wasted ticks/hour); ContextualPromptsWidget is the
one widget that correctly skips its interval when document.hidden or the
route is inactive — that guard is not applied anywhere else.

05.5 15-MONTH UI REVEAL CADENCE
No artifact, doc, or code reference to a 15-month or month-to-month reveal
schedule was found anywhere in docs/ or src/ (grep across both, zero hits).
The only build-up counter in the codebase is the continuous Day-N operator
counter in About.tsx (Day 1072+, LOT founded 2016-04-07) — a different
concept (uptime, not a phased reveal). PROVISIONAL: either this cadence
lives outside this repo (design doc, roadmap) or the instruction describes
an intended-but-unbuilt mechanism. Not fabricating a finding here — flagging
for S-2 to point at the source if one exists.

05.6 LOADING SPEED / LAG
Only 1 of 39 widgets (MemoryWidget) is React.memo'd; System.tsx itself is
memoized with ~21 internal useMemo calls, but a parent re-render still force-
renders every non-memoized child regardless of prop stability — e.g.
TimeWidget and QuantumRandomWidget take zero props yet re-render on every
System.tsx re-render (every useLogs() refetch, every interval tick).
Loading: no React.lazy/dynamic import anywhere in src/client — all 39
widgets compile into one ~730KB app.js and mount eagerly on first paint,
including any widget gated behind a tab or accordion at runtime. esbuild's
splitting:true only extracts a 4.3KB shared chunk, not per-widget bundles.

05.7 OTHER RED FLAGS
1. badges.ts: 'quarter_drop' defined twice (L3214 "first easter egg",
   uncommon vs L5501 "midnight check-in", rare) and 'elixir_found' twice
   (L4825 hidden/uncommon vs L6883 non-hidden/rare, wider trigger words) —
   confirmed by esbuild duplicate-key warnings. The earlier definition of
   each is permanently dead; that badge can never be unlocked. Not fixed
   this session — renaming a badge id risks reinterpreting already-awarded
   user badge records with no test coverage to verify against; needs a
   scoped session with DB awareness, not a blind rename.
2. /api/logs has no LIMIT (queries.ts:134, comment-acknowledged); mitigated
   only by a 5-min client staleTime — payload grows unbounded with account
   age.
3. intentionEngine.ts:3830 — WIDGET_DEPENDENCY_MAP references unconfirmed
   emitters (05.3).
