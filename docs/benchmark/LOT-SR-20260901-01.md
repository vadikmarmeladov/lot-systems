R1 STORY PERIOD WINDOW   `/story day|week|month|year` (bare `/story` keeps
                        its original flat behavior — additive, non-breaking).
                        Client: logTriggers.ts detection needed no change
                        (`/story week` already satisfies the existing
                        `(^|\s)\/story(\s|$|[^a-z0-9_])` token match);
                        NoteEditor's story-mode handler now regex-extracts
                        the period, strips it from logText, and forwards
                        `period` on the mutation.
R2 SERVER COMPRESSION    POST /api/story accepts optional `period`. When
                        present: `Log.findAll` where-clause gains
                        `createdAt >= Op.gte(now - windowMs)` (day=24h,
                        week=7d, month=30d, year=365d), limit raised
                        200->500 rows to leave room for the wider windows,
                        and entry/mood/self-care slice depth scales with
                        window (5 baseline -> 8/15/30/50) so a year isn't
                        summarized off the same five lines as a day. The
                        systemPrompt now names the window explicitly
                        ("compress the last day/week/month/year") instead
                        of the generic "recent journey" phrasing. Response
                        and `Log.metadata` both now carry `period` so the
                        client can label the entry and the record is
                        self-describing without re-deriving from text.
R3 CHRONICLE KEEPER      New badge (easter_egg category, epic, hidden) —
                        checkChronicleKeeper() in easter-eggs.ts tracks
                        distinct periods used via a small localStorage set
                        (`story_periods_used`, mirrors the existing
                        checkDawnRunner/checkGreatWorkSequence pattern of
                        cross-session localStorage state, not a text-regex
                        WORD_TRIGGERS entry — this badge fires on action,
                        not on a word appearing in text). Awards once all
                        four windows have been invoked at least once each.
                        Wired from NoteEditor's submitStory onSuccess, only
                        when a period was present on the request.
R4 SYSTEM HELP SYNC      /system help text expanded from one /story line to
                        five (bare + 4 periods) so the passive-UI surface
                        stays self-documenting — S-2's own spec: "if the
                        user types /system all commands appear."
