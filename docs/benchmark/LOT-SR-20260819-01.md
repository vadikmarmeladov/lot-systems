B. FIXES APPLIED THIS SESSION (recovered from stranded branch ofbejf +
   new finds; all re-verified against current code before applying)
   1. QIE P147 CRASH — intentionEngine.ts:3332 referenced an undeclared
      `dayMs` (only in scope at unrelated lines 3543/4620). Any operator
      reaching adaptive-signal-web + quantum-coherence-peak simultaneously
      threw a ReferenceError inside System.tsx's unguarded
      analyzeIntentions() call. Fixed: inlined `24 * 60 * 60 * 1000`.
   2. MONTHLYPULSE DEAD GATE — MonthlyPulseWidget.tsx:74 reads
      `user?.joinedAt`, but UserProfile (shared/types/index.ts) never
      declared the field and User.useProfileView()'s fp.pick() list
      (server/models/user.ts) never selected it — the widget's fire
      condition has been permanently false since it shipped (SR-20260707-
      01). Fixed: added `joinedAt` to the pick() list and
      `joinedAt?: Date | null` to UserProfile.
   3. MEMORY RESPONSE TYPE GAP — useCreateMemory (queries.ts) was typed
      `{ response: string }`; MemoryWidget.tsx:66 destructures `{ response,
      insight }` from onSuccess, and the server (api.ts /memory/answer)
      returns `{ response, insight, answerCount }`. Not a runtime bug
      (esbuild doesn't type-check per DOCTRINE rev O) but a real type-
      safety gap. Fixed: widened the response type to match.
   4. NEW — QUANTUM-RANDOM OFF-TAB CHURN: QuantumRandomWidget.tsx runs
      TWO independent 1s setInterval countdowns (`useQuantumNumber()`
      called twice) plus a 10s setInterval, none gated on `document.
      hidden` — continuous state updates + recordSignal() calls even on a
      backgrounded tab, same class of issue as R1/R2 in SR-20260719-01 and
      the later "perf: pause System background work off-tab" commits, but
      this file (created 2026-06-29) was never touched by either pass.
      Fixed: both intervals now `if (document.hidden) return` before
      doing work.
   5. QUERY-BATCHING GAP — api.ts:2269 Answer.findAll(where: userId) had
      no `limit`, unlike the other Answer.findAll call sites in the same
      file. Only fetches id+metadata to build a recent-question-id set, but
      is genuinely unbounded for long-tenured users. Fixed: `limit: 200`,
      matching the existing 200-row precedent for cohort matching (QUERY-
      BATCHING doctrine).
   6. DOC DRIFT (docs/technical/WIDGETS.md) — two items disagreed with
      current code: (a) "Awareness Dashboard" was documented as "integrated
      into System.tsx" but AwarenessDashboard.tsx is not imported anywhere
      — it was intentionally skipped as a duplicate per SR-20260719-01 R6,
      the doc just never caught up; marked NOT MOUNTED with the citation.
      (b) "Quantum Engine Connect Widgets" documented 3 devices (Car/Home/
      Computer); QuantumEngineWidgets.tsx now wires 6 (+ Phone/Watch/
      Robot, each with its own connect/disconnect signal pair) — added the
      3 missing entries.
