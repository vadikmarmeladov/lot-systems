05 // WHAT WAS FOUND (audit, before any fix)

The Log entry system already implements a pure-detector slash-command layer
(src/client/utils/logTriggers.ts) feeding an if/else dispatch in the journal
textarea component (src/client/components/Logs.tsx NoteEditor), covering 18
triggers: /synth /scan /silent /breathe /fast /radio /night /prayer /freeze
/qos /assembly /phys /sil /qi /system /story /how, plus emoji shortcuts.
/system already rendered a static help block; /story already POSTed to
/api/story, which pulls the operator's logs, moods, and self-care notes and
calls Together AI (aiEngineManager.getEngine('together')) to compress them
into a 1-2 paragraph narrative, persisted as a `generated_story` Log event —
this IS the LOT User data -> QIE -> Together AI -> stored pipeline S-2
described, already wired for the ad-hoc case. A separate template-based
weekly job (Job 24, executeWeeklyLOTAIStory, Sunday 18:00 UTC) independently
aggregates 7-day logs into `lot_ai_story`. No monthly/yearly variant existed.

Three defects found against S-2's literal spec:
  BUG-1  /system's help text omitted /sil (sil-check trigger exists, listed
         nowhere) — "all commands appear" was false by one command.
  BUG-2  `generated_story` (the event every /story call writes) was ABSENT
         from the GET /api/logs `displayableEvents` whitelist — a textbook
         instance of the DOCTRINE's own "Backend Whitelist Hygiene" clause.
         Every /story invocation silently wrote a Log row the operator could
         never see again in their own feed. Write-only, no error, no signal.
  GAP-3  S-2 asked for day/week/month/year compression; only an unscoped
         "recent" /story and a background weekly job existed — no way for
         the operator to request "compress my month" on demand.

07 // WHAT CHANGED — MECHANISM
--------------------------------------------------------------------------------
/story now accepts an optional trailing scope keyword: `/story`, `/story
day`, `/story week`, `/story month`, `/story year` (`today` normalizes to
`day`). No keyword preserves the exact prior behavior (recent-200,
unbounded) — zero regression risk for existing users' muscle memory.
With a scope, the server bounds the Log query by createdAt >= now-N-days
(day=1, week=7, month=30, year=365; Op.gte via dayjs, matching the query-
batching/date-scoping pattern already used elsewhere in api.ts), scales how
many entries feed the AI prompt (5/8/12/15) and the target narrative length
(80-120w / 120-180w / 150-220w / 200-280w), and records `scope` in both the
Log event metadata and the JSON response. This is additive on the same
pipeline and event type — no new job, no new table, no new whitelist
category beyond the one bug fix. /system now lists /sil and the four /story
forms. displayableEvents gained `generated_story` under a new `v114` comment
block, following the file's existing versioned-comment convention.
