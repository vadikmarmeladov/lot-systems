## ARCHITECTURE

### Data Model

```
lot_mails
  id          UUID PK
  senderId    UUID FK → users
  receiverId  UUID FK → users
  body        TEXT (max 1000 chars)
  readAt      DATE nullable
  createdAt   DATE
  updatedAt   DATE
```

### Command Flow

```
User types in Log:
  /email to Hitomi Hello, how are you today?
         ↓
logTriggers: detectNewTriggers → 'email-send'
         ↓
NoteEditor effect: parse /email to {name} {body}
         ↓
useSendLotMail: POST /api/lot-mail
         ↓
Server: find user by firstName (Op.iLike)
         ↓
Server: create LotMail record
         ↓
Server: sync.emit('lot_mail', notification)
         ↓
SSE /api/sync: broadcast to receiver only
         ↓
Receiver's Sync component: show mail alert banner
         ↓
Log: create 'lot_mail_sent' event entry
         ↓
Textarea: cleared
```

### API Routes

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/lot-mail` | Send mail. Body: `{ recipientName, body }` |
| `GET` | `/api/lot-mail/inbox` | Get received mails (50 most recent) |
| `GET` | `/api/lot-mail/unread-count` | Get unread count |
| `PUT` | `/api/lot-mail/:id/read` | Mark mail as read |

### SSE Integration

- Server emits `lot_mail` event with `LotMailNotification` payload
- SSE handler filters: only writes to the **receiver's** stream
- Client `Sync.tsx` listens for `lot_mail` — shows inline alert banner
- Alert banner is clickable → navigates to `/mail` (LotMail tab)

### Navigation

```
Sync | Mail | Log | System | Basics | ...
```

Mail tab shows:
- Inbox list with sender name, timestamp, body preview
- Click to expand full message
- Unread count in header
- Usage hint: `/email to [name] [message] in Log`

## DOCTRINE UPDATE

**New pattern: `/command to {entity} {payload}`**

The `/email to Hitomi ...` pattern establishes a general-purpose LOT command syntax for directed actions. This can extend to: `/call to Hitomi`, `/note to Hitomi`, etc. The command is typed in Log (the operator's workspace) and executes quietly — textarea clears on send, feedback appears below.

**Principle: commands belong in the journal.**

The Log is the operator terminal. All system commands route through it. Sync remains the community broadcast layer; it receives the signal, not the command.
