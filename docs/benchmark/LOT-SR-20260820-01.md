   client-side) — widgets touch AI exclusively through REST round-trips.
   ~16 of the audited widgets (Time, QuantumRandom, SystemPulse,
   SystemProgress, MicroGame, MicroImage, Calendar, MicroCalculator,
   ChakraErgonomics, EnergyCapacitor, Subscribe, CorporatePlan, DemoDay,

   pure local/client-computed display, which is appropriate for their role.

B. QUANTUM INTENT ENGINE / MEMORY / STORY — the significant finding
   TWO parallel Memory Engine implementations exist:
     - src/server/utils/memory.ts (a FILE) — this is the one actually
       running. package.json's `"#server/utils/*": "./dist/server/server/
       utils/*.js"` subpath-import map resolves the bare specifier
       `#server/utils/memory` (used by api.ts, admin-api.ts) to this file,
       literally — not to a directory index. Verified in compiled dist
       output.
     - src/server/utils/memory/question-generator.ts (48KB, in a directory
       alongside index.ts, cohort-determination.ts, story-generator.ts,
       trait-extraction.ts, constants.ts, pacing.ts) — has a materially more
       complete `formatLog()`/`buildPrompt()`, including cases for
       'self_care_complete', 'self_care_skip', 'theme_change', and a rich
       'quantum_intent_signal' handler. NOTHING imports it. `memory/index.ts`
       re-exports its buildPrompt/completeAndExtractQuestion/getMemoryEngine,
       but no file in the app imports the bare `#server/utils/memory/index`
       path — only 4 sibling files in that directory (cohort-determination,
       trait-extraction, story-generator, constants) are reached, via direct
       deep imports from scheduled-jobs.ts / public-api.ts. question-
       generator.ts appears to be superseded work that was never wired in.
   CONFIRMED, FIXED THIS SESSION: the live memory.ts's formatLog() had no
   case for 'self_care_complete' or 'self_care_skip' — both are created
   client-side (SelfCareMoments.tsx:165,202) with a populated `text` field,
   both are in the intentional user-facing `displayableEvents` allow-list
   (api.ts:1094), yet formatLog's switch fell through, returned '', and the
   entry was silently dropped from every AI prompt before question-
   generator.ts's question-generation logic ever saw it — exactly the
   failure mode LOT-DOCTRINE.md's "Widget→Memory Compression Loop" clause
   already warns about. Fixed with the same `body = log.text || ''` pattern
   used for the existing 'note'/'plan_set' cases (memory.ts, 8 lines added).
   NOT fixed, flagged for S-2 judgment (scope too broad for an unattended
   pass): 'quantum_intent_signal' still has no case in live formatLog() —
   goal/intention/journal/mood/self-care signals from recordSignal() (11+
   widgets: GoalJourneyWidget, IntentionsWidget, JournalReflection,
   EmotionalCheckIn, ChatCatalystWidget, CohortConnectWidget, ...) reach the
   Log table via /api/quantum-intent/sync but are excluded from AI prompt
   context. api.ts:1084's own comment calls this exclusion intentional for
   the user-facing /logs feed ("exclude raw QIE signal events") — whether
   that intent should also apply to the AI-context formatLog() is a real
   design question, not a bug I should guess the answer to. Two credible
   fixes exist and are not equivalent: (a) port question-generator.ts's
   quantum_intent_signal case into the live memory.ts formatLog, or (b)
   properly wire memory/question-generator.ts in as the live engine (it's
   more complete, but unverified against memory.ts's other exports:
   generateRecipeSuggestion, extractUserTraits, determineUserCohort,
   calculateIntelligentPacing). Recommend S-2 pick a direction next session.
   Also: `LogEvent` union (shared/types/index.ts:111-120) only lists 9
   values; a second, separately-maintained `LogEvent` exists in
   src/types.ts; `MODULE_BY_LOG_EVENT: Record<LogEvent,string>` is
   duplicated in memory.ts and story-generator.ts. All three casts of
   `log.event as LogEvent` around the codebase are technically lies against
   the real runtime event set (30+ event strings in api.ts's own
   displayableEvents list) — the type can't catch a missing formatLog case
   because it doesn't know the case exists. Left as-is: correcting it
   safely means auditing all three call sites plus two Record literals in
   one atomic change; deferred rather than risking a partial, silently
   inconsistent update.
   STORY: composeLocalStory-equivalent logic (generateMemoryStory) is
   duplicated in memory.ts:772 and memory/story-generator.ts:176; only the
   latter is reachable from public-api.ts, the former from the main app.
   Both filter Log rows to `event === 'answer'` only — Story is not
   orphaned, but structurally starved of goal/intention/self-care/mood
   widget signals for the same reason as the Memory Engine above.

D. 15-MONTH UI REVEAL ROADMAP
   The number in code and commit history is 12, not 15 — no "15-month"
   artifact exists anywhere in src/ or docs/. MonthlyPulseWidget.tsx caps at
   `Math.min(monthNumber, 12)` / "N / 12 months"; commit history (e.g.
   `fe87e614` "Usership 12-month evolution doctrine") confirms 12 is the
   intended cadence. That widget is a dismissible congratulatory toast for
   Usership-tag users only — it does not gate or reveal any other widget.
   The actual progressive-unlock mechanism is achievement-based, not
   calendar-based: src/client/utils/interfaceEvolution.ts (exploration/
   consistency/depth/connection dimensions 0-1) drives
   InterfaceEvolutionWidget.tsx. The two systems are functionally
   disconnected — worth flagging to S-2 in case "15-month" reflects an
   intended change from 12 that hasn't shipped yet, rather than a stale
   reference on my end.
