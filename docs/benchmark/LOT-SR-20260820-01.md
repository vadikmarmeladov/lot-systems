DESIGN
--------------------------------------------------------------------------------
Researched the live repo before writing code (general-purpose research agent,
28 tool calls): "Log" is the slash-command console in Logs.tsx, driven by the
pure detector in logTriggers.ts. "Sync" and "Lot Chat" are the same system —
ChatMessage rows rendered in Sync.tsx, delivered live over the existing SSE
bus (`sync.emit('chat_message', ...)`). "Cohort Dating" and "LOT Community"
do not exist as named features — the closest real analogs are Cohort Connect
(CohortConnectWidget.tsx, behavioral-pattern matching, Block label "Cohort:")
and the `/cohorts` endpoint. Resend-backed `sendEmail()` already existed
(src/server/utils/email.ts), previously used only for auth codes.

Simplest-possible design, no new tables:
  1. Operator writes a note in the Log, then attaches "/email to <Name>"
     anywhere in it (same convention as /prayer, /story — command wraps
     already-written text, not a separate argument typed after it).
  2. Detected by logTriggers.ts ('email-compose'); fires off the existing
     7s autosave debounce (not on every keystroke — a real send is not a
     UI toggle). Sends once per recipient name while the command remains
     in the entry; editing the message further does not re-send. Removing
     and re-adding (or switching the name) re-arms it.
  3. POST /api/log-email resolves the recipient by first name (case-
     insensitive, scoped to LOT Community = all platform users), creates
     a ChatMessage exactly like a normal Sync post, emits the same SSE
     event Sync already listens for, mirrors a Log event (`lot_email_sent`),
     and calls sendEmail() to the recipient's registered address.
  4. Cohort Connect's "Send message" action (previously a no-op navigate
     to Sync) now hands `/email to <FirstName> ` to the Log via a new
     one-shot `pendingLogInsert` store and routes there — this is the
     literal "Cohort Dating through LOT Community" integration: emailing
     a cohort match starts from the match card.

No new DB table, no inbox — the ChatMessage row IS the email record, same
as every other Sync post.
