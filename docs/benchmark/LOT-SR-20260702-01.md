NEW CODE-LEVEL BUGS FOUND (this session):

  [BUG-01] SEVERITY: HIGH — Memory Engine health check false-positive error
  FILE:    src/server/routes/public-api.ts, checkMemory() ~line 242
  ISSUE:   checkMemory() was checking only for ANTHROPIC_API_KEY to determine
           if the Memory Engine is available. On 2026-06-30, Together AI was
           promoted to primary engine (AI_ENGINE_PREFERENCE: 'together').
           Any production environment where TOGETHER_API_KEY is set but
           ANTHROPIC_API_KEY is absent would report Memory Engine as 'error'
           on the /status page — a false negative hiding the actual healthy state.
  FIX:     Replaced ANTHROPIC_API_KEY check with aiEngineManager.hasAvailableEngine(),
           which correctly checks the full provider fallback chain.
  STATUS:  FIXED

  [BUG-02] SEVERITY: MEDIUM — Status endpoint never produces 'degraded' state
  FILE:    src/server/routes/public-api.ts, performHealthChecks() ~line 359
  ISSUE:   The StatusData interface declares 'degraded' as a valid overall status,
           and StatusPage.tsx renders a distinct label for it. However,
           performHealthChecks() only ever returned 'ok' or 'error' — any single
           failing check (including non-critical ones like the Weather API) would
           escalate to 'error', incorrectly signaling a full system outage.
  FIX:     Added critical-check logic. Critical checks: Database, Authentication,
           Memory Engine. Non-critical failures now produce 'degraded' status.
           Critical check failure OR 3+ errors = 'error'.
  STATUS:  FIXED

  [BUG-03] SEVERITY: LOW — Stale Claude model in test-anthropic-key endpoint
  FILE:    src/server/routes/public-api.ts, /test-anthropic-key route ~line 706
  ISSUE:   The test endpoint used 'claude-3-5-sonnet-20241022', which is a 2024
           model. Updated to current 'claude-haiku-4-5-20251001' — faster and
           cheaper for a connectivity test, avoids routing to deprecated model IDs.
  STATUS:  FIXED
