DESIGN, ONE PARAGRAPH PER SURFACE:
LOG:     detectTriggers gained 'lot-mail' (/email, /mail, ✉). parseEmailCommand
         splits "/email to <Name> <body>" into recipient + message. NoteEditor
         fires it exactly like /prayer and /qi — mutate, inline loading block,
         inline result block ("MAIL:" — SENT → Name, or the server's rejection
         text verbatim).
SERVER:  POST /api/mail resolves <Name> against the caller's own Cohort Dating
         / Community matches (the exact same matcher GET /cohorts already
         uses — factored into resolveCohortMatches, now shared by both
         routes so they can never disagree on who counts as a connection).
         A match creates a DirectMessage, emits direct_message over SSE, and
         logs email_sent (or email_failed, with no receiver leaked, if the
         name isn't a connection). Mail cannot reach a stranger — it reaches
         only who Cohort Dating already introduced.
SYNC:    Found and fixed a real bug on the way: the /sync SSE relay's event
         switch had no case for 'direct_message', so DMs (mail included)
         never pushed live to either party — only a manual refetch would
         reveal them. Added the case, scoped to sender/receiver only (never
         broadcast). Sync.tsx now also listens on that channel directly and
         renders a live "MAIL:" notice list, click-through to the /dm thread.
         This is literally where "new messages appear in Sync."
COHORT:  CohortConnectWidget's "Send message" button used to just switch to
         the Sync tab with no addressee. It now opens /dm/<userId> for that
         match directly — the one-click path from Cohort Dating into a
         mail thread with that exact person.
