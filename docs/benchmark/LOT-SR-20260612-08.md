07 // DESIGN DECISIONS
--------------------------------------------------------------------------------

D-1  Time field is optional.
     Rationale: notes and non-time-sensitive tasks don't need clock precision.
     Alert system only activates for entries that have time set.

D-2  Alert fires on today's entries only.
     Rationale: future-day events don't need live alerts; the upcoming list
     in the widget shows +XD countdowns for those.

D-3  Session-memory dedup (Set in React state, not localStorage).
     Rationale: alerts should re-fire on page reload (the event may still be
     pending). localStorage would suppress valid re-alerts after a hard refresh.

D-4  Static T-minus in Logs.tsx, live T-minus in CalendarWidget.
     Rationale: Logs is a historical ledger — entries don't change over time,
     so a computed-at-render badge is appropriate. The widget is a live tool.

D-5  Priority scan: NOW → 15MIN → 1H. One alert at a time.
     Rationale: stacking alerts for the same session produces noise. The most
     urgent fires; others are queued implicitly by the per-tick scan.

D-6  Minimalist styling preserved.
     No new colors introduced. Urgency expressed via opacity (0.8→0.3),
     not color change. All text remains text-acc with opacity variants.
