## COMPONENTS BUILT

### 1. `/email` Command in Log

**Trigger:** `/email to [Name] [body]` — also accepts `/mail to [Name]`
**Emoji variants:** `✉️` `✉` `📧`

Flow:
```
User types: /email to Hitomi Great session today
→ email-compose trigger fires
→ Inline compose panel appears below editor
→ To: field pre-filled with "Hitomi"
→ Body pre-filled with "Great session today"
→ User clicks Send → POST /api/mail
→ Confirmation: "✉ Sent to Hitomi."
→ SSE event fires to recipient's Sync in real-time
```

If body is omitted:
```
/email to Hitomi
→ Compose panel opens blank — user writes body there
```

### 2. Sync — Chat | Mail Tab Strip

- New tab strip at top of Sync: `Chat` | `Mail (N)`
- Mail tab shows unread count badge in real-time
- Clicking Mail tab opens `EmailInbox` component
- Incoming `lot_mail` SSE events trigger inbox refresh + badge update
- Switching to Mail tab clears the notification count

### 3. EmailInbox Component

- Shows all received LOT Mails (newest first, limit 50)
- Unread messages displayed at full opacity; read at 60%
- Click message → expands full body + marks as read
- Subject shown if present; falls back to body preview
- Time shown as relative ("3 hours ago")

### 4. Real-Time Delivery via SSE

- Server emits `lot_mail` event on send
- SSE `/api/sync` switch case routes only to `toUserId`
- Client `sync.listen('lot_mail')` in Sync updates badge + triggers inbox refresh

### 5. Cohort Dating Integration

- `ChatCatalystWidget` gains `✉ Mail` button for cohort member suggestions
- Clicking routes to Log and pre-populates `/email to [Name]` in the textarea
- Fires `connection_accepted` signal with type `'email'` for QIE tracking

## DATABASE

### Migration: `20260612120000_add-lot-mail.cjs`

```sql
CREATE TABLE lot_mails (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  fromUserId  UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  toUserId    UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  subject     VARCHAR(255),
  body        TEXT NOT NULL,
  read        BOOLEAN NOT NULL DEFAULT false,
  createdAt   TIMESTAMP,
  updatedAt   TIMESTAMP
);

INDEX (toUserId, read, createdAt)
INDEX (fromUserId, createdAt)
```

**Max body length:** 2000 characters (`MAX_LOT_MAIL_LENGTH`)

## API SURFACE

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/mail` | Send mail (lookup recipient by first name) |
| `GET`  | `/api/mail/inbox` | Fetch inbox (50 most recent) |
| `GET`  | `/api/mail/unread-count` | Unread count for badge |
| `PUT`  | `/api/mail/:id/read` | Mark message as read |

### Recipient Lookup Logic
- Searches `users.firstName` (case-insensitive iLike)
- If full name given (e.g. "Hitomi Sato"), also matches `lastName`
- Returns 404 with `hint` if not found
- Returns 400 if sender = recipient

## DOCTRINE NOTES

- LOT Mail is **internal-only** — no SMTP, no external delivery. Messages stay inside LOT Community.
- The recipient lookup is intentionally fuzzy (first name only) because LOT is a small, known community. Add stricter matching if the community scales.
- `/email` and `/mail` are interchangeable by design — operators use what feels natural.
- Future: `/email to Hitomi subject: <subject> <body>` parsing, sent folder, reply threading.
