04 // PERFORMANCE ANOMALIES
--------------------------------------------------------------------------------

  PERF-001  Monitoring scripts — new Sequelize instance per poll    SEVERITY: MED
  ──────────────────────────────────────────────────────────────────────────────
  Files:  scripts/monitoring/health-check.ts (5s interval)
          scripts/monitoring/pool-monitor.ts (10s interval)
  Issue:  Both scripts create a fresh Sequelize instance, authenticate,
          query, and close on every tick. This means:
          — 2 handshake round-trips per 5–10 seconds during monitoring
          — TCP connection churn visible in pg_stat_activity
  Recommendation: Refactor to persistent singleton connection per script.
          Not changed in this session (monitoring scripts are dev tooling,
          not production path). Flag for next monitoring iteration.
  Status: NOTED — not blocking

  PERF-002  No HTTP /health endpoint for external uptime monitors   SEVERITY: MED
  ──────────────────────────────────────────────────────────────────────────────
  Detail: No `/health` or `/status` route exists in src/server/routes/.
          External uptime checkers (UptimeRobot, BetterStack, etc.) have
          nothing to ping. All monitoring is internal terminal scripts only.
  Recommendation: Add a lightweight GET /health route returning
          { status: 'ok', version, uptime, db: boolean } — zero auth,
          rate-limited. Ideal for CDN and uptime integrations.
  Status: OPEN — recommend next session
