FINDING (fixed) — Intentions Widget: write/read split
  `handleSetIntention()` in IntentionsWidget.tsx called `recordSignal(...)`
  (client-only QIE store) and `localStorage.setItem(...)`, but never called
  `useCreateLog()` — no server-side Log row was ever created with
  event: 'intention'. Meanwhile the server actively reads that event:
    - GET /api/stats/patterns ("Live Intention Patterns")
    - GET /api/system/pulse intentions-today count
    - admin-api.ts diagnostic panel for "IntentionPatterns Widget"
    - scheduled-jobs.ts weekly intent-to-action-gap detection (P95) and
      multiple cohort/digest jobs keyed on `event: 'intention'`
    - useLogContext.ts hasIntention / todayIntentionCount (drives the CQGS
      "dormant module" directive and engagement-level scoring)
    - Logs.tsx already has a renderer for `log.event === 'intention'`
    - `/api/logs`'s own displayableEvents allowlist already includes
      'intention' (api.ts:1096) — the read path was fully provisioned and
      waiting for a write that never came.
  Net effect: every user's Intentions module has always scored "dormant" in
  their own biofeedback breakdown, live intention-pattern stats have always
  been empty, and the intent-to-action-gap job has had nothing to detect —
  regardless of actual usage.
  FIX: IntentionsWidget.tsx now also calls `createLog({ text: focus,
  event: 'intention' })` on set, mirroring PlannerWidget's existing
  plan_set pattern exactly. Added `case 'intention'` to formatLog() in
  memory.ts (mirrors the 'plan_set' case) so stated intentions now also
  reach the Memory Engine's narrative-building prompt.

INTERACTIVE CONTEXT SYNC -> LOG (weather / time / users online)
  Real-time presence and shared state travel over a dedicated `sync` channel
  (app.tsx: `sync.listen('users_online' | 'users_total' | 'live_message' |
  'settings_updated')`) distinct from the per-user Signal Archive — both
  `users_online` and `users_total` are also valid Log `event` values
  server-side, so the same signals are durably recorded, not just broadcast
  live. Weather reaches widgets via `useWeather()` (React Query,
  refetchOnWindowFocus: false) and is written into Log `context` on every
  entry (temperature/humidity rendered inline by formatLog), not as a
  separate event — correct by design, since weather is ambient context for
  every log line rather than a discrete widget action.
