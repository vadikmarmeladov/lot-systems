05 // WHAT WAS BUILT
--------------------------------------------------------------------------------
CLIENT TRIGGER   `/email to <name> [message]` added to the same Log-composer
                 trigger system as /breathe /qi /prayer /assembly (logTriggers
                 .ts RULES + Logs.tsx trigger loop). Two-step parse, same
                 shape as /qi: detectTriggers() flags the keyword, a follow-up
                 regex (`/\/email\s+to\s+(\S+)\s*([\s\S]*)/i`) in the handler
                 pulls name + message out of the raw textarea text. Result
                 renders inline under a `MAIL:` block label — same pattern as
                 SIL:/FREEZE:/FAST:/PHYS: — showing delivery status and, when
                 applicable, the Cohort match percentage.

SERVER ROUTE     POST /api/mail/send {name, message}. Resolves candidates via
                 Sequelize.fn('CONCAT', firstName, ' ', lastName) ILIKE — the
                 same pattern already used (admin-only) in GET /admin-api/
                 users, now exposed to ordinary authenticated users for this
                 purpose. Excludes self and suspended accounts (same tag check
                 as chat posting). 0 matches -> 404. >1 match -> disambiguates
                 via findCohortMatches() (src/server/utils/patterns.ts),
                 scoped to just the candidate set instead of the full
                 200-user /api/cohorts pool, so LOT Community/Cohort
                 similarity breaks the tie. Delivers by creating a
                 DirectMessage row (envelope-prefixed "✉ LOT MAIL — <text>")
                 and calling the same sync.emit('direct_message', ...) + Log
                 audit trail (event: email_sent) that the existing manual-DM
                 route uses. No new table, no new model.

SSE RELAY FIX    /api/sync's per-connection `switch(event)` had no case for
                 'direct_message' — DirectMessage creation already called
                 sync.emit('direct_message', ...) (pre-existing code, the
                 manual DM feature), but the SSE endpoint silently dropped it
                 since it wasn't in the whitelist switch. DirectMessageThread.
                 tsx's `sync.listen('direct_message', ...)` (already present)
                 was therefore dead code — messages only appeared after a
                 manual refetch. Added the missing case, scoped to the
                 connected identity (data.receiverId/senderId === req.user.id)
                 so it stays private like settings_updated, not broadcast like
                 chat_message. This fix benefits ALL direct messages, not only
                 mail.

SYNC SURFACE     Sync.tsx now listens for direct_message events addressed to
                 the current user and shows a small "MAIL <sender>: <preview>"
                 banner above the group-chat feed (session-only, up to 5,
                 click opens /dm/:senderId). Satisfies "new messages appear in
                 Sync" without a persisted inbox-list endpoint — deferred, see
                 08.
