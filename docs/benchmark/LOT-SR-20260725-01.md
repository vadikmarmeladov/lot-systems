05 // FEATURES IMPLEMENTED (this session)
--------------------------------------------------------------------------------
F1 MILITARY TIME     New `formatMilitaryTime()` in client/utils/index.ts:
                     "09:30" -> "0930H"; no time -> "ALL-DAY". Shared by
                     CalendarWidget (add-entry input, selected-date list,
                     upcoming list) and Logs.tsx CAL: block — one source of
                     truth for the notation, no duplicated formatting logic.
F2 TIME TRACKING     CalendarEntry gained an optional `time` field (24h
                     `<input type="time">` next to the existing text input).
                     Entries persist `time` in log.metadata alongside the
                     existing date/text/entryType. Sort key is now
                     `date + time` (all-day entries sort first within a day)
                     instead of date-only.
F3 T-MINUS COUNTDOWN Widget now ticks a `now` state every 60s (cleared on
                     unmount) and derives a live "T-MINUS Nd/Nh/Nm · NEXT"
                     line above the upcoming-entries list for the nearest
                     entry — genuine time-tracking, not just a static list.
                     Also fixes a correctness edge: `today`/`upcomingEntries`
                     previously computed `dayjs()` fresh per render with no
                     re-render trigger, so a widget left open across midnight
                     could silently show yesterday's "today" until some
                     unrelated state change forced a re-render.
F4 CAL: LOG BLOCK    Logs.tsx's calendar_entry branch (pre-existing, line
                     ~1656) rendered only entryType + raw date string — the
                     actual entry text was never shown in the Log feed at
                     all. Enriched to a two-tier stylish block: TYPE / TIME
                     header row (uppercase tracking-widest + military time),
                     entry text at 80% opacity, formatted date at 30% opacity
                     uppercase tracking-widest — matching the visual grammar
                     already established by OS [MODE]:, COHORT:, etc. blocks
                     elsewhere in Logs.tsx.
F5 MEMORY ENGINE FIX doctrine already documents (Widget→Memory Compression
                     Loop clause) that any log event without an explicit
                     formatLog() case is silently erased from the AI prompt
                     context — invisible even though logged. Audited: this
                     was true of calendar_entry. Traced the actual live
                     formatLog() to src/server/utils/memory.ts (the
                     `#server/utils/memory` package-import subpath resolves
                     to the flat memory.ts file, NOT the memory/ directory's
                     question-generator.ts — that refactored module tree is
                     unwired dead code, confirmed via package.json `imports`
                     wildcard mapping). Added a `case 'calendar_entry':` to
                     the live formatLog(), so scheduled entries now reach the
                     Memory Engine's question-generation prompt.
F6 RELIABILITY       React keys for entriesOnDate/upcomingEntries switched
                     from array index to `log.id` (CalendarEntry now carries
                     `id`) — correct reconciliation identity for a list that
                     can reorder (time-aware sort) or grow live.
