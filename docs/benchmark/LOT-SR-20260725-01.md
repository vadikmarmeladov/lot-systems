06 // WHAT CHANGED, IN DETAIL
--------------------------------------------------------------------------------
/story day|week|month|year (src/server/routes/api.ts, POST /story):
  - period is optional; omitted, behavior is byte-for-byte the pre-existing
    "recent" path (last ~10 of the most recent 200 logs) — no regression for
    existing callers of the unscoped command.
  - When set, the log query window becomes createdAt >= now - {1,7,30,365}
    days (day/week/month/year), pool widens to 500 rows and the per-category
    sample widens from 10 to 25 before the prompt's final top-5 slice, and
    the system prompt is told explicitly which window it may draw from ("ONLY
    the last 24 hours", etc.) so the model can't quietly reach past the
    requested scope.
  - Word-count target and max_tokens scale with period (day: 60-100w/320
    tok; week: 100-200w/512 tok — the original numbers; month: 150-250w/640
    tok; year: 200-320w/768 tok).
  - Response now echoes period; Log.create metadata records it too, so a
    generated_story row is self-describing about which window produced it.
  - This is a per-request, on-demand sibling to the existing Job 24 (Sunday
    18:00 UTC weekly auto-story) — Job 24 stays untouched; it is a template
    (no AI call) cadence-driven compression, this is an AI-call, operator-
    invoked, any-period compression. Two different tools for the same
    "compress the loop" idea in the S-2 brief, now both present.

/system derived from RULES (src/client/utils/logTriggers.ts, src/client/
components/Logs.tsx):
  - TriggerRule gained optional description/usage fields; every typed
    command (i.e. every rule with a non-empty keywords array) got a
    description, cohort-support (emoji-only, reactive, not typeable) stays
    undocumented on purpose.
  - New export listCommands() maps RULES to {command, usage, description}.
  - Logs.tsx's system-help handler now builds its help lines from
    listCommands() instead of a 17-line hand-written array. The old array
    had already drifted: /sil (sil-check trigger, added in an earlier
    session) was never added to the help text, so an operator asking
    /system for the full command list was given an incomplete answer with
    no way to know it was incomplete. Structural fix, not a spot patch:
    there is now exactly one registry.
