FIX LOG:
  F1  UserMetricsWidget.tsx:98 — classifyPhysiologicalCohort() called with
      ZERO of its 3 required args (signals, userState, recognizedPatterns).
      Every invocation threw inside the function on `signals.filter(...)`
      (signals was undefined). The call sat inside a useMemo with no
      try/catch, so WidgetErrorBoundary caught it on every render — the
      entire "Dashboard" widget stack (UserMetricsWidget, CorrelatedIndexes-
      Widget, SystemProgressWidget, SystemPulseWidget — 4 widgets, one shared
      boundary) rendered NOTHING for every user, silently, since this landed
      in commit 9364aba (2026-07-28). ~1 week of total outage on that stack.
      Fixed: pass the 3 args (matching the working call sites in System.tsx,
      SystemPulseWidget.tsx, QuantumEngineWidgets.tsx); guard on empty
      signals. Also fixed 2 stale property reads on the return value
      (`.label`/`.dominant` don't exist on PhysiologicalCohortClassification —
      the real fields are `.archetype`/`.dominantModule`) that would have
      rendered blank even after the arg fix.
  F2  SignalStreamWidget.tsx / EvolutionWidget.tsx — both had a `useMemo`
      hook placed AFTER an early `return null`, so the two widgets called a
      different number of hooks depending on data state (signals.length < 3;
      narrativeData/logs not yet loaded). React threw "Rendered more hooks
      than during the previous render" the instant that boundary crossed —
      crashing the "Biofield Engine" and "Bioethics" widget stacks (7 widgets
      total behind those two boundaries). Fixed: hooks moved before the early
      return in both files, matching the Rules-of-Hooks placement the same
      2026-07-28 commit got right in UserMetricsWidget but missed here.
  F3  CohortConnectWidget (via usePunctuationContext) — infinite render loop
      ("Maximum update depth exceeded") crashing the "Community" stack
      (PatternInsightsWidget, MoodAnalytics, CohortConnectWidget). Root cause:
      `const { data: logs = [] } = useLogs()` creates a NEW empty-array
      reference on every render whenever `data` is undefined (query loading/
      erroring) — the effect's `[logs]` dep never stabilizes, so it re-fires
      every render. Compounding: updatePunctuationFromLogs()'s empty-input
      branch had no no-op guard (unlike the populated-input branch two lines
      below it) and unconditionally called .set() with a fresh timestamped
      object every call, so the store notified every single re-fire — a true
      loop, not just wasted effect churn. Fixed both: stable EMPTY_LOGS
      module constant; no-op guard added to the empty branch.
  F4  QuantumEngineWidgets.tsx — the 6 device-connect handlers
      (handleCarConnect etc.) called recordSignal() (a store write) INSIDE
      the setState updater function passed to setCarConnected/etc. React
      flagged this live during the button-lag pass ("Cannot update a
      component while rendering a different component") when the connect
      buttons were clicked. State updaters must be pure. Fixed: compute
      `next` from the captured state value and call recordSignal() directly
      in the handler body, outside the updater.
  F5  InterventionsWidget / EnergyCapacitor / GoalJourneyWidget /
      MicroImageWidget — all four call recordSignal() directly in the render
      body (ref-guarded "once per mount"), which is a store write during
      render — the same anti-pattern already named in doctrine (Render
      Isolation corollary, D-clause "atom writes must not run inside
      useMemo/render phase"). Confirmed live via the same React warning.
      Fixed: moved into useEffect, guard preserved.
  F6  GET /api/community-emotion (api.ts) — Sequelize `attributes:
      ['emotionalState', 'createdAt']` selected a column that does not exist
      on `logs` (the value lives at `metadata.emotionalState`, a JSONB path
      — the pattern used correctly everywhere else in the codebase: energy.ts,
      weekly-summary.ts, monthly-summary.ts, contextual-prompts.ts). Every
      call threw a Postgres 42703 and the route 500'd, every time, with no
      symptom beyond a swallowed try/catch — the System-tab "shared community
      emotional state" pulse (communityEmotion.sharedEmotion in System.tsx)
      has silently never shown a value for any user who reached it. Fixed:
      select `metadata`, read `.metadata?.emotionalState`.
  F7  Two dynamic <style> injection sites (evolution.ts theme-animation CSS;
      EvolutionMilestoneToast.tsx toast fade keyframes) create `<style>`
      elements with no nonce. The CSP header requires
      `style-src 'nonce-<per-request>'`; the server already generates
      `reply.cspNonce.style` and passes `styleNonce` into every view render,
      but generic-spa.ejs never emitted it into the HTML, so there was no way
      for client JS to read it. Both style blocks have been silently dropped
      by the browser (console warning only, confirmed live via a
      securitypolicyviolation listener) since strict CSP went in — evolution
      theme animations and the milestone-toast fade/slide keyframes have
      never actually applied. Fixed: styleNonce now emitted as
      `<meta name="csp-style-nonce">`; both call sites read it and set
      `.nonce` on the created element before appending.
