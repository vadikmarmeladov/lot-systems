## SYSTEM DESIGN

### Compose Flow (Log)

```
User types: /email to Hitomi
      ↓
logTriggers.ts detects `compose-email`
      ↓
NoteEditor handler:
  - parse recipient name from "/email to {name}"
  - call searchUsers(name) → GET /api/users/search?q=Hitomi
  - set emailCompose state: { status: 'resolving' → 'ready' }
      ↓
MSG [COMPOSE]: block appears below textarea
  TO: Hitomi Tanaka
  [ message textarea ]
  [ Send ] [ Cancel ]
      ↓
On Send: POST /api/direct-messages
  - creates DirectMessage record
  - emits SSE `direct_message` event to receiver
  - logs `direct_message_sent` event with receiverName in metadata
```

### Delivery Flow (Sync)

```
Receiver opens Sync tab
      ↓
useDirectMessagesInbox() → GET /api/direct-messages
  - returns messages where receiverId = me.id
  - includes sender { id, firstName, lastName }
      ↓
SSE listener for `direct_message` event
  - real-time delivery if Sync tab is open
  - merged with fetched inbox (deduplicated)
      ↓
Messages section above chat feed:
  Hitomi  [message text]  [timestamp]
```

### Log Rendering

`direct_message_sent` events now render in Logs as:

```
MSG [OUT]:
TO: HITOMI TANAKA
[message text]
```

### Cohort Dating Integration

`CohortConnectWidget` "Send message" button now routes to the Logs tab (not Sync), where the user can naturally type `/email to {name}` to compose a direct message to the cohort match.

## API ADDITIONS

### `GET /api/direct-messages` (requires auth)
Returns inbox: all DMs where `receiverId = me.id`, most recent first, limit 50. Includes sender info.

```json
[{
  "id": "uuid",
  "senderId": "uuid",
  "receiverId": "uuid",
  "message": "string",
  "createdAt": "ISO8601",
  "sender": { "id": "uuid", "firstName": "string", "lastName": "string" }
}]
```

### `GET /api/users/search?q={name}` (requires auth)
Returns up to 10 users matching first or last name (case-insensitive). Excludes self.

```json
[{ "id": "uuid", "firstName": "string", "lastName": "string" }]
```
