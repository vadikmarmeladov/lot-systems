WHAT WAS BUILT

1. Time tracking — CalendarWidget.tsx
   Entries carry an optional `time` (HH:mm) alongside `date`. Add-entry form
   gained a native `<input type="time">` next to the text field. Both the
   day-detail panel and the upcoming list render the time inline
   (tabular-nums) when set.

2. Status tags — getEntryStatus(date)
   Pure function: diffs target date against today, returns OVERDUE / TODAY /
   TOMORROW / `IN Nd`. Upcoming rows show the tag at full-opacity-30 next to
   the entry text — data only, no color, matches COCKPIT-RULE.

3. Reliability: completion loop, not deletion
   No DELETE endpoint exists for /api/logs (PUT only rewrites 'note' events).
   Rather than add server surface, completion is a second append-only log:
   `calendar_entry_done` with `metadata.entryId` pointing at the original
   log's id. `getCompletedEntryIds()` + `getActiveCalendarEntries()` (both
   exported, pure, reused by the toast) filter completed entries out of the
   upcoming/overdue lists while the day-detail panel still shows them
   struck-through with a DONE tag — nothing is erased, matching the Log's
   append-only ground truth.
   Overdue entries (date < today, not completed) now surface in their own
   block above the upcoming list — previously they just vanished from view
   with no record the widget had ever missed them.

4. CAL: alert toast — CalendarAlertToast.tsx (new)
   Reads the same /api/logs react-query cache the widget already holds — no
   extra network path. Computes OVERDUE + TODAY active entries, checks on
   mount and every 60s, shows a bordered monospace card (CAL: ALERT header,
   OVERDUE/TODAY counts, up to 4 entries listed). Dedupes via a sorted-id
   signature stored in localStorage — dismissing (or 12s auto-hide) will not
   re-surface the same due-set; a new/completed entry changes the signature
   and the toast reappears once. Mounted in System.tsx next to CalendarWidget,
   same pattern as EvolutionMilestoneToast.

5. Log handlers — Logs.tsx
   CAL: now prints `time` inline with `date` (tabular-nums). New CAL-X:
   handler for calendar_entry_done — "{TYPE} COMPLETE" + date, following the
   existing GOAL-X: completion-suffix convention.

6. QIE wiring — intentionEngine.ts, api.ts
   recordCalendarCompletionSignal(entryType) mirrors recordCalendarSignal —
   distinct signal name so future pattern work (Pattern 26 calendar-gap and
   any follow-through pattern) can tell scheduling from completion apart.
   'calendar_entry_done' added to server displayableEvents whitelist.
