03 // CHANGES MADE
--------------------------------------------------------------------------------

A. DEGRADED STATE — public-api.ts:358-361
   Before: const overall = hasErrors ? 'error' : 'ok'
   After:  const hasSlow = !hasErrors && checks.some(c => (c.duration ?? 0) > 500)
           const overall = hasErrors ? 'error' : hasSlow ? 'degraded' : 'ok'
   Effect: Status page can now surface "Degraded Performance" when all checks
           pass but any individual check exceeds 500ms.

B. ANTHROPIC MODEL — public-api.ts:705
   Before: model: 'claude-3-5-sonnet-20241022'
   After:  model: 'claude-haiku-4-5-20251001'
   Effect: /test-anthropic-key endpoint now uses the cheapest model for
           key-validity pings.

C. checkSettings() — public-api.ts:190-219
   Before: Duplicate User.findOne() + app.js fs check (both covered by
           other checks)
   After:  Validates JWT secret (exists + length >= 32) + appName + appHost
           config presence.
   Effect: Settings health check now has a unique, meaningful signal.

D. StatusPage VISUAL UPGRADE — StatusPage.tsx
   - Overall status banner: colored left-border strip with text-green /
     text-yellow / text-red, matching the three possible states.
   - Status dots: replaced ✓/✕/? ASCII with inline w-8 h-8 rounded-full
     spans using bg-green, bg-red, bg-yellow (LOT design system colors).
   - Status labels: "Operational" / "Outage" / "Unknown" in matching semantic
     colors instead of generic "Ok" / "Error" / "Unknown" in opacity.
   - Latency badges: text-green (<100ms) / text-yellow (100-500ms) /
     text-red (>500ms) — performance tiers at a glance.
   - Error messages: text-red/80 for outage details (was text-acc/60).
   - Memory Engine section: dots replace ✓/✕ for next-prompt availability.
   - Footer: updated copy to reflect auto-refresh + cache cadence.
   - Loading state: "Checking systems…" replaces "Loading...".

E. CORE WEB VITALS — src/client/utils/perf.ts
   - LCP observer: fires on largest-contentful-paint, stores to
     window.__LOT_PERF__.lcp, warns at >2500ms.
   - CLS observer: accumulates layout-shift (excluding hadRecentInput),
     stores to window.__LOT_PERF__.cls, warns at >0.1.
