§1 WIRING / DATA STORAGE / TESTING
  - TESTING: zero test files in the repo (no *.test.ts(x), *.spec.ts(x); no
    jest/vitest/mocha/playwright in package.json). The only "tests" are five
    manual scripts/tests/*.ts smoke checks (db, email, cold-start, prod env).
    NOTABLE — the single largest gap this scan surfaced. No unit/integration
    coverage exists for any of the 43 widgets, System.tsx, the QIE store, or
    the Log/signal pipeline; regressions are caught only by the build
    typecheck + manual S-2 review.
  - FIXED (data bug): src/client/utils/badges.ts had two duplicate object
    keys — `quarter_drop` (Arcade Class v6 "first easter egg of any type",
    line 3214) silently shadowed by a second `quarter_drop` (midnight
    check-in, line 5501); `elixir_found` (Alchemist v12, hidden, line 4825)
    silently shadowed by a second `elixir_found` (Hero's Journey v22, line
    6883). In a JS object literal the later key wins — both first-defined
    badges were permanently unreachable in the live BADGES map even though
    their trigger code ran. Renamed the shadowed entries to
    `first_egg_unlocked` and `elixir_transmuted`, repointed the one live
    caller each had (easter-eggs.ts word-trigger for elixir; the Alchemist
    v12 completion array for the other) — see easter-eggs.ts:1359,
    badges.ts:7558. `first_egg_unlocked` has NO trigger call site anywhere
    in the repo (confirmed by full-repo grep) — it was declared but never
    wired to an award event even before the collision. Not fixed here:
    inventing "award on first-ever easter egg" logic is a feature addition,
    not a dedup fix — flagging for S-2 as a build candidate, not building it
    unasked.
  - ORPHANED WIDGET: AwarenessDashboard.tsx exists and is documented in
    WIDGETS.md, but is never imported by System.tsx or anywhere else in
    src/client. Confirmed intentional per LOT-SR-20260719-01 (skipped as a
    duplicate of a live widget) — not a fresh regression, but WIDGETS.md
    still lists it as live; doc should eventually note it's parked.
  - Sampled wiring (Memory, Planner, GoalJourney, QuantumState, Recipe,
    Subscribe, stats stack) otherwise matches WIDGETS.md claims exactly —
    correct endpoint/nanostore per widget, correct recordSignal() calls.

§2 LOT AI / SYSTEM TAB / PORTRAIT
  - AIFeedbackWidget.tsx is fully wired end-to-end (os-diagnostics, profile,
    logs, intentionEngine, Together.AI) — not stubbed.
  - Portrait (PublicProfile.tsx) runs on a SEPARATE data path from the
    System tab: /api/public/profile/:id (public-api.ts) vs. the
    authenticated /api/user-profile used by System.tsx's useProfile().
    Shared trait/cohort extraction is reused, but streak/OS-version/pattern-
    strength math is independently re-implemented on the Portrait side —
    duplication/divergence risk, not currently broken.
  - Two competing generateMemoryStory implementations: server/utils/
    memory.ts (used by the authenticated app) vs. server/utils/memory/
    story-generator.ts (used only by Portrait). Both call Together.AI
    independently and both work; it's a fork, not a break.

§3 QIE / MEMORY / STORY
  - Central QIE store confirmed at src/client/stores/intentionEngine.ts.
    recordSignal() mutates the nanostore client-side and defers persistence
    via schedulePersist() — it does not itself POST to /api/logs; widgets
    that "record a signal" per WIDGETS.md do so correctly (verified by
    direct grep of each sampled widget's call site).
  - "Story" is computed by THREE separate functions total: NarrativeWidget's
    generateUserNarrative (api.ts), and the two forked generateMemoryStory
    variants in §2. No broken path found, but three independent
    implementations of the same concept is a consistency risk over time.

§4 CONTEXT SYNC / LOG
  - Main /api/logs handler is correctly bounded (limit 500, user-scoped,
    explicit event whitelist) — not a lag source.
  - Two CSV-export log queries (emotional_checkin export, self_care export in
    api.ts) run unbounded, no LIMIT / date filter, full-history scan per
    click. User-scoped so not a thundering-herd risk, but will degrade for
    long-tenured accounts. Minor, not fixed this session (export path, not
    a widget-render path — out of scope for a wiring/lag dedup pass).

§5 LOADING SPEED / LAG

  - The July-19 render-unblock pattern (useEffect over useMemo for atom

  - React-query polling is uniformly refetchInterval: 120000 with
    refetchIntervalInBackground: false across the board; no sub-10s network
    poll exists outside the already-documented, intentional cases.
