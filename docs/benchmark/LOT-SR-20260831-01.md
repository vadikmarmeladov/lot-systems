What changed, precisely:
- POST /api/story now accepts an optional `period` field
  ('day'|'week'|'month'|'year', default 'day'). Each period maps to a
  window (1/7/30/365 days via dayjs().subtract()), a widened entry sample
  size (10/25/60/150 rows) so a year-story isn't drawn from the same
  handful of rows as a day-story, and a target word count (100-200 through
  250-350) passed into the AI prompt.
- Log query is now `createdAt: { [Op.gte]: since }` scoped instead of an
  unbounded "last 200 rows regardless of age" query — a real behavior
  change: previously a /story on a quiet account could reach back months
  for its 10 sample rows with no window framing at all.
- New peak detection: moods are scored against a fixed 10-point low->high
  vocabulary (depleted..thriving); when 2+ distinct scored moods exist in
  the window, the single highest and lowest are surfaced to the prompt as
  HIGH POINT / LOW POINT with date, and the prompt is instructed to name
  both plainly rather than flatten the story toward positivity or caution.
  This is the "surface more intimate high and low peaks" requirement from
  the LOT AI know-how doc, made concrete and testable.
- Logs.tsx: `/story week`, `/story month`, `/story year` now parse from
  the log text (regex on the value before it's sent), default remains bare
  `/story`. The /system help screen lists all four forms explicitly instead
  of one generic /story line.
- queries.ts: `useStoryGeneration` mutation body type gained `period?`.
- logTriggers.ts: trigger detection unchanged (keyword match on `/story` is
  a prefix match already tolerant of a trailing argument) — only the
  documentation comment on the `story-mode` trigger was updated to state
  the new argument.
- metadata.period is persisted on the generated_story Log row so period
  usage is queryable later without re-parsing text.
