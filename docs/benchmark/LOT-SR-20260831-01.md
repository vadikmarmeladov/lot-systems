05 // WHAT WAS BUILT
--------------------------------------------------------------------------------
TIME TRACKING     Entry form gained a native <input type="time"> beside the
                  text field. Stored as metadata.time (HH:mm, optional) on
                  the calendar_entry log; folded into the [SCHEDULE] log text.
                  Entries sort by date then time (untimed entries sort last
                  within their day) in both the day view and upcoming list.

EVT [DUE] ALERT   Reused the house military-log idiom already established in
                  Logs.tsx (CAL:, BPEAK:, MER: block-header + uppercase
                  tracking-widest rows) for a live, not just retrospective,
                  notification: a fixed toast reading "EVT [DUE]:" / entry
                  type · time / entry text, with an ACK control. Fires when a
                  timed entry's moment arrives, using the same visibility-
                  gated setInterval(20s) + !document.hidden pattern as
                  EvolutionMilestoneToast.tsx (no new toast infra — the app
                  has no global notification root; each widget renders its
                  own fixed overlay). A 15-minute due window and a
                  localStorage ack-id set (mirrors EvolutionMilestoneToast's
                  seen-milestone dedup) mean a background tab won't miss the
                  alert and won't re-fire it after ack or reload.

RELIABILITY       Calendar entries previously had no way to be undone — the
                  only correction path in the whole Log system was PUT
                  /logs/:id's backspace-to-empty delete, and that endpoint
                  hard-coded `if (log.event !== 'note') return log`, silently
                  no-opping for calendar_entry. Extended the delete branch to
                  also accept calendar_entry (edit remains note-only, since
                  a calendar_entry's display text is derived from structured
                  metadata a text-only PUT can't keep in sync). Added a
                  "remove" control (opacity-0, group-hover reveal — matches
                  the file's existing hover-reveal idiom) to both the open-day
                  list and the upcoming list.

SECURITY FIX      PUT /logs/:id had no ownership check at all — findByPk by
                  id, then act, no `userId === req.user.id` comparison. Any
                  authenticated user could edit or delete another user's log
                  by id (IDOR). Extending this endpoint's reach to a second
                  event type without closing that gap would have widened a
                  live vulnerability, so it was fixed in the same change:
                  `if (log.userId !== req.user.id) return reply.throw.notFound()`
                  — same 404-on-mismatch shape used elsewhere in api.ts.

LOGS.tsx CAL:     Added a TIME row to the existing CAL: block-header render
                  (opacity-40, tabular-nums, matching the QOS-COHR/BPEAK
                  number-row convention) so timed entries show their time in
                  the retrospective Log view too, not only inside the widget.

SIGNAL WIRING     recordCalendarSignal(entryType, date, time?) — time is now
                  threaded into the QIE signal metadata for future patterns
                  that want it (Pattern 26 calendar-gap etc. untouched this
                  session — no pattern currently reads it).
