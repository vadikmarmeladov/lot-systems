What changed, concretely:
- CalendarEntry gained `time?: string` (HH:mm) and `reminderMinutes?: number`,
  both stored in the existing calendar_entry Log metadata — no schema
  migration, metadata is already JSONB.
- Add-entry form gained a `<input type="time">` and a reminder-lead select
  (at time / 5m / 15m / 30m / 1h / 1d before), shown only once a time is set.
- getEntryStatus() classifies each entry live: overdue -> MISSED (struck
  through, dimmed), due within 5 min -> ● NOW (full opacity), else upcoming
  or ALL-DAY. A 30s tick (paused via document.hidden) keeps status current
  without hammering re-renders.
- CalendarNotifications: a new global toast (mounted in System.tsx beside
  CalendarWidget, same pattern as EvolutionMilestoneToast) polls Log-sourced
  calendar entries every 20s, fires once per entry when now crosses
  (event time - reminderMinutes) within a 3-minute grace window, plays a
  new two-tone square-wave klaxon (alertKlaxon.ts, sharper than the hourly
  Soviet chime), and writes a calendar_notification Log entry as the audit
  trail — the notification itself is tracked, per the S-2 brief. Fired keys
  persist in localStorage (calendar_notified_v1, capped at 500) so a reload
  never double-fires.
- Toast styling stays in the existing monochrome accent system (no new
  colors): bordered box, uppercase tracking-widest "[ SCHEDULE ALERT //
  HH:MM ]" header, blinking ◆ markers — military-grade signaling without
  breaking the minimalist grid the rest of the UI already uses.
