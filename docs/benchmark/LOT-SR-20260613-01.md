---

## ARCHITECTURE OVERVIEW

LOT Mail is built on the existing `DirectMessage` infrastructure — zero new database tables. The system layers three surfaces:

```
LOG (compose)
  └── /email to [name] trigger
        └── MAIL [COMPOSE]: inline block
              └── POST /api/direct-messages
                    └── sync.emit('direct_message', payload)
                          ├── SYNC tab: MAIL [RECV]: block (receiver)
                          └── LOG stream: MAIL [SENT]: / MAIL [RECV]: blocks
```

### 4. `src/server/routes/api.ts`
**New endpoint:**
- `GET /api/users/search?q=` — case-insensitive first/last name match, max 5 results, excludes self

**SSE switch — added `direct_message` case:**
- Forwards DM events only to `senderId` or `receiverId` (never broadcasts)
- This enables real-time delivery of mail to the recipient's Sync tab

**DM POST route — enhanced:**
- Added `receiverName` to sender's `direct_message_sent` log metadata
- Added `direct_message_received` log creation for the receiver
- Included `updatedAt` in SSE payload

**displayableEvents whitelist:**
- Added `direct_message_sent` and `direct_message_received`
- These now appear in the Log stream as `MAIL [SENT]:` and `MAIL [RECV]:` blocks

### 5. `src/client/components/Logs.tsx`
**Log block renderers:**
- `direct_message_sent` → `MAIL [SENT]: TO: [name] / [message]`
- `direct_message_received` → `MAIL [RECV]: FROM: [name] / [message]`

**NoteEditor — lot-email trigger handler:**
- Imports `useSendDirectMessage`, `searchUsers`
- State: `mailCompose` with fields `{query, toId, toName, body, status}`
- Status flow: `searching → compose → sending → sent / error`
- Effect: on trigger fire, parses recipient name from `/email to [name]`, kicks off `searchUsers`
- Renders `MAIL [COMPOSE]:` block inline below the textarea
  - Shows recipient lookup result
  - Body textarea + Send button + Cancel
  - On send: calls `sendDirectMessage({ receiverId, message })`
  - On success: transitions to `sent` state → `TRANSMITTED → [NAME]` display

### 6. `src/client/components/Sync.tsx`

- Added `direct_message` SSE listener — appends messages where `receiverId === me.id`

### 7. `src/client/components/CohortConnectWidget.tsx`

## USER FLOW

```
1. User types in Log:
   /email to Hitomi

2. Trigger fires → MAIL [COMPOSE]: appears inline
   TO   HITOMI
   [ message body... ]
   [Send]  [Cancel]

3. User types message body, presses Send

4. POST /api/direct-messages → DirectMessage created
   sync.emit('direct_message', { senderId, receiverId, message, senderName, ... })

5. Sender sees:
   MAIL [SENT]:
   TO: HITOMI
   [message text]
   (recorded in Log stream as direct_message_sent event)

6. Receiver (Hitomi) — real-time in Sync tab:
   MAIL [RECV]:
   FROM: [SENDER NAME]
   [message text]
   [timestamp]

7. Receiver's Log stream:
   MAIL [RECV]:
   FROM: [SENDER NAME]
   [message text]
   (recorded as direct_message_received event)

8. Cohort Dating:
   CohortConnectWidget "Send Message" → /dm/:userId
   Opens DirectMessageThread for full conversation
```
