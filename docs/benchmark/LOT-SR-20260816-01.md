05 // ROUTINES IMPLEMENTED (this session)
--------------------------------------------------------------------------------
R1 TIME-OF-DAY        Entries carry an optional HH:mm (validated via TIME_RE,
                       stored in log.metadata.time). Add-entry form gained a
                       native <input type="time"> beside the existing text
                       field — one control, no new UI section.
R2 T-MINUS READOUT     Live countdown to the next entry with a future
                       date+time, ticking once a minute (paused on hidden
                       tabs, matching the codebase's existing document.hidden
                       gating convention). Small font-mono line next to
                       "Add date" — this is the "track time" half of the ask.
R3 ALERT ENGINE        20s poll (also hidden-tab gated) diffs entries against
                       the clock. First time an entry's scheduled datetime is
                       reached (and still within a 12h grace window, so a
                       stale reload never dumps a backlog), it fires once:
                       writes a calendar_alert Log entry, shows a military-
                       log-styled toast, and — if permission was granted —
                       a native browser Notification.
R4 MILITARY TOAST      Fixed top-right, font-mono text-xs, ASCII-bordered
                       (border-acc/40, header rule, uppercase tracking-widest
                       label "LOT · CALENDAR ALERT"), 8s auto-dismiss with the
                       same fadeInUp/fadeOut keyframes used by
                       EvolutionMilestoneToast — defined locally too so this
                       widget doesn't depend on that module's load order.
                       Matches the "Military-log aesthetic: ASCII-bordered
                       entries, font-mono text-xs" already documented in
                       About.tsx for ArchitectWidget's Transmission log.
R5 RELIABLE DEDUP      Notified entry ids persist to localStorage
                       (calendar_notified_ids_v1, capped at 500) so the same
                       alert never re-fires across reloads or remounts; a
                       useRef holds the live Set to avoid re-render churn.
R6 DISPLAY             Time shown alongside text in both the selected-date
                       entry list and the upcoming-entries list; entries now
                       sort by date then time.
