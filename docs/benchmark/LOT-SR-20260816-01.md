05 // FINDINGS + FIXES (this session)
--------------------------------------------------------------------------------
F1 RENDER FLICKER (fixed)
   System.tsx IntentionsWidget/SubscribeWidget gates called Math.random()
   directly inside a render-body IIFE. Every re-render of System.tsx (any
   store write anywhere in the subscriber tree) redrew the dice — the 2-3
   day intentions cooldown and the 20% subscribe-prompt roll could flip a
   widget in or out of the tree on renders that had nothing to do with
   either widget. Fixed: both rolls now anchor to a `useRef(Math.random())`
   taken once per mount. Same class as the DOCTRINE Render Isolation clause,
   new instance — RANDOM-INSTABILITY is a CANDIDATE token (1st occurrence).

F2 DEAD WIDGETS REMOVED (fixed)
   AwarenessDashboard.tsx (179 lines) and JournalReflection.tsx (80 lines)
   carried zero imports anywhere in the client. SR-20260719-01 had already
   decided to skip both as duplicates of MoodAnalytics/GoalJourneyWidget but
   never deleted the files; WIDGETS.md still documented Awareness Dashboard
   as "integrated into the System.tsx layout." Deleted both files, corrected
   the doc entry to a retirement note.

F3 STALE CONSOLE.LOG (fixed)
   RecipeWidget's log-on-view mutation printed `Logged recipe: ${key}` to
   the console on every successful write — a debug leftover, noise on every
   recipe view. Removed; onError path (which matters) is untouched.

F4 DOC DRIFT — SystemPulseWidget (fixed)
   WIDGETS.md still described "1-second polling"; the widget has polled at
   10s (foreground-only, route-gated) since SR-20260719-01 R1. Doc updated
   to match the live interval and its two guards.

F5 DUPLICATE BADGE KEYS (recorded, not auto-fixed)
   esbuild flags two duplicate object keys in badges.ts: `quarter_drop`
   (line 3214 "first easter egg of any kind," uncommon vs. line 5501
   "midnight check-in," rare) and `elixir_found` (line 4825 Alchemist-arc
   "write elixir," uncommon vs. line 6883 Hero's-Journey-arc "elixir/boon/
   treasure," rare). JS object-literal semantics mean the second definition
   silently wins at runtime; the first is dead data, and any advertised
   total badge count is off by up to 2. Both trigger call sites in
   easter-eggs.ts award the surviving key, so nothing crashes — this is a
   data-integrity gap, not a runtime bug. Left unresolved: renaming either
   key changes which badges exist under which IDs, and several docs/ledger
   entries track exact badge-total counts across Codex versions — a rename
   is a content decision for S-2, not a mechanical fix. DUPLICATE-BADGE-KEY
   is a CANDIDATE token (1st occurrence).

F6 WIRING — clean
