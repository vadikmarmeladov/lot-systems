05a // CHANGE DETAIL
--------------------------------------------------------------------------------
CalendarWidget.tsx:
  CalendarEntry type: time?: string (HH:MM) added — backward compatible.
  TYPE_LABEL map: note→NOTE · task→TASK · call→COMM (military designators).
  formatCountdown(): pure fn — date+time+now→ T-Xh·T-Xm·NOW·PAST·T-Nd strings.
  Live ticker: setInterval(30_000) updates `now` state → countdowns stay current.
  alertedRef: session-scoped Set<string> prevents double-fire within a session.
  Auto-alert useEffect: deps=[entries,logs,now]. On each tick, builds existingAlerts
    from persisted calendar_alert logs (date|text key). Any today-entry not in
    existingAlerts and not in alertedRef fires createLog(calendar_alert). Fires once
    per entry per day — persisted key prevents re-fire on page reload.
    Status: TODAY (all-day or time > T+60m) · IMMINENT (entry within 60 minutes).
  Entry form: time input (type="time") added alongside text input. Optional — blank
    stores time:undefined in metadata, existing entries unaffected.
  Sort: entries sorted by datetime key (date+time or date+T23:59 for timeless entries).
  Upcoming list: 4-column display — countdown · date+time · TYPE · text.
    Countdown accent: NOW→text-acc · today→text-acc/60 · future→text-acc/30.
  Selected date entries: inline TYPE + time + text display.

Logs.tsx — calendar_entry block (enhanced):
  Was: TYPE label only + date. Now: TYPE + date+time (right-aligned, tabular-nums),
  entry text on second line (opacity-80). Backward compatible — text field extracted
  from metadata.text (field present in all new entries; absent in legacy → graceful).

Logs.tsx — calendar_alert block (new):
  Label: CAL-ALERT:
  Row 1: STATUS (TODAY/IMMINENT) + T-minus (T-Xm or NOW) — tabular-nums, right.
  Row 2: entry text (body).
  Row 3: TYPE label (left, opacity-30) + date+time (right, tabular-nums, opacity-40).
  Military COCKPIT-RULE compliant: no prose, instrument readings only.

api.ts — displayableEvents whitelist:
  'calendar_alert' added. Required: auto-alert effect reads logs to build
  existingAlerts set — if calendar_alert not in whitelist, GET /api/logs never
  returns them, existingAlerts stays empty, alert fires on every page load.
