## ARCHITECTURE NOTES

**Why localStorage for alert dedup:**  
Server-side dedup would require a new DB table or a metadata query on existing logs. localStorage is sufficient because alerts are per-device and per-user session — the same device should not double-notify, and cross-device dedup is not required for this use case.

**Why T-0 and T-1 only (not T-7):**  
T-7 would fire for every entry the moment it enters a 7-day window, generating noise. T-0 and T-1 represent the two operationally actionable windows (day-of and 24h-out). A T-7 quiet-reminder can be added as a user preference later.

**Why `createLogRef`:**  
`useCreateLog()` returns a `mutate` function with stable identity (react-query guarantee). The ref pattern is used defensively to avoid any stale-closure edge case inside the 5-minute interval.

**T-minus label format:**
- `T-0` — event is today
- `T-1` — event is tomorrow  
- `T-5D` — 5 days out (military countdowns use D-suffix for day-resolution)
- `PAST` — event date has elapsed (shown only if entries slip through the upcoming filter)
