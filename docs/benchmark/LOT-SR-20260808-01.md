DESIGN — how LOT Mail reuses existing LOT infrastructure end to end:

  Log (compose)      Operator types "/email to Hitomi <message>" (or appends
                      /email to a longer journal entry — the log text minus
                      the command token becomes the message body).
       |
       v
  logTriggers.ts      'email-send' fires on the /email token (same
                      detectNewTriggers() framework as /qi, /prayer, /phys —
                      no new parsing infrastructure).
       |
       v
  Logs.tsx             Regex extracts the name token. Recipient is resolved
  (client)              by matching firstName against the operator's
                        useCohorts() match list (LOT Community integration —
                        an operator can only LOT-Mail someone LOT has already
                        surfaced as a cohort/Cohort-Dating match, not an
                        arbitrary user).
       |
       v
  POST /direct-messages  EXISTING endpoint (api.ts ~4021), unmodified. Creates
  (server, unmodified)   a DirectMessage row, emits SSE 'direct_message' to
                          the recipient, writes a Log 'direct_message_sent'
                          audit entry. Zero new server code.
       |
       v
  Sync                  DirectMessageThread (routed at /dm/:userId, listed
                          under the SYNC TAB in LOT-SYSTEM-OUTLINE.md §03)
                          receives the message live via the SSE listener
                          already wired in DirectMessageThread.tsx.
       |
       v
  Log (feedback)        A local MAIL: cockpit-style result block (COCKPIT-RULE
                          — key/value instrument readings, no prose) confirms
                          TO / STATUS / ROUTE inline, matching the /qi, /phys,
                          /prayer result-block convention. Not-found recipients
                          render NOT FOUND — RECIPIENT MUST BE A COHORT MATCH.
