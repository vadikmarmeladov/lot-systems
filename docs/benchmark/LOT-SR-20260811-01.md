--------------------------------------------------------------------------------

label appears in three places, and only one of the three is a real model
call:

  1. EmotionalCheckIn.tsx:156-158,208 — labeled "LOT AI:" in the UI, but
     the response (api.ts:55-134, generateCompassionateResponse) is a

     call.
  2. AIFeedbackWidget.tsx — despite the name, getStateInsight() (54-124)
     and getGuidance() (127-184) are deterministic if/else chains over
     local store state. Zero fetch/mutation calls in the file. Not AI-
     driven output.
  3. ChatCatalystWidget.tsx -> GET /api/chat-catalysts (api.ts:3734+) —
     rule-based cohort matching against User/Log rows. Not LLM-driven.

Where a real LLM genuinely IS wired in (server/utils/ai-engines.ts, a
multi-provider abstraction: Anthropic/OpenAI/Gemini/Mistral/Ollama/
Together):
  - CosmicUpdateWidget.tsx:131-172 (System.tsx:980) — real TogetherAI
    image-generation call, the one widget in System.tsx genuinely driven
    by AI output.
  - /api/qi ("Quantum Intelligence RFI", api.ts:4924-5090+) is the real AI
    conversational surface — but it's invoked from Logs.tsx's /qi slash
    command, NOT from any System.tsx widget. It builds a prompt from
    getUserState()/getUserIndex() (the same intentionEngine values
    AIFeedbackWidget and the Table view display) plus 500 recent logs, and
    calls aiEngineManager.getEngine('together').generateCompletion(). The

prompt; the AI-context wiring lives one surface over, in the log
terminal, reading the identical store. If "LOT AI" is meant to feel like
a unified presence across System/Portrait, today it is namesake-only in
two of its three appearances.

all share one react-query cache key and are correctly deduped by the

10 // "15-MONTH UI REVEAL/BUILD-UP" — WHAT ACTUALLY GATES THE UI TODAY
--------------------------------------------------------------------------------
No calendar-month-based reveal schedule exists in code — searched for
unlockDay/monthGate/revealAt/15-month patterns across src/ and docs/,
found none. What DOES gate UI reveal is engagement-based, not time-based:
utils/interfaceEvolution.ts's calculateEvolutionState() derives
featureUnlockLevel (0-5, gates advanced widgets/features),
visualRefinement (spacing density: breathable -> instrument across 5
layout levels), chapter (1-4, by user level), and badgeTier (0-3, by
badges earned) from achievements + level + streak + entries — i.e. the
interface visibly densifies and unlocks as a user DOES things, not as a
calendar advances. If a literal 15-month phased calendar reveal is the
intended design, it is not implemented anywhere today — the existing
mechanism is progression-based and would need new gating logic to become
time-phased. Flagging this as a design question for S-2 rather than
guessing at unwritten intent.
