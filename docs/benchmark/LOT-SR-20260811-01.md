WHAT CHANGED:

  displayableEvents whitelist  — added 'generated_story'. Every /story
    response server writes is now readable back through GET /logs, matching
    the qi_rfi / prayer_scripture / assembly_directive precedent already in
    the array.

  formatLog() (memory.ts)      — added a case for 'generated_story'. Past
    story compressions now feed the Memory Engine prompt (Widget->Memory
    Compression Loop doctrine clause) instead of silently vanishing.

  Logs.tsx render dispatcher   — added a STORY: / STORY [PERIOD]: Block for
    generated_story, mirroring the existing PRAY: case for prayer_scripture.
    Persisted story compressions now render as their own history entries,
    not only as text glued into the note that triggered them.

  POST /story                  — accepts an optional `period: 'day' | 'week'
    | 'month' | 'year'`. When present, the log query window widens to match
    (1 / 7 / 30 / 365 days), sample sizes scale per period (6/12/24/40
    entries), and the AI prompt asks for a period-scoped compression with a
    period-appropriate word budget (80-120 up to 320-420) instead of the
    fixed ~10-entry "recent" mode. Bare /story is unchanged — same behavior
    as before. Also added a fallback Log.create on engine failure (parity
    with the existing /qi pattern; /story previously returned a canned
    string on error with no record of the attempt at all).

  Logs.tsx story-mode trigger  — parses "/story day|week|month|year" from
    the note text, forwards `period` to the mutation. Falls through to the
    original untimed behavior when no period keyword is present.

  /system help text            — documents the new /story [period] syntax.

  useStoryGeneration (queries.ts) — typed for the new period request field
    and response field.
