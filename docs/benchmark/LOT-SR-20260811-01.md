05 // WHAT SHIPPED (this session, on this branch)
--------------------------------------------------------------------------------
CalendarWidget.tsx — replaced the plain date-only scheduler with the fuller
implementation originally built on branch gifted-lovelace-cZOWR (978cf52a,
2026-05-27, listed BEST in the manifest but never merged):
  - Live HH:mm:ss clock, T-minus/T-plus countdown to the next timed entry
  - Optional per-entry time-of-day (HH:MM) alongside the existing date
  - Per-entry status derived live: EXECUTE (<=15min) / ALERT (<=60min) /
    STANDBY (today or <=24h) / ELAPSED (past) — color-coded text-red /
    text-yellow / text-acc/50 / text-acc/25
  - "Today" panel listing the day's entries with live countdowns
  - Fixed-position military-grade alert overlay (CAL [EXECUTE]/CAL [ALERT])
    for entries entering the 60-minute window, auto-dismiss 30s, manual ACK
  - Fixed the source branch's bg-base bug (see FIX LOG) so the overlay is
    actually opaque against the page
Added on top (not present in any prior branch found):
  - Browser Notification API integration — opt-in "Enable alerts" button,
    permission-gated, feature-detected, wrapped in try/catch; fires an OS
    notification alongside the in-page overlay so a due entry still reaches
    the operator with the tab backgrounded. Best-effort only: requires the
    tab open and permission granted, not a service-worker push.
Logs.tsx — calendar_entry renderer upgraded from "TYPE + date only" (the
version already on master, which silently dropped the entry's actual text)
to full text + time + SCHEDULED/ELAPSED status, per the same 978cf52a design.
api.ts — no change needed; calendar_entry was already in displayableEvents
on this branch's base (unlike 978cf52a's base, where it was still missing).

the manifest — the one durable record meant to prevent exactly this — was

feature specifically (verified by fetching the branch directly, not by
trusting the note). Net effect: roughly 10x redundant engineering effort
over ~11 weeks, zero net progress until this session cross-checked before
writing new code. Folded into LOT-DOCTRINE.md as "Manifest Drift /
Reinvention Loop" with a standing procedure: fetch and read a listed BEST/
READY branch's actual diff before rebuilding, every time.
