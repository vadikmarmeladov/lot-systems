### ⚠️ Improvement Opportunities

#### A — Accessibility (Priority: HIGH for designer-site standard)

**`Button.tsx` — disabled state not communicated to assistive tech**

```tsx
// Current: disabled prop silences interaction but no aria attribute
<button {...props} disabled className={...} />

// Standard: add aria-disabled for screen reader parity
<button {...props} disabled aria-disabled="true" className={...} />
```

**`GhostButton` — span variant is not keyboard-accessible**

When `GhostButton` receives neither `onClick` nor `href`, it renders a bare `<span>`.
If that span contains interactive intent it needs `role="button"` + `tabIndex={0}` +
`onKeyDown` (Enter/Space). Current code makes it invisible to keyboard users and screen readers.

#### B — `isButton()` Heuristic Fragility (Priority: MEDIUM)

```ts
const isButton = (props: InnerProps): boolean => {
  if ((props as ButtonProps).type === 'submit') return true
  if ((props as AProps).href !== undefined) return false
  return (props as ButtonProps).onClick !== undefined  // can be undefined → falsy
}
```

A `<button>` with no `onClick` and no `type="submit"` returns `undefined` (falsy),
causing the element to render as `<a>` with no `href` — semantically a broken link.
Fix: coerce to `!!` or default the return to `true` for button-shaped props.

```ts
// Safer:
return !!(props as ButtonProps).onClick || !((props as AProps).href !== undefined)
```

#### C — System.tsx God-Component (Priority: MEDIUM)

`System.tsx` imports 80+ widget components at the top of a single file. The full
render tree is loaded eagerly on every page visit. For a top-tier site, consider:

- `React.lazy` + `Suspense` for below-the-fold widgets
- Splitting into logical sections (CoreWidgets, ExtendedWidgets, QuantumWidgets)
- This file is currently ~40KB of imports alone — a first-load performance concern

#### F — Nav Spacer Key Fragility (Priority: LOW)

```tsx
// In Layout.tsx
{navLinks.map((link, i) =>
  link.spacer ? (
    <div key={link.label ?? i} ...>  // null label → key = index
  ) : (
    <NavButton key={link.label} ...> // non-null strings only
  )
)}
```

The spacer uses `link.label ?? i`. For spacer items `label` is `null`, so the key
falls back to `i` (array index). If nav items ever reorder, React may reconcile
incorrectly. Assign a stable string key like `'spacer'` or `'spacer-1'` instead.
