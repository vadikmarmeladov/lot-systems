05 // FEATURE — LOT EMAIL v0
--------------------------------------------------------------------------------
F1 COMMAND         Log composer recognizes "/email to <Name>." as a new
                    LogTrigger (`email-command`), parsed by the new pure
                    `parseEmailCommand()` in logTriggers.ts — same
                    additive/no-store-deps pattern as the other 17 Log
                    triggers (/prayer, /qi, /assembly, ...). Everything
                    after the command becomes the email body; the command
                    itself is stripped out. "/system" help list updated.
F2 SERVER MODEL     New `Email` Sequelize model / `emails` table: senderId,
                    recipientId (nullable — unresolved names are still
                    recorded), recipientName, subject, body, status
                    (sent|unresolved|failed), resendMessageId. Migration
                    20260801053300_add-emails.cjs follows the chat_messages
                    migration exactly (direct_messages has no migration in
                    this repo at all — its table's origin predates the
                    migrations/ history; Email gets a proper one regardless).
F3 ROUTES           POST /api/emails resolves the recipient two ways: an
                    explicit recipientId (used by the Community button, F5)
                    wins outright; otherwise the "<Name>" from the command is
                    ILIKE-matched against active users' first names. On a
                    resolved match with an email on file, sendEmail()
                    (existing Resend util, unchanged) dispatches for real;
                    status is recorded either way so "/email to Nobody" is
                    honest about non-delivery rather than pretending success.
                    GET /api/emails returns the calling user's sent+received
                    emails with sender names joined in.
F4 SYNC (LOT CHAT)  POST /emails emits `sync.emit('email', ...)` on the
                    existing EventEmitter; the /sync SSE endpoint's switch
                    statement gained one new case that forwards an 'email'
                    event ONLY when the connected client is the sender or the
                    resolved recipient (mirrors the existing
                    'settings_updated' per-user filter) — chat_message is
                    public-broadcast by design, direct_message and email are
                    not, so this is a deliberate asymmetry, not an oversight.
                    Sync.tsx (the /sync page = "Lot Chat") gained a small
                    EmailFeed section (fetched via new useEmails() + live via
                    sync.listen('email')) rendered underneath the chat feed,
                    and — unlike the chat feed itself — visible regardless of
                    the canAccessChat tag gate, since Email is not restricted
                    to Usership/Onyx/Legacy/R&D/Admin the way public chat is.
F5 COMMUNITY LINK   CohortConnectWidget (the "LOT Community" cohort-matching
                    surface) gained an "Email" button next to each match's
                    existing "Send message" button, calling useSendEmail with
                    the match's known recipientId directly (bypassing name
                    matching, since the ID is already known) and a short
                    default connection note. NOTE (honesty per SELF-ASSEMBLY):
                    no "Cohort Dating" feature exists anywhere in this repo —
                    grepped clean. Cohort Connect (pattern-similarity
                    matching between members) is the closest and only
                    existing substrate, so LOT Email was wired into that
                    real feature rather than inventing a dating system this
                    session was never asked to design. If "Cohort Dating"
                    means something more specific, that is future scope.
