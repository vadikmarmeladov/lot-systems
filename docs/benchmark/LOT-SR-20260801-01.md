05 // WIDGET HEALTH SCAN — FINDINGS AND FIXES
--------------------------------------------------------------------------------
Scope: all 38 src/client/components/*Widget.tsx components, their data wiring
(React Query hooks, Sequelize-backed API routes, nanostore atoms), and their
integration into System.tsx (System tab), PublicProfile.tsx ("Portrait" — the
personal profile page; no literal Portrait.tsx exists, "portrait" is copy-level
metaphor for the profile that accretes from user data), the AI/Memory Engine
prompt pipeline ("LOT AI"), the Quantum Intention Engine (QIE), the weekly
"LOT AI Story" job, and the generic Log system.

FIXED THIS SESSION (6):

F1  RENDER ISOLATION (recurrence)   System.tsx:377 optimalWidget and
    PatternRecognitionWidget.tsx:78 optimal both called getOptimalWidget() ->
    analyzeIntentions() -> intentionEngine.set() inside useMemo — a store
    write during the render phase. This is the exact anti-pattern already
    fixed once for System.tsx's quantumState (SR-20260719-01) but the fix
    pass missed these two call sites (one had zero comment, one had a
    comment acknowledging the hazard but not fixing where the write
    happens). Both moved to useState(lazy-init) + useEffect[deps], mirroring
    the quantumState pattern exactly. Doctrine: Render Isolation (existing
    clause, reused — see 06).

F2  WIDGET ERROR BOUNDARY GAP        TimeWidget and QuantumRandomWidget were
    the only 2 of 38 widgets rendered in System.tsx NOT wrapped in
    <WidgetErrorBoundary>. An uncaught render error in either (both run
    client-side dayjs/interval/audio logic) would have taken down the
    entire System tab instead of degrading to one widget's fallback UI.
    Wrapped both mount sites (System.tsx:449, :623-624).

F3  INTERVAL GATING GAP              QuantumRandomWidget.tsx ran two
    concurrent 1s setInterval timers (per useQuantumNumber() instance x2)
    plus one 10s timer, none gated on document.hidden — the only widget(s)
    in the codebase with unconditional intervals shorter than 60s, breaking
    from the document.hidden/isRouteActive gating doctrine applied
    everywhere else (7 query polls, ChakraErgonomics, ContextualPrompts,
    EvolutionMilestoneToast, SystemProgressWidget, SystemPulseWidget).
    Added `if (document.hidden) return` guards to all 3 intervals.

F4  INTERVAL GATING GAP              MicroCalculatorWidget.tsx's 10s
    magic-time poll ran before the widget's own early `return null`,
    meaning it polled indefinitely regardless of tab visibility. Gated the
    poll on document.hidden and added a visibilitychange listener so a
    magic-minute window is still caught within ~0s of the tab regaining
    focus (not up to 10s late) rather than silently missed.

F5  EVOLUTION GATE — DEAD IDs        interfaceEvolution.ts:137-138 scored
    the `exploration` dimension of the Evolution Gates system against
    achievement IDs 'first_breath' and 'mirror_gazer' — neither exists in
    src/server/utils/rpg-narrative.ts, which defines 'first_checkin' and
    'first_answer' instead. Only 1 of 3 target IDs ('community_voice')
    could ever match, permanently capping exploration at 33% and making
    the `achievementGallery` feature-unlock flag structurally unreachable
    for every user. Corrected the two dead IDs to the real ones.

F6  STORY JOB CRASH (BROKEN -> FIXED)  src/server/scheduled-jobs.ts Job 24
    (Weekly LOT AI Story, Sundays 18:00 UTC) called
    `parseInt(userId)` before both Log.create({userId: ...}) and
    User.findOne({where: {id: ...}}) — but Log.userId and User.id are
    Postgres UUID columns (models/log.ts:34, models/user.ts:23), and userId
    here is already a full UUID string. parseInt() on a UUID truncates to a
    small bogus integer (e.g. "3fa85f64-..." -> 3), which throws
    "invalid input syntax for type uuid" on insert. The per-user loop body
    had no own try/catch — only the job's single outer catch — so the
    FIRST user processed with this bug aborted the ENTIRE run, silently
    skipping every remaining user for that week. In practice this job has
    almost certainly never successfully written a story for a real user
    since it shipped. Fix: removed both parseInt() calls (userId is used
    directly, both columns are UUID-typed); wrapped each user's loop body
    in its own try/catch so one bad record can no longer abort the batch.

    PublicProfile.tsx section) once F6's fix has produced real story data
    to display.

F8  BROKEN — formatLog() SILENT EVENT DROP (~50 event types)   Three
    independent, divergent formatLog() dispatchers exist
    (memory.ts:784-826 [6 cases], question-generator.ts:841-903 [10 cases
    + 1 generic default], story-generator.ts:28-63 [4 cases, least
    complete]). None of them has a case for any of the ~50 QIE
    "arc/peak/lock" pattern-signal log types (vitality_cascade,
    social_presence_arc, clarity_momentum_peak, temporal_alignment_peak,
    full_system_coherence, embodied_cognition_arc, ...) that scheduled-jobs
    v52-v108 actively write and that QuantumStateWidget/SignalStreamWidget/
    PatternRecognitionWidget surface to users. Each uncovered event type
    silently returns '' from formatLog(), is filtered out, and never
    reaches the AI prompt — the exact "silent erasure, no error" failure
    mode LOT-DOCTRINE.md already names in the Widget->Memory Compression
    Loop clause (folded 20260630-01), now confirmed empirically wider than
    documented. RECOMMEND: unify the 3 dispatchers into one shared
    formatLog(), extend coverage to the QIE pattern-signal whitelist
    already maintained in api.ts's displayableEvents. Deferred — real
    design work (which patterns should influence AI tone, not just a
    mechanical fix) and touches 3 files feeding live AI prompts; too much
    surface for a single audit-session fix.

F9  MINOR — DUPLICATE BADGE KEY      src/client/utils/badges.ts defines
    `quarter_drop` twice (line 3103 "uncommon/achievement_rpg" and line
    5390 "rare/behavioral", different symbol/description/unlockMessage
    each time) — an esbuild duplicate-object-key WARNING on every build
    (both pre- and post-fix in this session, confirmed unrelated to any
    widget change). The first definition is silently shadowed and
    unreachable. Not a widget-wiring issue; flagged because CHECK B
    surfaces it every run. RECOMMEND: rename one badge ID in a future
    badges-focused session — deferred here to avoid touching earned-badge
    ID stability without that session's full context.

F10 NOTABLE — TESTING: ZERO COVERAGE   No *.test.ts(x), no test runner
    (jest/vitest/playwright) configured anywhere in the repo; package.json
    has no "test" script beyond a live-server cold-start smoke check. None
    of the 38 widgets or their query hooks have any regression protection.
    RECOMMEND: a dedicated session to stand up a test runner + first
    coverage pass — large enough in scope (tooling choice, CI wiring) to
    warrant its own benchmark cycle rather than folding into this one.

F11 NOTABLE — NO WIDGET CODE-SPLITTING   `grep -r "React.lazy"` across
    src/client returns zero matches. esbuild's `splitting: true` only
    produces shared vendor chunks between the app's 7 static entry points,
    not per-widget chunks — System.tsx statically imports all ~42
    widget/component modules, so app.js (680K) ships every widget
    regardless of scroll position. LazyMount (System.tsx) defers store
    subscription cost until a widget scrolls into view but does not reduce
    initial parse/download cost. RECOMMEND: React.lazy + Suspense for
    below-the-fold widgets (game/micro widgets, calendar, benchmark)
    behind the existing LazyMount viewport gate.
