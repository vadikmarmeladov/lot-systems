## SCOPE DECISION — WHY THIS IS AN IN-APP TAB, NOT A LOGGED-OUT PAGE

LOT-FM-001 calls the Month 1 surface "OPEN TAB" and says "a stranger can
read it." Taken completely literally that implies an unauthenticated,
logged-out-reachable page. I checked whether that's cheap to do:

- `src/client/entries/app.tsx` gates the entire SPA shell on `getMe()`
  resolving (`isLoaded = !!user`).
- `/api/me` (`src/server/routes/api.ts:412`) reads `req.user` — it assumes
  an authenticated session; there is no anonymous/guest profile path.
- The only genuinely public entry points in this repo are `about.tsx` /
  `About.tsx` (served via `templates/about-standalone.ejs`) and the
  `/status` status page.

Wiring a new unauthenticated server route + template for a single tab is a
meaningfully bigger, security-relevant change (new auth-bypass surface) than
"render a ledger" — and `LOT-MANIFEST.md` explicitly protects `About.tsx` as
a wiki-session-only file that feature branches must never carry changes to.
Doing that properly is Month 2/3-scale work, not a Month 1 read-only ledger.

**Decision:** ship Month 1 as a real in-app tab — exactly what the literal
task description asks for ("when the user clicks on the tab, they see a
minimalist UI in LOT style"), reachable by any logged-in operator, with no
Usership/subscription gate on *viewing* the ledger (doctrine: "the ledger is
the marketing — no layer between public and manifest" is honored *within*
the app: nothing paywalls the read). True logged-out reachability is called
out below as follow-up work, not silently dropped.
