05 // ROUTINES IMPLEMENTED (this session)
--------------------------------------------------------------------------------
R1 EMAIL TRIGGER     logTriggers.ts: new 'email-compose' trigger, keywords
                     [email, mail], emoji [✉️]. Logs.tsx NoteEditor handler:
                     "/email to <name> <message>" — <name> is the first
                     token after "to"; whatever remains once the trigger
                     substring is stripped becomes the body (same
                     strip-and-send convention already used by /prayer and
                     /story). Empty body -> opens the DM thread instead of
                     sending. Resolves name via new GET /api/users/lookup,
                     then sends through the existing useSendDirectMessage
                     mutation (no new send path). Renders a MAIL: status
                     block matching the existing QI:/SCAN:/SYSTEM: blocks;
                     /system help text updated with the new command.
R2 USER LOOKUP       New GET /api/users/lookup?name= — case-insensitive
                     prefix match on firstName (Op.iLike, same pattern as
                     admin-api.ts user search), excludes self and
                     suspended-tagged accounts (same tag check used by
                     chat's participation gate), capped at 6 candidates.
R3 MAIL INBOX        New GET /api/direct-messages (distinct route from the
                     existing GET /api/direct-messages/:userId thread
                     fetch — different path depth, no Fastify route
                     conflict) — one row per conversation partner (latest
                     message only), newest first, capped at 20 partners
                     from the last 200 messages.
R4 SYNC MAIL SECTION Sync.tsx: new Mail block below the chat feed, gated by
                     the same canAccessChat check the page already returns
                     early on. Seeded from R3 on mount, kept live by
                     listening on the 'direct_message' SSE event
                     DirectMessageThread.tsx already emits/consumes — no
                     new transport. Clicking a thread row navigates to the
                     existing /dm/:userId route (DirectMessageThread,
                     already implemented, was reachable only by direct URL
                     before this session — no UI linked to it).
R5 COHORT WIRING     CohortConnectWidget.tsx "Send message" button called
                     stores.goTo('sync') — switched tabs and did nothing
                     else; the DM thread it should have opened was never
                     wired. Changed to stores.goTo('dm', { userId }), which
                     opens the real, pre-existing DirectMessageThread. This
                     is the full extent of "Cohort integration" this
                     session — see scope note below.

SCOPE NOTE ("Cohort Dating"): the request also asked to incorporate LOT
Mail with "Cohort Dating through LOT Community." No dating/matching
feature exists in this codebase (confirmed absent in pre-session research)
and none was built here. Cohort pattern-matching (CohortConnectWidget,
already shipped, already consent-free/automatic for any user with 10+ log
entries) was left as-is; R5 only makes its existing "Send message" action
functional. Inventing new user-matching or discovery logic for real users,
unattended and unreviewed, was judged out of scope and out of proportion
to "simplest" — flagging explicitly rather than silently narrowing scope.
