05 // AUDIT FINDINGS + ACTIONS
--------------------------------------------------------------------------------

A. WIDGET-TO-LOG / SIGNAL WIRING
   Canonical helper `recordSignal()` (intentionEngine.ts:199) is used
   consistently by ~28 of 37 widget files. Two real gaps found and closed:
   - QuantumSignWidget.tsx — 4 "Actions" choices (Journal/Create/Connect/Rest)
     wrote only to localStorage, framed in-code as a QIE "catalyst" but never
     reaching the engine. FIXED: chooseAction() now also calls
     recordSignal('selfcare', 'quantum_sign_action', {action, hour}).
   - IntentionsWidget.tsx — WIDGETS.md documents an `intention_set` / `integrate`
     signal pair; only `intention_set` existed. FIXED: added a one-time
     `integrate` signal when the Alignment view shows a 7+ day streak
     (intention converged into daily runtime).
   Two minor/cosmetic gaps recorded, not fixed this session (lower priority,
   avoid unnecessary churn): CosmicUpdateWidget.tsx generation action has no
   signal (undocumented, so not a doc/code mismatch); MonthlyPulseWidget.tsx
   isn't described in WIDGETS.md at all (doc omission, not a functional bug).
   PatternInsightsWidget signal names (`pattern_checkin`/`pattern_reflect`/
   `pattern_integrate`) didn't match WIDGETS.md prose — FIXED via doc edit
   (code was correct, doc was stale).

B. QIE / MEMORY / STORY (NARRATIVE) WIRING
   Sound. All fields widgets consume from intentionEngine.ts (recognizedPatterns,
   signals, getUserState(), getOptimalWidget(), recordSignal()) are genuinely
   exported and correctly consumed by QuantumStateWidget, PatternRecognitionWidget,
   SignalStreamWidget, AIFeedbackWidget — no renamed/removed fields, no dead
   references. MemoryWidget correctly hits /api/memory + /api/logs; badge
   milestone logic is a real, substantial system (badges.ts), not a stub, with
   working error/retry UI. NarrativeWidget and GoalJourneyWidget correctly hit
   /api/narrative and /api/goal-progression; engagement-level tone logic reads
   live log data, not hardcoded. Minor gap noted, not fixed: neither widget
   surfaces a retry affordance on query error (silently returns null), unlike
   MemoryWidget's explicit pattern — worth aligning in a future session.

C. SYSTEM TAB / PORTRAIT (PROFILE PAGE) WIRING
   All 45 widget imports in System.tsx are rendered in JSX (free-tier and
   paid-tier layouts) — no orphaned import, no missing-import compile risk.
   Visibility gating (time/cooldown/activity/subscription/mode/pattern) spot-
   checked against WIDGETS.md's Architecture Overview — matches on every
   category checked. The "Portrait" personal profile page is `PublicProfile.tsx`
   (route `/u/:username`), hitting `/api/public/profile/:id` — a different
   endpoint than System.tsx's `useProfile`/`/api/user-profile`, but both
   compute from the same underlying trait/cohort logic so values stay
   consistent; no divergence found. FIXED (doc only): WIDGETS.md said Awareness
   Dashboard sources `/api/profile`; corrected to `/api/user-profile`.
   FINDING, no code change: `AwarenessDashboard.tsx` is fully built (uses
   useProfile per its WIDGETS.md entry) but is not imported anywhere — not in
   System.tsx, not on the profile page. A documented feature that does not
   currently appear anywhere live. Recorded as a reveal/build-up decision for
   S-2, not treated as a bug — this may be an intentional pending-reveal widget
   rather than dead code, and wiring it into a layout is a product placement
   call this session shouldn't make unilaterally. WIDGETS.md updated to state
   its current orphaned status plainly.

D. PERFORMANCE / LAG
   D-001 (rev A, see doctrine): 5 widgets carried the exact render-phase
   atom-write anti-pattern a prior session (SR-20260719-01) fixed once in
   System.tsx — a "record signal once per mount" ref-check running directly in
   the component body instead of inside useEffect, so the recordSignal() write
   fires synchronously mid-render and cascades a re-render into every other
   `intentionEngine` subscriber. FIXED in: GoalJourneyWidget.tsx,
   CohortConnectWidget.tsx, MicroImageWidget.tsx, InterventionsWidget.tsx,
   ChakraErgonomicsWidget.tsx — all five moved into `React.useEffect`.
   SystemPulseWidget confirmed still correct: 10s interval (not the 1s the
   docs describe), gated on `document.hidden` and route-active — no action.
   The 7-widget stats-polling thundering herd from SR-20260719-01 is confirmed
   still fixed (uniform 120s, `refetchIntervalInBackground: false`); noted but
   not fixed this session — all 7 still land on the same 120000ms boundary if
   mounted together, jitter would be a cheap future win. No setInterval/
   setTimeout leaks found anywhere (all clear their own effects). No
   unmemoized heavy synchronous work found in click handlers.
   FIXED (comment only): queries.ts:136 said "/api/logs has no LIMIT" — the
   server has capped it at 500 rows for a while; comment corrected so a future
   session doesn't re-loosen staleTime on a false premise.

E. TYPE-SAFETY GAP (found while investigating the MicroGameWidget doc mismatch)
   MicroGameWidget.tsx calls `recordSignal('micro_game', 'switch', ...)` but
   `'micro_game'` was never a member of `IntentionSignal['source']` in
   intentionEngine.ts — a real type-safety gap invisible to any check this
   repo currently runs (client code has no gating typecheck script; only
   server:build's scoped tsc runs, and it doesn't cover client files). FIXED:
   added `'micro_game'` to the union. Diagnostic sweep of every recordSignal()
   call-site literal confirms all now match the union exactly. WIDGETS.md's
   Micro Game Widget entry also corrected: it claimed "records gameplay
   signals" but only game-switch is (and by design should be) signaled — per-
   keystroke signaling would reintroduce exactly the lag class in finding D.

F. 15-MONTH UI REVEAL / BUILD-UP ROADMAP
   No document matching a "15-month" or month-to-month UI reveal schedule
   exists anywhere in docs/ or src/ (searched by name and by content). The
   closest real mechanism is `$featureUnlocks` (evolution system) and the
   Self-Assembly module-phase progression (System Progress Widget) — both are
   activity-derived unlocks, not calendar/tenure-derived. Recording this
   plainly rather than inventing a roadmap to match: if a 15-month reveal
   cadence is meant to exist, it isn't currently encoded anywhere. This needs a
   decision from S-2, not an assumption from this session.

G. USAGE LOG COVERAGE
   `/api/logs` is the shared substrate nearly every widget and both audits
   above cross-referenced; coverage is broad and consistent (see finding A).
   No widget was found writing usage data anywhere outside this log path
   (no shadow/duplicate logging system found).
