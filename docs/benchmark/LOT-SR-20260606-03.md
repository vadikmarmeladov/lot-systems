02 // ERRORS AND WARNINGS — FOUND BEFORE THIS SESSION
--------------------------------------------------------------------------------

The following accuracy and quality defects were identified in the
health check system during this session audit:

  BUG-01  [MEDIUM]  Node.js version check wrong
          File:  src/server/routes/public-api.ts:91
          Issue: Engine stack check required Node ≥ 18, but
                 package.json engines field requires ≥ 20.
                 A Node 18/19 server would pass the check incorrectly.
          Fix:   Updated threshold from 18 to 20.
          Status: FIXED ✓

  BUG-02  [MEDIUM]  checkSettings() was a redundant duplicate
          File:  src/server/routes/public-api.ts:189–218
          Issue: checkSettings() called models.User.findOne() and
                 checked dist/client/js/app.js — identical to
                 checkUsers() and checkWeatherAPI() respectively.
                 The "Settings" health check provided zero unique
                 signal; any settings failure would pass silently.
          Fix:   Rewritten to query User.metadata attributes,
                 which is the actual storage layer for user settings.
          Status: FIXED ✓

  BUG-03  [LOW]   Overall status never returned 'degraded'
          File:  src/server/routes/public-api.ts:358–360
          Issue: performHealthChecks() had binary logic: any error
                 → 'error', else → 'ok'. The 'degraded' type was
                 declared but never produced. A single misconfigured
                 API key would show the same severity as a full
                 database outage.
          Fix:   Introduced critical-path distinction:
                   - Database stack or Engine stack error → 'error'
                   - Any other check fails → 'degraded'
                   - All pass → 'ok'
          Status: FIXED ✓

  BUG-04  [LOW]   test-anthropic-key used outdated model ID
          File:  src/server/routes/public-api.ts:713
          Issue: /api/public/test-anthropic-key fired a test call
                 with 'claude-3-5-sonnet-20241022' — a more
                 expensive model than needed for a key validation
                 ping. The latest model taxonomy has moved on.
          Fix:   Swapped to 'claude-haiku-4-5-20251001' — lowest
                 cost model available, sufficient for key validation.
          Status: FIXED ✓

05 // COMPONENT ACCURACY — STATUS PAGE REDESIGN
--------------------------------------------------------------------------------

  FILE: src/client/components/StatusPage.tsx

  BEFORE (issues):
    - Status icons used ✓ / ✕ symbols — violates LOT style guide
      ("Periods over symbols: 'Done.' instead of 'Done ✓'")
    - 'degraded' overall state existed in type but was never rendered
      differently from 'ok' — dead branch in UI
    - No visibility into when the next auto-refresh fires; users had
      no sense of data freshness between 2-minute cycles
    - Memory status section used "✓"/"✕" for next-prompt availability
    - Status text inconsistent ("Ok" without period vs "Error" without period)

  AFTER (fixes applied):
    - All status indicators now use text with trailing period:
      "Ok."  |  "Error."  |  "Unknown."
    - Overall status uses opacity hierarchy:
        ok       → text-acc      (full visibility)
        degraded → text-acc/60   (secondary)
        error    → text-acc/40   (tertiary — serious but consistent)
    - Live countdown: "Next check: in 47s" — updates every second,
      resets on manual refresh
    - Manual Refresh button now also resets the countdown clock
    - Memory prompts section: "Available now." / "Not available."
      (no symbols)
    - Consistent period punctuation throughout
    - Removed redundant loading comment; cleaned trailing spaces
    - blockView={true} on check rows so message text wraps below
      the status line correctly

  QUALITY STANDARD: LOT minimalist aesthetic, top-tier legibility,
  no decorative symbols, live data freshness signal visible at all times.
