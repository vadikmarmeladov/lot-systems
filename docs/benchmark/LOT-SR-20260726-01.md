SCOPE B — QIE / MEMORY / STORY WIRING
  QIE (intentionEngine.ts, client-side, P1-P118+) receives recordSignal()
  calls from 11 widgets; separately syncs raw signals server-side as
  quantum_intent_signal Log rows. Real bug: two Memory Engine trees exist
  (memory.ts flat file, live; memory/ directory, DEAD — import-map string
  substitution on '#server/utils/memory' only ever resolves the flat file).
  formatLog() (memory.ts:784) had only 6 event cases (answer, chat_message,
  note, settings_change, plan_set, emotional_checkin) against a ~90-entry
  displayableEvents whitelist the Logs UI actually renders. Any event without
  a case silently vanishes from the AI prompt — no error, per existing
  Widget→Memory Compression Loop doctrine. Confirmed newly-affected:
  calendar_entry (CalendarWidget), self_care_complete/self_care_skip
  (SelfCareMoments) — all written, all reaching the UI, none reaching the AI.
  Also confirmed: IntentionsWidget and GoalJourneyWidget never write to the
  Log at all (QIE signal only) — invisible everywhere but QIE. RecipeWidget
  writes Log rows with no event type (defaults to 'note', loses identity).
  goal_set/goal_update/goal_complete/goal_journey are whitelisted for display
  but never written anywhere in src — dead whitelist entries.
  Real bug found: rpg-narrative.ts checked event === 'self_care_completed'
  (trailing "d") for the "Gentle With Self" achievement; the actual write is
  'self_care_complete' (no "d") — achievement was permanently unreachable.
  Logs.tsx already defended both spellings; rpg-narrative.ts did not.

SCOPE C — LOG POSTING FOR INTERACTIVE / SYNCHRONIZED WIDGETS
  Central Log model confirmed (Sequelize `logs` table: id/userId/event/text/
  metadata/context). Weather + time ride along on every Log write via
  getLogContext() (ambient context, not a widget-triggered event) — there is
  no dedicated WeatherWidget. TimeWidget: zero logging (pure client clock,
  by design). users_online / users_total presence: SSE broadcast-only
  (`/api/sync`), never persisted to the Log table — by design, this is a
  live counter, not a recordable event. Of ~40 widgets, only 4
  (CalendarWidget, PlannerWidget, RecipeWidget, SelfCareMoments) call
  useCreateLog(); the rest are read-only/derived-state or QIE-signal-only.
  No generic "widget viewed/interacted" tracking call exists anywhere in the
  codebase — confirmed absence, not a bug (COCKPIT-RULE: the Log records
  instrument readings, not UI telemetry — this is consistent with that
  doctrine, not a violation of it).

SCOPE D — 15-MONTH UI REVEAL / BUILD-UP

  per-user gate. The actual progressive-reveal system is level/streak/
