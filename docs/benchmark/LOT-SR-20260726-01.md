01 // ROOT CAUSES CONFIRMED PRESENT ON THIS BRANCH (pre-fix)
--------------------------------------------------------------------------------
Verified by direct code read on `claude/brave-rubin-rrtgfz` @ add997e6, not
assumed from other sessions' reports.

C1. RENDER-PHASE STORE WRITE — System.tsx
    `src/client/components/System.tsx:346` (pre-fix):
      const optimalWidget = React.useMemo(() => getOptimalWidget(), [logs])
    `getOptimalWidget()` (src/client/stores/intentionEngine.ts:2935) calls
    `analyzeIntentions()`, which — once its 5-min cooldown has elapsed —
    runs a ~125-pattern scan and then calls `intentionEngine.set(...)`
    (line 2712) SYNCHRONOUSLY, inside the render phase. A nanostores
    `.set()` during render fires all subscribers synchronously, which can
    cascade further renders before the current one has even committed.
    Any interaction that touches `logs` (posting a log, using a widget
    button that appends a signal) re-runs this useMemo and can re-trigger
    the write-cascade — this is the "button feels laggy" symptom.

C2. RENDER-PHASE STORE WRITE — MemoryWidget.tsx
    `src/client/components/MemoryWidget.tsx:268` (pre-fix):
      const quantumState = React.useMemo(getQuantumState, [question?.id])
    `getQuantumState()` calls `analyzeIntentions()` directly — identical
    hazard to C1, independent call site. This is exactly the "sibling call
    site missed by the earlier 6e5007a4 fix" that the orphaned branch's
    9520b7db commit also found and fixed — confirming it's a real,
    reproducible pattern and not a one-off.

C3. UNGUARDED INTERVALS — QuantumRandomWidget.tsx
    Two `setInterval` calls (1s tick, 10s pair-toggle) with no
    `document.hidden` / active-tab guard. System is mounted permanently
    (kept `display:none` off-tab per earlier fixes), so these intervals
    ran forever in the background on every tab, continuously calling
    `setState` + `recordSignal()` — background CPU/render churn that
    steals frame budget from whatever the user is actually clicking.

C4. UNGUARDED POLL — StatusPage.tsx
    `setInterval(..., 2 * 60 * 1000)` auto-refresh with no
    `document.hidden` guard — the only unguarded network poll found in the
    component tree.
