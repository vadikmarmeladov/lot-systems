05b // WHAT CHANGED
--------------------------------------------------------------------------------
/story PERIOD COMPRESSION
  POST /api/story now accepts `period?: 'day'|'week'|'month'|'year'` (default
  'day'). Each period maps to a bounded lookback window + query limit (day:
  1d/200, week: 7d/500, month: 30d/1000, year: 365d/2000 — no unbounded
  findAll, per existing Query Batching doctrine). Dominant-mood/tone
  derivation reuses the exact MOOD_POSITIVE/MOOD_HARD compression already
  proven in the weekly LOT AI Story cron (Job 24, scheduled-jobs.ts) so
  day/week/month/year read as one family of compression, not a bespoke
  one-off. The AI prompt is grounded with the period + stats block; on AI
  failure the route now composes a REAL local fallback narrative from the
  same stats (previously: a static placeholder sentence, not an actual
  fallback story). Client: /story alone compresses today; /story week|month|
  year widens the window (parsed via regex on the log text at trigger time,
  same convention as the existing /qi [query] argument pattern). The STORY
  block in the LOG now labels itself with the period (e.g. "📖 WEEK").

BUG FIXES (found during investigation, in scope because they directly affect
/story quality — S-2 asked specifically about compression accuracy):
  - recentEntries filter checked `event === 'log_entry' || event === 'journal'`
    — neither event name is ever written; real journal entries use event
    'note' (confirmed against 6 other call sites in api.ts that all correctly
    filter on 'note'). recentEntries was silently empty on every /story call
    since the route shipped. Fixed to `event === 'note'`.
  - 'generated_story' (the /story command's own log event) was missing from
    the displayableEvents GET whitelist — Backend Whitelist Hygiene violation
    (doctrine, below). It only "worked" because the client manually splices
    the story text into the editable note body; on a fresh page load without
    that splice, the event would have been invisible. Added to whitelist.

/system
  Updated the static help text's /story line to document the new
  `[period]` argument (day default, week/month/year). No other changes —
  /system was already fully live (static client-side help, no server call).

ARCADE / GAMIFICATION (self-care-appropriate, not score-chasing)
  New badge `chronicle_keeper` (◇·◇, rarity: rare, category: achievement_rpg):
  earned once the operator has used /story across all four compression
  windows at least once each (tracked via a small localStorage set,
  `story_periods_used`). This rewards DEPTH of reflection across timescales
  — looking at one's day, week, month, and year — rather than repetition
  count or streak pressure, consistent with LOT's "self-care, not a game"
  positioning (Ambient AI doctrine: healing the user doesn't notice
  happening). Reuses the exact existing awardBadge()/hasBadge() mechanism —
  zero new UI plumbing; renders through the same badge_unlock Block path
  every other badge already uses.
