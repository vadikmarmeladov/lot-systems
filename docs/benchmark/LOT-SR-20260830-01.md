DESIGN — kept to the smallest working surface:

  1. logTriggers.ts — new pure trigger `lot-email`, keyword `/email`
     (`✉️`/`✉` emoji alias), following the exact RULES-table shape already
     used by /prayer, /story, /qi, /system etc. Detection is delta-based
     (detectNewTriggers), so old logs already containing "/email" text never
     re-fire on remount — same guarantee every other trigger already relies
     on.

  2. Logs.tsx (NoteEditor) — on fresh `lot-email` trigger:
       - Parse `/email to <name>[. ,!?]* <body>` out of the live log text.
       - Resolve <name> against the user's live Cohort Dating matches
         (useCohorts() — same query CohortConnectWidget reads, react-query
         cache-shared, no extra network cost) by first-name match. This is
         the LOT Community tie-in S-2 asked for: a name a person actually
         has an active cohort match with resolves to that match's identity
         and similarity score in the confirmation; an unresolved name still
         sends, just unresolved.
       - Build a plain-text envelope: `✉ TO: <NAME>` header line + body.
       - POST it through the existing useCreateChatMessage() mutation
         (/api/chat-messages) — the same call Sync.tsx's own composer uses.
         The server already broadcasts every chat_message over SSE and
         Sync.tsx already renders every chat_message it receives — so "new
         messages appear in Sync" is satisfied by construction, zero changes
         to Sync.tsx, zero new schema, zero new route.
       - Show a one-line SENT confirmation inline in the Log (same
         Block-label pattern as /scan, /phys, /silent results).
       - Added `/email to X` to the /system help listing.

  Why this is "simplest LOT style": every other Log command in this codebase
  already proves the pattern (detect → parse → call existing
  mutation/store → render inline confirmation). LOT Email needed no new
  concept, table, or endpoint — only a new detector and a formatting rule on
  top of infrastructure Sync and Cohort Connect already provide. A DM-based
  private "email" was considered and rejected for v1: S-2's brief explicitly
  named Sync as the delivery surface.
