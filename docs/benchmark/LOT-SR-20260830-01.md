05 // WHAT WAS BUILT
--------------------------------------------------------------------------------
R1 TIME TRACKING     Per-entry Track/Stop control in the expanded date view.
                     One timer app-wide (other entries' Track buttons hide
                     while a timer runs — no concurrent-timer state to
                     reconcile). Stop logs a `calendar_time_logged` entry
                     (text, date, entryType, durationMs) and sums prior
                     sessions per entry as a running total next to it.
                     Sub-1s stops are discarded (no accidental-tap noise).
R2 RELIABILITY FIX   handleAddEntry cleared the input and closed the form
                     unconditionally, before the createLog mutation resolved
                     — a failed save silently lost the typed entry with no
                     feedback. Moved the reset into onSuccess; added onError
                     with an inline "Failed to save" message and a disabled/
                     "Adding…" button state while the request is in flight.
R3 EVENT TOAST       New CalendarEventToast — scans logs once a minute (mount
                     + interval, gated on tab visibility + active route, same
                     guard EvolutionMilestoneToast uses) for entries due
                     today, alerts once per entry per day (localStorage-
                     scoped to today's date, bounded). Also confirms a logged
                     time session. Cockpit styling — uppercase, tracking-
                     widest, bracket-tag label (`SCHED [T-0]:`, `CAL [TIME]:`).
R4 ALERT BUS         New calendarAlerts store (nanostores atom, FIFO queue):
                     CalendarWidget pushes a "logged" alert without importing
                     the toast; the toast watches for "due" dates without
                     importing the timer. One alert visible at a time, 6.5s
                     dwell + fade.
R5 LOG VISIBILITY    Added `calendar_time_logged` to the server's displayable-
                     events whitelist (GET /logs) — an event not on that list
                     is created fine but never comes back to the client, so
                     time sessions would have been invisible to both the
                     widget's running-total and the Logs feed without this.
R6 LOGS FEED         Added a `CAL [TIME]:` renderer in Logs.tsx for
                     calendar_time_logged (duration, entry type, entry text)
                     matching the CAL: renderer already in place for
                     calendar_entry, instead of falling through to the
                     generic LOG: text renderer.
R7 QIE WIRING        recordCalendarTimerSignal(entryType, date, durationMs) —
                     sibling of the existing recordCalendarSignal, same 'log'
                     source, called on Stop so time-on-task feeds the same
                     Temporal Planner / Pattern 26 substrate as scheduling.
