DESIGN NOTES
--------------------------------------------------------------------------------
Architecture:
  · LOT Mail reuses the DirectMessage model (no new table, no migration).
  · /email trigger fires in Log → parseEmailCommand() extracts TO + BODY →
    POST /api/lot-mail → finds user by first name (case-insensitive LOWER()),
    creates DirectMessage, emits SSE lot_mail event.
  · Recipient sees the mail appear in real-time in Sync feed (✉️ MAIL: prefix)
    and in the /mail inbox (LotMail.tsx).
  · Sender sees ✉️ MAIL: block appear in Log immediately, and a lot_mail_sent
    entry in their log history.
  · CohortConnect: inline compose form per member. "Send message" renamed "Sync"
    (navigates to /sync); new "✉️ Mail" button opens inline compose.
  · Inbox batches sender name lookups (single IN-clause, per doctrine).

Simplest-valid-design choices:
  · No new DB table — DirectMessage is the right shape.
  · No subject field — body only. LOT® style is direct.
  · Name-based addressing ("to Hitomi") matches natural Log syntax.
  · Sync integration is real-time via existing SSE infrastructure.
