05 // WHAT CHANGED
--------------------------------------------------------------------------------
Backend (src/server/routes/api.ts, POST /api/story):
  - Body accepts `period?: 'day'|'week'|'month'|'year'` (undefined = legacy).
  - PERIOD_CONFIG per period: since-date, entry limit, word range, token
    budget — day=24h/5 entries/100-200w, week=7d/15/150-250w, month=30d/30/
    200-300w, year=365d/50/250-350w. Unscoped keeps limit:200/entryLimit:10/
    100-200w exactly as before.
  - Log.findAll filters `createdAt >= since` only when a period is given;
    bare /story still pulls the most recent rows with no date bound.
  - System prompt states the period label and instructs compression across
    the whole window (a throughline, not a day-by-day list) for week+.
  - Response returns `period`; generated_story Log metadata records `period`
    and `entryCount`.
  - Fixed: `generated_story` added to GET /api/logs' displayableEvents —
    was write-only before this session (see MID-SESSION FINDING above).
Frontend (Logs.tsx, queries.ts):
  - story-mode trigger parses an optional day|week|month|year word after
    /story, strips it from the persisted log text, passes it through
    (undefined when absent — no forced default).
  - storyPeriod state (nullable) drives a small "<PERIOD|RECENT>
    COMPRESSION" label above the story block.
  - /system help text documents all five forms (/story, /story day, week,
    month, year).
