DESIGN — LOT® Email (LOT Mail)

COMMAND SURFACE:
  User types in Log (NoteEditor):
    <message body>
    /email to Hitomi

  Or inline:
    /email to Hitomi Hey, checking in...

  The trigger detector fires when /email appears in the log text.
  Parser: /email\s+(?:to\s+)?(\w+)/i extracts recipient first name.
  Body: everything in log text EXCEPT the /email to <name> command, trimmed.

SEND FLOW:
  1. NoteEditor trigger effect detects 'lot-mail' trigger
  2. Calls sendLotMail({ recipientName, message }) → POST /api/lot-mail
  3. Server looks up user by firstName (case-insensitive, PostgreSQL Op.iLike)
  4. Creates DirectMessage record (reuses existing direct_messages table — no migration needed)
  5. Emits 'lot_mail' SSE event directly to recipient's Sync stream
  6. Logs lot_mail_sent event to sender's Log history
  7. NoteEditor shows EMAIL: block: SENT / TO: HITOMI / MSG: ...

SYNC DISPLAY (recipient side):
  - SSE event 'lot_mail' arrives → added to incomingMail state
  - Inbox also loads on Sync mount via GET /api/lot-mail
  - Displayed above chat messages with MAIL label, sender name, message, timestamp

LOG HISTORY (sender side):
  - lot_mail_sent event renders in past logs as:
    EMAIL:
      TO: HITOMI
      <message body>

LOT COMMUNITY INTEGRATION:
  - CohortConnectWidget "Send message" button already routes to /sync (stores.goTo('sync'))
  - The Sync tab now shows incoming LOT Mail — cohort members who click "Send message"
    see the recipient's Sync, where LOT Mails from the Log command appear
  - Full circle: Log → /email to Hitomi → server → SSE → Hitomi's Sync

ARCHITECTURE DECISIONS:
  - Reuse direct_messages table: avoids schema migration on a live system
  - Name-based lookup (firstName): LOT® UX is first-name-based — no IDs required
  - SSE delivery: instant, no polling — consistent with chat_message pattern
  - Inbox at top of Sync: mail is priority signal, not buried in chat stream
  - MAIL label in monospace uppercase: consistent with LOT® terminal grid aesthetic
