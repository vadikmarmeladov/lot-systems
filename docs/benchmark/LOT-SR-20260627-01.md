### 3. ERRORS AND WARNINGS

  ISSUE A — DEBUG CSS IN PRODUCTION [SEVERITY: HIGH]
    File: src/client/index.css (input-resizible-v::after)
    Finding: `outline: 1px dashed red; color: red;` left in production CSS.
    The ::after pseudo-element has `visibility: hidden` so it does not render,
    but debug artifacts in production code are not acceptable for a top design site.
    Action: PATCHED — debug lines removed.

  ISSUE B — ACCESSIBILITY FAILURE: *:focus WITHOUT focus-visible [SEVERITY: HIGH]
    File: src/client/index.css
    Finding: `*:focus { outline: none }` globally suppresses ALL focus indicators,
    including keyboard navigation. This is a WCAG 2.1 AA failure (Success Criterion
    2.4.7: Focus Visible). Any keyboard or switch-access user loses all orientation.
    Action: PATCHED — replaced with `*:focus:not(:focus-visible)` so click/touch
    focus is still hidden but keyboard focus gets a 1px acc-color outline.

  ISSUE C — useCallback DEPS BUG IN Select [SEVERITY: MEDIUM]
    File: src/client/components/ui/Input.tsx (Select component)
    Finding: `onChangeHandler` was declared with deps `[onChange, value]`.
    The handler does not reference `value` — including it causes unnecessary handler
    recreation on every keystroke, and masks the real contract of the closure.
    Action: PATCHED — corrected to `[onChange]`.

  ISSUE D — max-h ANIMATION ANTI-PATTERN [SEVERITY: MEDIUM]
    File: src/client/components/ui/ToggleSection.tsx
    Finding: `max-h-[2000px]` to `max-h-0` transition is a widely-known CSS hack.
    For content shorter than 2000px the animation is compressed into a tiny fraction
    of the 300ms duration, making close look instant and open look slow — animation
    easing is effectively broken. Not suitable for a top-tier design system.
    Action: PATCHED — replaced with CSS `grid-template-rows: 1fr → 0fr` transition.
    This animates to exactly the content height, giving a precise, smooth collapse.

  ISSUE E — DECORATIVE ICONS WITHOUT aria-hidden [SEVERITY: LOW]
    File: src/client/components/StatusPage.tsx
    Finding: ✓ and ✕ status icons rendered without `aria-hidden="true"`. Screen
    readers would announce "check mark" / "multiplication x" alongside the adjacent
    text label (Ok / Error), creating redundant and confusing output.
    Action: PATCHED — added `aria-hidden="true"` and `role="status"` on the
    containing element.

  ISSUE F — PRE-EXISTING TypeScript ERRORS [SEVERITY: LOW / TRACKED]
    Finding: `tsc --noEmit` shows type errors in the remote environment due to
    missing dev dependencies (node_modules not installed in container). Additionally,
    pre-existing router.ts type errors noted in SR-20260624-03 remain. These are not
    regressions from this session.
    Action: No change. Tracked in prior session reports.

  STRENGTHS:
  ✓ Subscription minimization — PrimaryBtn and SecondaryRoundedBtn split into separate
    components so secondary buttons render with zero store subscriptions. Best practice.

  ✓ WidgetErrorBoundary — proper error isolation with perf timing logged to

  ✓ Layout.tsx NavButton — React.memo isolation prevents nav re-renders on route
    changes. Correct.
  ✓ error.html — static HTML, no framework dependency. Survives any server crash
    that still serves static files. Resilience layer is correct.
  ✓ grid-fill-hover — uses ::before opacity transition (GPU-composited). Correct.
  ✓ Tag.tsx — useMemo for className computation. Correct.
  ✓ index.css evolution variables — well-designed CSS custom property system
    for theme/evolution state propagation.

  ISSUES PATCHED THIS SESSION:
  ✗→✓ Debug CSS in input-resizible-v::after removed
  ✗→✓ Focus accessibility restored (*:focus-visible with acc-color outline)
  ✗→✓ Select useCallback deps corrected
  ✗→✓ ToggleSection animation upgraded to grid-rows technique
  ✗→✓ StatusPage status icons marked aria-hidden

  OPEN ITEMS (not patched — scope exceeded or future work):
  - Block.tsx onClick guard checks `target.onclick !== null` which misses React
    synthetic handlers. A `data-interactive` attribute pattern would be more robust.
    Low priority; current behavior is correct for non-React handlers.
  - error.html version is hardcoded as v1.3.0. Needs manual update on each release.
    Consider templating via EJS or a build-step substitution.
  - Page.tsx has no max-width constraint — content can span full viewport width on
    ultra-wide displays. The `desktop:` breakpoint (1024px) is the last constraint.
    For a top-tier design site, a max-width cap (e.g. 1440px) would improve reading
    line length on > 27" screens.
