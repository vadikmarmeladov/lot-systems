FIRMWARE MODULES:

  │  main.cpp — init sequence, FreeRTOS task launch            │
  │                                                             │
  │  Tasks:                                                     │
  │   lot_wifi_task     — Wi-Fi connect, reconnect loop        │
  │   lot_notify_task   — poll lot-systems.com /device/notify  │
  │   lot_display_task  — update OLED from notification queue  │
  │   lot_sensor_task   — BME688 read loop (30s interval)      │
  │   lot_button_task   — button ISR → debounce → action       │
  │   lot_camera_task   — on-demand capture + JPEG compress    │
  │   lot_ota_task      — BLE OTA listener (background)        │
  │   lot_power_task    — deep sleep manager + wake reasons    │
  └────────────────────────────────────────────────────────────┘

MODULE DETAIL:

lot_wifi_task:
  - Stores SSID/password in NVS (provisioned via BLE at setup)
  - Uses esp_wifi with WPA2/WPA3-Personal
  - Reconnects on disconnect with 30s backoff
  - Powers down Wi-Fi modem between notification polls to save power
  - BLE provisioning: device broadcasts "LOT-NODE-XXXXXX" until provisioned

lot_notify_task:
  - Polls GET https://lot-systems.com/api/device/notifications
    every 60 seconds (configurable via NVS)
  - Auth: Bearer token from NVS
  - Response: JSON { notifications: [ { id, text, priority, expiresAt } ] }
  - Pushed to lot_display_task queue via FreeRTOS xQueueSend
  - Marks notifications ACK'd: POST /api/device/ack { ids: [...] }
  - On new notification: wake display from sleep, show for 20s, then sleep

lot_display_task:
  - Driver: Adafruit SH110X (SH1106) or u8g2 library
  - Default screen: time + battery % (bottom status bar)
  - Notification screen: full-width text, word-wrapped, auto-scroll for long text
  - Font: 8×8 pixel bitmap (crisp at OLED resolution)
  - Sleep: display off after 30s idle (GPIO wakes MCU → display wakes)
  - Brightness: fixed (no PWM needed for OLED)

lot_sensor_task:
  - BME688 via I2C (400kHz)
  - Bosch BSEC2 library for IAQ (Indoor Air Quality) index
  - Readings every 30s: temp_c, humidity_pct, pressure_hpa, iaq_index, gas_resistance
  - Batched upload to POST /api/device/heartbeat every 5 min
  - Local display: current temp+humidity shown on idle screen

lot_button_task:
  - GPIO interrupt on SW1 (active-low, internal pull-up)
  - Debounce: 50ms in software
  - Short press (< 800ms):  POST /api/device/log → event: hardware_copy
    Payload: { event: "hardware_copy", text: "Copy pressed on LOT NODE", context: { ... } }
  - Long press (> 2000ms): cycle display mode (idle / sensor / clock)
  - Double press:           trigger camera capture + send to /api/device/photo

lot_camera_task:
  - OV2640 via DVP (8-bit parallel), JPEG mode
  - Resolution: QVGA (320×240) for quick capture, SVGA (800×600) for photo
  - Capture on double button press or remote command
  - JPEG compressed to ~15KB, uploaded via POST /api/device/photo (multipart)

lot_ota_task:
  - NimBLE GATT server exposes LOT OTA Service (custom UUID)
  - BLE client (LOT Companion app) sends firmware binary in 512-byte chunks
  - ESP-IDF OTA partition scheme: OTA_0 + OTA_1 + factory
  - On success: reboot into new firmware partition
  - Version check prevents downgrade

lot_power_task:
  - Battery ADC via BQ25895 I2C register read
  - Deep sleep when battery < 10% and not charging
  - Light sleep (modem sleep) during notification poll intervals
  - Wake sources: RTC timer (60s), GPIO (button), charging detect

      User opens lot-systems.com/settings/device

    OTA Flow:
      User opens device settings → "Update Firmware"
      → System checks current device firmware version
      → If update available: download .bin from lot-systems.com/firmware/latest
      → Stream binary to device via BLE GATT in 512B chunks
      → Device reboots into new partition

  KEY FILE: src/client/components/DeviceSettings.tsx (NEW)

── B) LOT SERVER — DEVICE API ENDPOINTS ─────────────────────────────────────

  NEW ROUTES (add to src/server/routes/api.ts):

  POST /api/device/register
    Body: { deviceId: string, firmwareVersion: string }
    Auth: User JWT (associates device with user account)
    Returns: { deviceApiKey: string, userId: string }
    Stores: Device record in devices table (new Prisma model)

  GET /api/device/notifications
    Auth: Device API key (Bearer)
    Returns: { notifications: [{ id, text, priority, expiresAt }] }
    Logic: Returns queued notifications for device's user
           Notifications sourced from Memory Engine QOS output

  POST /api/device/ack
    Auth: Device API key
    Body: { ids: string[] }
    Logic: Marks notification records as delivered

  POST /api/device/log
    Auth: Device API key
    Body: { event: "hardware_copy" | "device_event", text: string, context?: object }
    Logic: Creates Log record for user (same as existing Log model)
           event: "hardware_copy" → shown in user's Log tab as "[LOT NODE] Copy"
    Response: { logId: string }

  POST /api/device/heartbeat
    Auth: Device API key
    Body: { batteryPct: number, temp: number, humidity: number,
            pressure: number, iaq: number, firmwareVersion: string }
    Logic: Updates device record with latest sensor data
           Creates a 'device_event' log entry once per hour (not every heartbeat)
    Response: { ok: true, serverTime: ISO8601 }

  POST /api/device/photo
    Auth: Device API key
    Content-Type: multipart/form-data
    Body: JPEG binary
    Logic: Stores image, associates with user memory entry
    Response: { photoId: string, url: string }

  GET /api/firmware/latest
    Auth: None (public endpoint)
    Query: ?platform=esp32s3
    Returns: { version: string, url: string, sha256: string }

08 // LOT API INTEGRATION SPEC
================================================================================

AUTHENTICATION FLOW:
  1. User sets up device via LOT Companion App (logged in as their account)
  2. POST /api/device/register → device receives unique deviceApiKey
  3. Key stored in device NVS flash (encrypted partition)
  4. All device→server requests: Authorization: Bearer <deviceApiKey>
  5. Server maps deviceApiKey → userId via Device table

  User presses button on LOT NODE

  → LOT NODE polls GET /api/device/notifications (60s interval)
