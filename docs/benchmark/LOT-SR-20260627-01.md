ALERT ENGINE DESIGN:
  · Client-side only — no server-side cron required
  · Deduplication via localStorage avoids repeated alert spam
  · Alert store key v2 (incremented to clear stale v1 data if any)
  · 5-minute check interval balances responsiveness vs CPU
  · Ref pattern for createLog prevents stale closure capture in setInterval

ALERT THRESHOLDS:
  D1      → T-1D   → Entry is tomorrow
  TODAY   → TODAY  → Entry matches current calendar date
  OVERDUE → +1D    → Entry was yesterday (first day missed)

T-MINUS PRECISION:
  Day-level only — entries store YYYY-MM-DD, no time component
  Countdown computed from startOf(today) to startOf(entryDate)
  Shows hours/minutes only via live clock for TODAY entries

  Block: SCHED: (alert) vs CAL: (entry creation)
  Levels uppercase, single token: D1 · TODAY · OVERDUE
  Entry type uppercase, body prose verbatim from user input
  tMinus field shows computed label at moment of alert fire
