DESIGN NOTES
--------------------------------------------------------------------------------
TIME TRACKING:
  - CalendarEntry gained `id` (log id) and `time: string | null` (HH:mm).
  - Optional native <input type="time"> beside the existing text field;
    validated with a strict HH:mm regex before persisting to log metadata
    (`{ date, time, text, entryType }` on the existing `calendar_entry`
    event — no new event type for entries themselves).
  - Entries sort by date then time (untimed entries sort last within a day);
    time renders inline (tabular-nums) in the day-detail list and the
    upcoming-entries list.

ALERT ENGINE (military-grade notification):
  - `todaysTimedEntries` — memoized: today's entries with a time set and not
    yet fired. This is the only list the engine watches, so the timer setup
    is a no-op on every day with no timed entries (the common case).
  - Firing loop: setInterval(15s), gated on `!document.hidden &&
    isRouteActive('system')` (matches the EvolutionMilestoneToast pattern
    already in the codebase) — checks once immediately on mount too, so an
    entry whose time already passed while the tab was closed still fires.
  - Fired ids persist to localStorage (`lot_calendar_fired_alerts_v1`,
    capped at 200 entries) so a page reload doesn't re-fire the same alert.
  - Each firing: (1) plays a two-tone klaxon via a new lazy-AudioContext
    util (`calendarAlert.ts`, same pattern as the existing
    `sovietKeyboard.ts` chimes — no new audio dependency), (2) writes a
    `calendar_alert_fired` Log entry (`[ALERT] <type>: <text> fired at
    <time>`) so every firing is auditable in the Log stream, (3) pushes the
    entry onto a stacked `ALERT :: HH:mm` overlay (fixed bottom-right,
    uppercase, monospace, red border/text on the flat `bg-bac` panel —
    Tailwind's built-in `animate-pulse`, no custom keyframes) with an ACK
    button to dismiss. Kept to the existing flat-border, no-shadow, no-
    rounded-corner visual language — "military-grade" reads through
    typography (uppercase, tracking-widest, bracketed `[ ALERT :: 14:30 ]`)
    rather than color noise.
  - T-minus countdown: a "NEXT: HH:mm — text" line always shows the next
    timed entry today; a live seconds-precision T-minus only appears once
    the target is within 60 minutes. The 1s ticker is started/stopped by a
    coarse 15s window check so it is never torn down and recreated every
    second while counting down (avoided a self-referential effect-recreate
    bug caught during implementation — the naive version depended the
    ticking effect directly on the live countdown value it was producing).

WHY NO FRAMEWORK CHANGE: researched the codebase first (agent survey) —
no toast/notification library installed (`sonner`/`react-hot-toast`/etc.
absent from package.json), no browser Notification API usage anywhere, no
existing "fire at wall-clock time" scheduler. Built the smallest engine
that satisfies "reliable + logged + minimalist" rather than adding a
dependency.
