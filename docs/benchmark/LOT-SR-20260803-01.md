DESIGN NOTE ON WHERE THE COMMAND IS PARSED: the command is detected
server-side, inside the existing POST /logs and PUT /logs/:id handlers, at
the point the Log's `text` is already being persisted — not client-side in
Logs.tsx's per-keystroke trigger effect (logTriggers.ts), which is where
every other /command lives. Reason: those saves are already the debounced
commit points (blur, Cmd+Enter, tab-switch, unmount all funnel to the same
onChange), so hooking there gets the finished note for free with zero new
client-side debounce logic — the 3700-line Logs.tsx component, already dense
with render-isolation optimizations, is untouched except for one help-text
line. The tradeoff: /email doesn't get a live in-progress preview like /qi
or /prayer do. For "the simplest" system this is the right side of that
tradeoff, and it avoids the double-send risk a naive per-keystroke hook
would have carried into a delivery that can't be un-sent.
