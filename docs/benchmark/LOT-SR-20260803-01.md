05b // FIXES APPLIED (this session)
--------------------------------------------------------------------------------
R1 SUBSCRIBE TIER BLIND SPOT
   SubscribeWidget.tsx: both pricing-tier buttons ("R&D $15" / "Usership
   $99") called the identical handleSubscribe handler — which tier a user
   picked was never recorded anywhere, client or server. Split into
   per-tier handlers and added recordSignal('subscribe', 'tier_clicked',
   {tier}). Added 'subscribe' to IntentionSignal['source'] union
   (intentionEngine.ts) — additive, no existing call sites affected
   (confirmed via tsc diff, see 04).

R2 AIFeedbackWidget RE-RENDER COST (same bug class as commit 9364aba)
   AIFeedbackWidget.tsx subscribed to the full intentionEngine store with
   zero memoization — re-renders (and reruns getStateInsight/getGuidance
   branching) on every recordSignal() call anywhere in the app, same
   pattern already fixed in its sibling "Biofield Engine" widgets
   (SignalStreamWidget/UserMetricsWidget) but missed here. Fixed the
   concrete double-computation: engine.recognizedPatterns was .filter()'d
   twice inline on the same JSX line for one conditional string — now
   computed once via useMemo keyed on engine.recognizedPatterns. Also
   replaced the redundant getUserState() call with the already-subscribed
   engine.userState (same object reference, one less store read per
   render).

R3 MicroCalculatorWidget REMOUNT-ON-KEYPRESS
   The `Key` button sub-component was declared inside the widget's render
   function body — recreated fresh every render, so React treated every
   calculator button as a new component type and remounted its DOM node on
   every single digit press instead of just updating props. Hoisted `Key`
   to module scope (it has no closure dependencies — pure props). This was
   the only inline-component-definition instance found across all 37
   widget files.

R4 ERROR-BOUNDARY COVERAGE GAP
   TimeWidget (both render sites in System.tsx) and QuantumRandomWidget
   were the only 2 of 37 rendered widgets with no WidgetErrorBoundary
   ancestor — a throw in either would propagate up and take a larger
   section of the tab down instead of degrading gracefully like every
   other widget. Wrapped both render sites (WidgetErrorBoundary is a class
   component that renders children directly on the happy path — zero
   layout impact, confirmed by reading its render()).

NOT FIXED THIS SESSION (recorded for a future scoped session — each is a
structural/product decision, not a mechanical scan-fix):
  - No test framework/tests exist for any widget or store (05, TESTING).
  - forceSyncToServer() dead code + no beforeunload flush for QIE signals.
  - TimeWidget / CosmicUpdateWidget generate action / CalendarWidget browse
    navigation still unlogged.
  - WidgetErrorBoundary crash + mount-perf data (__LOT_WIDGET_PERF__) is
    console-only, nothing ships it server-side.
  - LazyMount used for 1/37 widgets; broader adoption needs per-widget
    priority triage, not a blanket change.
  - prisma/schema.prisma is an unused 15-line stub (no models) — actual
    ORM in use is Sequelize (src/server/models/*.ts). Docs referencing
    "Prisma models" for widget persistence should be corrected.
