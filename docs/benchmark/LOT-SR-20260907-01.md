01a // DESIGN — reused, not invented
--------------------------------------------------------------------------------
Read live before designing: logTriggers.ts (17 existing /commands, pure
detector + Logs.tsx call-site pattern), the chat_message and
direct_message_sent write paths (create row -> sync.emit -> Log.create),
Sync.tsx (canAccessChat tag gate, SSE merge pattern), /api/cohorts +
CohortConnectWidget (cohort match = {user, similarity, sharedPatterns},
"Send message" currently just navigates to Sync). Also found: About.tsx's
own changelog already names a prior "LOT Mail" attempt (branch
relaxed-hamilton-eRBVA, 8 iterations, BEST candidate) with near-identical
shape — /email trigger, Sync inbox, SSE, Usership-gated — but its code was
never merged and no longer exists on any branch. This build is a fresh
implementation, not a recovery of that branch.

Design decisions:
  - Reuse the direct_messages table/model as-is. An email IS a 1:1 message;
    the only difference from a plain DM is the entry point (/email in Log,
    not DirectMessageThread) and the Log event name (email_message).
  - Recipient resolution is the Cohort/Community tie-in: "/email to <name>"
    matches only against the sender's current /api/cohorts matches. No new
    user-search endpoint, no open directory — LOT Email is reachable
    through LOT Community or not at all. This is the concrete "incorporate
    with Cohort Dating through LOT Community" requirement, not a metaphor.
  - Compose happens in the sender's Log (their own email_message Log entry,
    COCKPIT-RULE body: TO <name> + message). Delivery happens in the
    receiver's Sync (new Inbox section, GET + SSE 'email_message'), which
    is literally "compose in Log, appears in Sync" as specified. LOT Chat
    tie-in: the Inbox lives inside Sync.tsx itself, gated by the same
    canAccessChat tag set (Usership/Onyx/Legacy/RND/Admin) chat already
    uses — one access boundary, not two.
