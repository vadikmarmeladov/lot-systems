02 // DESIGN NOTES
--------------------------------------------------------------------------------
ARCHITECTURE:    Kept the Log field as the single source of truth — no new
                 mutable state, no schema migration. Every new capability is
                 an additional log event, matching the append-only pattern
                 already used across the system (recordCalendarSignal,
                 qos_coherence, archetype_shift, etc.):
                   - calendar_entry           (existing) — schedule an item,
                     now optionally carries time + reminderMinutes
                   - calendar_entry_complete  (new) — closes an entry, logs
                     signed variance in minutes vs. scheduled time
                   - calendar_reminder_fired  (new) — fired once per entry
                     when its reminder window opens
                 Entry identity for completion/reminder matching is a derived
                 key (date|type|text) rather than a stored id — no server
                 changes needed, PUT /api/logs/:id still only patches text.
UI:              No new chrome. Time + reminder inputs appear inline in the
                 existing "Note / Task / Call" disclosure only when adding an
                 entry with a time. T-MINUS countdown sits next to the
                 existing "Add date" button. Entries render a ✓ complete
                 button and inline OVERDUE / T-minus / DONE status — all
                 text-only, same text-acc/opacity scale as the rest of the
                 widget. No color, no icons beyond the existing typographic
                 style.
NOTIFICATIONS:   New CalendarAlertToast.tsx mirrors the existing
                 EvolutionMilestoneToast pattern (fixed bottom-center,
                 fade in/out keyframes) but reads as a military briefing:
                 corner brackets (◤ ◢), "INCOMING — <TYPE>" header, monospace
                 tabular-nums countdown, manual dismiss. A new tacticalAlert.ts
                 util plays a distinct 3-beep square-wave cue (separate
                 AudioContext instance from the existing Soviet-chime hourly
                 tone, deliberately sharper/faster cadence) so the two audio
                 languages don't collide. Reminder firing is deduplicated via
                 localStorage (survives reload) plus an in-memory ref guard.
LOG FIELD:       Logs.tsx gets two new military-format handlers alongside the
                 existing CAL: — CAL-X: (completion, shows EARLY/LATE Nm) and
                 CAL-RMD: (reminder fired, shows T-Nm lead). Matches the
                 established terse code+metric format (no prose body).
