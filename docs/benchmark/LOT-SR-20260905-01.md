05 // WHAT CHANGED
--------------------------------------------------------------------------------
/story now reads an optional period argument directly from the Log text:
  /story              -> compresses the last 1 day (unchanged default behavior)
  /story week         -> compresses the last 7 days
  /story month        -> compresses the last 30 days
  /story year         -> compresses the last 365 days
  /story week feeling steady lately   -> period="week", logText="feeling steady lately"

Server (`POST /api/story`, src/server/routes/api.ts):
  - Body now accepts `period?: 'day'|'week'|'month'|'year'`, defaulting to 'day'
    when absent or invalid.
  - The Log.findAll query is now bounded by `createdAt >= since` (since = now -
    period days), replacing the flat "last 200 logs regardless of age" read.
    A week-old /story call can no longer silently draw on log entries from
    months ago.
  - Sample size scales with window (day=40, week=120, month=300, year=800) so
    the AI prompt stays a bounded, fixed-cost read regardless of period length.
  - The prompt states the compression window explicitly ("COMPRESSION WINDOW:
    past 1 week (37 logs in window)") so the model is not free to imply data
    outside what was actually queried — Honest Engineering doctrine applied to
    prompt construction, not just to this report.
  - Response now returns `period` alongside `story`/`logId`; the generated
    Log row's metadata records `period`, `logsInWindow`, and `badgeCount`.

Arcade tie-in (honest, not decorative):
  - `req.user.metadata.badges.earnedBadges` (populated by the existing
    POST /sync-badges route — real synced milestone badges: milestone_7/30/100,
    never the full client-side word-turn catalog) is read and passed into the
    prompt as a plain PROGRESSION line. The system prompt instructs the model
    to weave it in "once, plainly — no hype" only when badges are present.
    No badge count or achievement is ever invented when the field is empty.

Client (src/client/components/Logs.tsx, src/client/utils/logTriggers.ts,
src/client/queries.ts):
  - story-mode trigger handler parses a leading day|today|week|month|year token
    (word-boundary matched, so "weekly update" does not false-positive as
    period=week) and strips it before sending logText.
  - New storyPeriod state drives the 📖 Block label ("📖 WEEK", "📖 MONTH") and
    the loading placeholder ("compressing your week...").
  - useStoryGeneration mutation type and /system help text updated to document
    the new syntax: "/story [day|week|month|year]  Compress that window into a
    personal story (default: day)".

Scope note: the environment-context-snapshot-per-click concept and the
User→QIE→Together-AI→stored-data pipeline named in the directive are already
live system-wide via intentionEngine.ts's recordSignal()/QOS-snapshot
machinery (LEXICON: QIE, QOS SNAPSHOT VIEW) and Job 24's weekly
lot_ai_story compression (scheduled-jobs.ts:834). Rebuilding either as new
infrastructure would have duplicated an existing, working system — the
Honest Engineering rule in this protocol cuts against inventing parallel
mechanisms where a real one already runs. This session's scope was narrowed
to the concrete, currently-missing piece: period-aware /story compression.
