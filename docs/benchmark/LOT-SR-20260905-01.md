05b // WHAT WAS BUILT
--------------------------------------------------------------------------------
R1 TIME TRACKING     CalendarWidget: per-entry Track/Stop control. Timestamp-
                     based (Date.now() diff, not setInterval accumulation) ->
                     immune to interval drift. Active timer persisted to
                     localStorage (lot_calendar_active_timer) so a running
                     session survives page reload; state restored on mount.
                     Only one timer at a time — other entries' Track controls
                     disable while one is running, so a stray click can't
                     silently overwrite the active session. A REC indicator
                     bar is visible even with the calendar view collapsed.

R2 LOG WIRING        Stop -> useCreateLog with new event 'calendar_time_
                     tracked', metadata {date, text, entryType, duration
                     Seconds}. Added to the server's displayableEvents allow-
                     list (src/server/routes/api.ts) — an event not on that
                     list silently never reaches useLogs(), same gap pattern
                     documented for recordLogSignal in the 2026-04-29 v11
                     assembly note. Also added to the signal-gap moduleMap
                     ('calendar_time_tracked' -> 'calendar') alongside the
                     existing calendar_entry mapping.

R3 QIE SIGNAL        New recordCalendarTimeSignal(date, durationSeconds) in
                     intentionEngine.ts, same shape/source ('log') as the
                     existing recordCalendarSignal — feeds the Temporal
                     Planner module and Pattern 26 (calendar-gap) detection
                     without inventing a new IntentionSignal source or a new
                     numbered pattern (kept additive, not a scope expansion).

R4 MILITARY LOG      New Logs.tsx handler for calendar_time_tracked: Block
                     label "CAL-T:", uppercase entryType, DUR: Xm Ys, date —
                     matches the existing CAL:/QOS-COHR: terse-code
                     convention exactly (uppercase tracking-widest, no
                     gradients, no icons).

R5 NOTIFICATIONS     New CalendarEventToast component + calendarNotifications
                     nanostore. Two triggers, one shell:
                       CAL-ALERT — a scheduled entry's date arrives (checked
                       every 60s while route is 'system' and tab is visible;
                       deduped per entry per day via localStorage so it fires
                       once).
                       TIME-LOG — fires immediately when a tracked session is
                       saved to the Log, showing the logged duration.
                     Terminal-grid styling: fixed bottom-center, bracket-coded
                     label ([CAL-ALERT] / [TIME-LOG]), uppercase tracking-
                     widest, border-acc/20 + grid-fill-light — same shell
                     convention as EvolutionMilestoneToast.tsx, self-contained
                     keyframes (calNotifyIn/calNotifyOut) to avoid any
                     collision with that component's own injected styles.
                     Mounted in System.tsx next to CalendarWidget.
