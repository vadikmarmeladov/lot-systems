05 // FINDINGS — WIDGET SYSTEMS HEALTH
--------------------------------------------------------------------------------
WIRING & DATA (35+ widgets in src/client/components/*Widget.tsx)
- Most analytics/log-backed widgets (Memory, Calendar, GoalJourney,
  PatternInsights, RecipeWidget) are genuinely wired through react-query
  hooks in queries.ts to real Fastify routes in api.ts/os-api.ts. No widget
  calls a route that doesn't exist.
- A meaningful cluster — QuantumStateWidget, SignalStreamWidget,
  ChakraErgonomicsWidget, ArchitectWidget, PlannerWidget, IntentionsWidget,
  MicroGameWidget/MicroImageWidget — reads/writes only the client-only
  `intentionEngine.ts` nanostore. Nothing here touches the server or a
  database; it is real UI state, not fake data, but it is simulated/
  heuristic, not measured or persisted. Worth labeling as such in-product if
  not already.
- SystemPulseWidget and UserMetricsWidget bypass react-query with raw
  `fetch` in `useEffect`, inconsistent with the rest of the codebase's
  pattern (harmless today, but a maintenance inconsistency).
- WidgetErrorBoundary wraps ~30 widgets in System.tsx; TimeWidget and
  QuantumRandomWidget render unwrapped. Boundaries only catch render
  throws — most query-backed widgets fail silently on fetch error
  (`if (isLoading) return null`), with MemoryWidget the lone widget that
  surfaces an explicit error state to the user.
- TESTING: zero test files exist anywhere in the repo (no *.test.ts(x),
  *.spec.ts(x), __tests__, no jest/vitest dependency). None of the 35+
  widgets, 152 QIE patterns, or Memory Engine logic has any automated
  coverage — every fix here was verified by hand and by the build gate
  only.
- DUPLICATES: AwarenessDashboard.tsx and JournalReflection.tsx are confirmed
  true orphans (zero imports anywhere). All other widget files are wired
  into System.tsx or About.tsx.

LOT AI / SYSTEM TAB / PORTRAIT
- "LOT AI" is a label inside EmotionalCheckIn's morning/evening flow, not a
  standalone chat surface. The real prompt engine is `buildPrompt()` in
  src/server/utils/memory.ts:241, which does pull genuine widget signal
  (weather, QIE energy/clarity/alignment, planner intention, goals, memory
  history, cohort/archetype) into AI context.
- System.tsx (1071 lines) is real: ~40 widgets driven by live queries, not
  mocked.
- There is no "Portrait" page by that name; the public-facing profile is
  PublicProfile.tsx (`/u/:id`), backed by a real endpoint that computes
  psychologicalProfile from the same archetype/cohort engine used by LOT AI.
  A single hardcoded demo account (`machiavelli`) intentionally returns
  mocked data — expected, not a bug.
- DOC DRIFT: LOT-SYSTEM-OUTLINE.md states the AI engine is "Claude Sonnet /
  Claude Haiku"; the live code's `AI_ENGINE_PREFERENCE` in memory.ts:52 is
  `'together'` (Together AI / Llama-3.3-70B, Claude as fallback only). The
  outline should be corrected to match reality, or the code corrected to
  match intent — S-2 call.

QUANTUM INTENT ENGINE / MEMORY / STORY — TOP FINDING
- QIE lives entirely in one client file, src/client/stores/intentionEngine.ts
  (6,503 lines); `analyzeIntentions()` alone is ~3,200 lines of 152
  sequential if-blocks with no shared matcher abstraction — a god function,
  single source of truth, but structurally unmaintainable at this size and
  fully untested.
- CONFIRMED SPLIT-BRAIN BUG: two parallel Memory Engine implementations
  exist — the legacy src/server/utils/memory.ts (1,917 lines) and a modular
  rewrite under src/server/utils/memory/ (~2,900 lines across 9 files,
  landed 2026-06-29). Both define near-identical `buildPrompt()`,
  `generateMemoryStory()`, `composeLocalStory()`, `formatLog()`,
  `extractUserTraits()`, `determineUserCohort()`. Because the path alias
  `#server/utils/*` resolves the bare specifier to the flat file, api.ts,
  admin-api.ts, and monthly-summary.ts silently run the OLD monolith, while
  public-api.ts deep-imports the NEW modular version for story generation.
  A fix landed in one copy does not reach the other's call sites. This is
  live, not hypothetical: LOT AI prompts and the public profile's story
  generation are running divergent logic today. This needs an S-2 decision
  (pick one implementation, delete the other, repoint all four call sites)
  before it is safe to touch either copy further.
- Story feature (`composeLocalStory`) reads only Memory `answer` logs, not
  QIE pattern/archetype output directly — matches the 20260707 "poetic
  rewrite" description. No dangling references to the removed WorldCanvas
  widget remain.

LOAD SPEED / LAG
- The 20260719 widget-lag fixes (logs LIMIT 500, stats staleTime/interval
  120s, quantumState useEffect pattern, GPU-composited button hover) are
  all still in place — no regression.
- NEW: SystemPulseWidget polls `/api/system/pulse` every 10s via a manual
  setInterval — the fastest client poll in the app. It is guarded
  (document.hidden, active-route check) and server-cached for 5s, so it is
  mitigated but is the one interval worth tightening if System tab idle-CPU
  matters.
- No code-splitting: all ~40 widgets are statically imported into System.tsx
  and land in one JS chunk regardless of esbuild's `splitting: true`. Open
  opportunity, not a regression, and not touched this session.
- Minor inconsistency: PrimaryBtn (light theme) and three other spots use
  bare `transition-all` instead of the documented GPU-composited pattern;
  low cost today but worth a follow-up pass for consistency.

BUILD-TIME CONTENT BUG (found via warnings, not fixed this session)
- badges.ts has two accidental key collisions: `quarter_drop` (line 3214 vs
  5501) and `elixir_found` (line 4825 vs 6883) — each pair has different
  symbol/description/rarity text, meaning the first-defined badge of each
  pair is silently dead (JS object-literal semantics let the later key win).
  Not fixed here because renaming either key requires verifying no other
  file references the shadowed badge's id string by name — left for a
  dedicated Badge Codex pass rather than folded into this audit.

15-MONTH UI REVEAL SCHEDULE — MISMATCH WITH TASK BRIEF
- The only month-keyed progressive-reveal widget in the codebase is
  MonthlyPulseWidget.tsx, and it is hardcoded 1–12 (`MONTH_MESSAGES`,
  capped at "12 / 12 months — One year with LOT"). No 15-month schedule
  exists anywhere in code or docs. This is either a brief that describes a
  future/intended extension not yet built, or a mismatch between the
  product brief and the shipped 12-month arc — flagging for S-2 rather than
  fabricating 3 more months of milestone copy in the founder's voice.

WIDGET USAGE LOGGING ("military-log" data log across the platform)
- No dedicated widget-usage tracking exists. os-api.ts references "widget
  usage" only incidentally, inside cohort-imbalance heuristics — there is no
  per-widget view/interaction log distinct from the domain event log
  (journal, planner, memory, etc.). If a platform-wide widget-usage ledger
  is wanted as its own feature, it does not exist yet and would be new
  work, not a wiring fix.
