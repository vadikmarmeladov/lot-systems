WHAT WAS BUILT

1. calendarEntries.ts (new, shared) — single source of truth for both widget and
   toast: getCalendarEntries() derives entries from Log rows (calendar_entry +
   calendar_entry_complete, matched by date+text), getEntryMoment() resolves an
   entry to a precise instant (date+time, or end-of-day when no time was set),
   getEntryStatus() classifies completed/overdue/due-soon/scheduled, formatCountdown()
   renders T-2H15M / T+0H42M. Two widgets sharing one derivation means the toast
   and the widget can never disagree about what's due.

2. CalendarWidget.tsx — added a <input type="time"> alongside the existing
   note/task/call selector; entries now carry an optional time in metadata.
   A 30s tick (setInterval → setNow) keeps countdown/status live without reload.
   Upcoming list now shows every uncompleted entry (not just date >= today) so
   an overdue item never silently drops off — that's the "reliable" half of the
   brief. Added a Done button per entry that writes a new calendar_entry_complete
   log rather than mutating the original (append-only, matching Ledger/Log
   philosophy already used everywhere else in this codebase).

3. CalendarAlertToast.tsx (new) — military-grade Terminal Grid toast, separate
   from EvolutionMilestoneToast (different corner, different visual grammar:
   bracket header "[ CAL-ALERT // T-MINUS 15 ]", pulsing dot, tabular-nums
   timestamp). Polls every 20s, fires at most once per entry per threshold
   (T-MINUS 15, EXECUTE, OVERDUE at +60min), dedup via a localStorage-backed
   fired-set. Every fire writes a calendar_alert_fired Log row — the alert
   trail is auditable in Log, not just a client-side toast that could be missed.

4. Logs.tsx — three new COCKPIT-RULE handlers (CAL-LOG:, CAL-DONE:, CAL-ALERT:)
   replacing the generic LOG: fallback calendar_entry was silently using before.
   Matches the existing 90+ event-specific Block renderers exactly in shape.

5. intentionEngine.ts — recordCalendarAlertSignal() records signal:'calendar_update'.
   Audit of Pattern 46 (temporal-coherence-window) found it already checks for
   'calendar_entry' OR 'calendar_update' but nothing had ever emitted the latter
   — the same class of dead-signal gap the v11 assembly log documented for
   recordLogSignal(). Closed on discovery rather than left for a future audit.
