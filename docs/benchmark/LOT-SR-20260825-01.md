TIME TRACKING   CalendarEntry gains time (HH:mm, optional) and durationMinutes
                (task/call only). Add-entry form gets a <input type=time> and,
                for task/call, a minutes field. Entries sort date then time;
                upcoming list shows "· HH:mm" and "(Nm)" duration suffix.
RELIABILITY     createLog(...) gains onError -> FAILED toast (6s hold, vs 4s
                for others) so a dropped write is visible instead of silent.
                entryStatus() computed with plain dayjs setters (no format-
                string parsing) to avoid the missing-plugin trap above.
ALERT TOAST     Self-contained fixed-position bottom toast, bracket/mono,
                uppercase, tracking-widest — "LOGGED" (acc), "FAILED"/"OVERDUE"
                (red), "T-MINUS"/"INCOMING" (gold). A 60s interval (paused on
                hidden tab / off the system route, matching the existing
                EvolutionMilestoneToast convention) fires one alert per entry
                when a timed entry on today's date enters a ±15min window;
                each key alerts once per session (alertedRef Set).
LOG INTEGRATION recordTimeTrackingSignal(entryType, durationMinutes) added to
                intentionEngine.ts alongside the existing recordCalendarSignal,
                same recordSignal('log', ...) plumbing. Logs.tsx CAL: block
                now renders time/duration when present so the Log view and the
                widget agree on what was recorded.
SCOPE           No new abstractions: reused the Block/Button primitives, the
                acc/red/gold tokens already in tailwind.config.js, and the
                exact toast-injection pattern already established by
                EvolutionMilestoneToast.tsx (own keyframe names to stay
                independent of that module's load order).
