                                      Section 2 status line now reads live state;
                                      Section 3 — Issue Log added

MECHANICS:
  - UPGRADE requires the USERSHIP/AI tag as base layer (403 otherwise).
  - Roster intake (size, shipping address/city/country/phone, cadence start)
    is required before enlistment; server validates completeness.
  - On confirm: tags gain 'basic' (lowercase, matching the 'usership' /
    'suspended' storage convention); metadata.basics records status,
    intake, enrolledAt, nextIssueAt (derived from cadenceStart), and an
    append-only issue log (PENDING -> CONFIRMED entries).
  - STAND DOWN: removes 'basic' tag only — 'usership' untouched — logs the
    event, status -> STAND_DOWN. Re-enlistment re-opens the intake form.
  - Billing: the +USD 100.00/MO additive line is recorded to the roster
    (metadata.basics) and to the issue log for audit. No payment processor
    is wired in this codebase (no Stripe keys, no billing package present;
    `stripeCustomerId` on the User model is unused elsewhere) — real card
    capture is explicitly out of scope for an unattended build session and
    is deferred to a human-supervised integration pass.
  - No new migration: metadata is JSONB on the existing users table.

DOCTRINE COMPLIANCE: no new color, icon, or radius. Terminal-grid tokens
reused (font-mono, 2px/1px rules, uppercase tracked labels). Roster intake
and controls use square 2px-bordered buttons, not the app's rounded
Button component, to hold the "no radius" constraint on this tab.
