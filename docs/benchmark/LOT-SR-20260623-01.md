## SYSTEM DESIGN

### Architecture

```
Log (write)
  ↓  /email to Hitomi  detected by logTriggers.ts
  ↓  extractEmailTarget() → "Hitomi"
  ↓  emailComposeTarget store atom set to "Hitomi"
  ↓  EmailCompose modal opens pre-filled

EmailCompose modal (compose)
  ↓  POST /api/lot-emails { recipientName, subject, body }
  ↓  Server creates lot_emails record
  ↓  sync.emit('lot_email', { ...email, senderName })
  ↓  Log entry created: event='lot_email_sent'

Sync (receive)
  ↓  sync.listen('lot_email') → setLotEmails([...])
  ↓  LOT® Mail section renders above chat feed
  ↓  Shows: sender → recipient · subject · body preview · timestamp

LOT Community (initiate)
  ↓  AdminUser profile page
  ↓  📧 Email button → sets emailComposeTarget to user's full name
  ↓  EmailCompose modal opens pre-filled with that user
```

## INTERACTION FLOW

### Primary: Log → Email

```
1. User opens /log tab
2. Types: /email to Hitomi
3. detectNewTriggers() detects 'email-compose'
4. extractEmailTarget("/email to Hitomi") → "Hitomi"
5. stores.emailComposeTarget.set("Hitomi")
6. EmailCompose modal appears (fixed overlay)
7. "To" field pre-filled: Hitomi
8. User types subject + body
9. Clicks Send
10. POST /api/lot-emails { recipientName: "Hitomi", subject, body }
11. Server creates lot_email record, emits SSE
12. Modal shows "Sent" → auto-closes after 1.4s
13. Sync tab shows new email at top of LOT® Mail section
```

### Secondary: LOT Community → Email

```
1. User navigates to /us (LOT Community)
2. Opens any user profile
3. Sees 📧 Email button next to user name
4. Clicks → EmailCompose opens pre-filled with that user's name
5. Composes and sends
```

### Receive: Sync feed

```
1. Any connected client receives 'lot_email' SSE event
2. Sync.tsx appends to lotEmails[]
3. LOT® Mail section renders above chat messages
4. Shows last 5 emails: sender → recipient, subject, body preview, time
```

## DOCTRINE NOTES

```
SIGNAL CLARITY     /email to Hitomi is unambiguous intent — one command,
                   one recipient, compose modal appears. No menus.

INTEGRATION DEPTH  Email lives in three surfaces: Log (compose), Sync
                   (receive + discover), Community (initiate). One model,
                   three entry points.

PRIVACY            recipientUserId is optional — the system works with
                   just a name. Full name resolution is a future upgrade
                   without breaking the current UX.

REAL-TIME          SSE broadcast means all open sessions see new emails
                   land in Sync instantly. Same pattern as chat_message.

SIMPLICITY         Smallest possible email: just a name and a body. Subject
                   is optional. No attachments, no threading v1. Ship clean.
```
