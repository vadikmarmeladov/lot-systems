## ARCHITECTURE

### System Design

LOT Email is a **closed-loop internal messaging system** — fully within the LOT® ecosystem. No external email. Messages travel from Log (compose) → Server (store) → Sync (broadcast) → Inbox (receive).

```
Log  →  /email to Hitomi  →  Compose Panel
                                     ↓
                           POST /api/email/send
                                     ↓
                      DB: lot_emails table (stored)
                      LOG: email_sent event
                      SYNC: lot_email broadcast
                                     ↓
             Sync Feed ←── ✉ Vadim → Hitomi  (all operators)
                                     ↓
             Email Inbox Widget ←── recipient sees full body
```

## DATABASE SCHEMA

**Table: `lot_emails`**

| Column | Type | Notes |
|--------|------|-------|
| `id` | UUID PK | Auto-generated |
| `fromUserId` | UUID FK → users | CASCADE delete |
| `toUserId` | UUID FK → users (nullable) | SET NULL on delete |
| `fromName` | TEXT | Denormalized sender name |
| `toName` | TEXT | Recipient name from command |
| `subject` | TEXT (nullable) | Optional subject |
| `body` | TEXT | Message body |
| `status` | ENUM('sent','read') | Read state |
| `createdAt` | DATE | Auto |
| `updatedAt` | DATE | Auto |

**Indexes:** `(toUserId, createdAt)`, `(fromUserId, createdAt)`

## API ROUTES

All routes at `/api/*` prefix (authenticated):

| Method | Path | Action |
|--------|------|--------|
| POST | `/api/email/send` | Compose + send email |
| GET | `/api/email/inbox` | Get received emails (limit 50) |
| GET | `/api/email/sent` | Get sent emails (limit 50) |
| POST | `/api/email/:id/read` | Mark email as read |

**Send logic:**
1. Fuzzy match recipient by first name (case-insensitive)
2. Store email with `fromName` denormalized
3. Create `email_sent` log entry
4. Broadcast `lot_email` sync event (names + preview only, no body)

## USER EXPERIENCE

### Composing (Log)

```
User types in Log:  /email to Hitomi

→ Inline compose panel appears:

  MAIL:   TO HITOMI
          [ compose message... ]
          [SEND]  CANCEL
```

The `/email to [name]` pattern is detected via `detectNewTriggers()` in `logTriggers.ts`. The compose panel appears inline beneath the Log textarea. On send, the panel clears and shows "SENT." for 4 seconds.

### Log History

After sending, a `email_sent` event appears in the Log feed:

```
  MAIL:   → HITOMI
          Your message lands here...
```

### Sync Feed

All connected operators see the email notification:

```
  ✉  VADIM → HITOMI                    2m ago
```

No body is visible — only sender → recipient. This creates social signal for Cohort Dating (who's talking to whom in the community).

### Email Inbox Widget (System)

Shown in the Community stack:

```
  EMAIL [3]:   INBOX  |  SENT
  ─────────────────────────────────
  from Hitomi · 2h
  Your message landed. Thank...
  ─────────────────────────────────
  from Marcus · 4h
  Meeting moved to Thursday...
  ─────────────────────────────────
  /email to [name] in Log to compose
```

Unread count shown in label. Click to expand full message. Marks as read automatically.

## LEXICON UPDATES

**LOT-MAIL** — The internal email system of LOT®. Messages flow entirely within the platform. Compose via `/email to [name]` in Log. Inbox visible in System under Community stack.

**email-compose** — Log trigger. Fires when user types `/email to [name]`. Opens inline compose panel in NoteEditor.

**email_sent** — Log event type. Recorded when an email is sent. Stores `toName` and body preview in metadata.

**lot_email** — Sync event. Broadcast to all operators on email send. Contains sender name, recipient name, and preview (no body). Visible in Sync feed as community activity.
