### 1. Time Support
- Optional HH:MM time field on every entry
- `<input type="time">` in the add-entry form alongside the text field
- Time stored in `metadata.time` (string, `HH:MM`)
- Entries sorted by date then time within the same day

### 2. Military-Grade Alert System
- 30-second polling interval via `setInterval`  
- Reads live log data through a ref (no stale closure bugs)
- **Timed entries:** when current time enters a 5-minute post-event window, fires an alert log:
  ```
  ◼ SCHEDULE ALERT ◼ [TASK] INVESTOR CALL // 14:30 // EXECUTE NOW
  ```
- **Daily brief:** at 08:00–08:05, fires a summary of all-day (no-time) events:
  ```
  ◼ DAILY BRIEF ◼ 3 EVENTS TODAY — [T] Gym / [N] Team standup / [C] Client call
  ```
- Deduplication via `sessionStorage` key set (`cal-alerts-v1`) — each alert fires exactly once per session per event

### 3. Entry Deletion
- Each entry in the day view shows an `×` button
- Tap once → switches to `del / ×` confirm state
- Confirm → calls `useUpdateLog({ id, text: '' })` which triggers server soft-delete (existing pattern)
- Cancel → returns to view state
- Query cache invalidated on success

### 4. Upcoming List — Countdown & Type Badges
- Each upcoming row now shows:  
  `[countdown] [type] [time?] [date] [text]`  
  Example: `TODAY  [T]  14:30  Sun 21 Jun  Investor call`
- Countdown labels: `TODAY` / `T-1` / `T-7` / `PAST`
- Today entries at full `text-acc` opacity, future at `text-acc/60`
- Type badges: `[N]` note / `[T]` task / `[C]` call

### 5. Smart Widget Label
- Label reads `Calendar: [3 today]` when there are entries today
- Falls back to `Calendar:` when no today entries

### 6. Calendar Grid Enhancement
- Dates with entries show a `·` dot suffix: `M21·`
- Dates with entries in current month displayed at `text-acc/70` (vs `text-acc/40` for empty dates)

## ARCHITECTURE NOTES

**Stale-closure pattern:** The alert interval runs once on mount (empty deps array). Three refs (`logsRef`, `createLogRef`, `queryClientRef`) are synced on every render to give the interval live data access without re-registering it.

**Session dedup:** `sessionStorage` chosen deliberately — persists across tab refreshes but clears on session end. Prevents re-firing the same alert if the page hard-reloads within the 5-minute window. Does not prevent next-day re-fire (correct behavior).

**No breaking changes:** All existing `calendar_entry` logs are fully compatible. New `time` field is optional and absent on legacy entries. New `calendar_alert` event type is additive.
