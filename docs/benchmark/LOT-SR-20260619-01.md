## LOT MAIL SYSTEM — DESIGN RECORD

### Architecture

```
LAYER        COMPONENT                     ROLE
─────────    ──────────────────────────    ────────────────────────────────────
TRIGGER      logTriggers.ts               Detects /email · ✉️ in NoteEditor
COMPOSE      Logs.tsx NoteEditor          Parses TO: + MSG: · auto-sends · shows MAIL: block
TRANSPORT    POST /api/mail               Creates lot_mail record · emits SSE lot_mail event
STORE        lot_mails table              UUID PK · senderId · senderName · recipientName · message · isRead
INBOX        GET /api/mail/inbox          ILIKE match on recipientName vs user.firstName
READ         PUT /api/mail/:id/read       Marks isRead=true · checks ownership
DISPLAY      Sync.tsx                     MAIL · LOT COMMUNITY section above chat feed
SSE          lot_mail event               Real-time delivery — client filters by firstName
```

### Compose Flow

```
User types in Log:
  /email to Hitomi
  Hello, thinking of you today.

TRIGGER fires:  email-compose
PARSE:          recipientName = "Hitomi"
                message = "Hello, thinking of you today."
LOG DISPLAY:
  MAIL:
  TO:  Hitomi
  Hello, thinking of you today.
  Transmitting...
  → SENT ✓
```

### Sync Inbox Flow

```
Sync.tsx — MAIL · LOT COMMUNITY section (above chat feed):
  Vadik    Hello, thinking of you today.          [time]
  [unread = full opacity; read = 30% opacity]
  [click → mark read via PUT /api/mail/:id/read]
```

### Cohort Dating Integration

LOT Mail is the messaging backbone for Cohort Dating matches.
When two operators are matched via COHORT classification, they can
communicate via /email to <firstName> — no additional infrastructure needed.
The ILIKE match on firstName means the recipient is anyone in the community
with that first name who has received the mail.

### Security Model

- Sender must be authenticated (standard session auth)
- Recipient ownership check on mark-read (firstName ILIKE match)
- Message length capped: recipientName 100 chars, message 2000 chars
- No PII leakage: inbox only returns mails addressed to current user's firstName
- SSE lot_mail event — client filters by own firstName (defense-in-depth)
