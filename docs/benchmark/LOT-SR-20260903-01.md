WHAT CHANGED, PLAINLY:

astrology.ts — new pure function getPersonalZodiacResonance(now, timestamps,
minSample=5). Buckets the caller's own Log entry timestamps into the 12
existing hourly-zodiac windows (reuses getHourlyZodiac(), no new time logic),
finds the bucket with the most entries, and reports whether the live hour
falls in that bucket. Returns peakHour: null under the 5-entry minimum so a
brand-new account never sees a single-entry "peak hour" as if it meant
anything. No side effects, no I/O — same style as the other exports in the
file.

System.tsx — answerLogs (already computed for the Journey view) is now also
fed into personalZodiac via the new function. The existing "Astrology:" line
(rendered in both the plain and the paid/pro layout) gains one conditional
line — "⟡ Your peak hour — most active here across N entries" — only when
the live hourly zodiac matches the user's own historical peak. The daily
QIE-sync effect (previously fired once per calendar day into the signal bus
regardless of Log state) was reordered to run after answerLogs/personalZodiac
are computed, and now passes personalPeakHour + isPersonalPeakHour into
recordAstrologySignal alongside the existing ambient fields.

intentionEngine.ts — recordAstrologySignal() gained two optional trailing
parameters (backward compatible; no other call site touches it) carrying the
personalization into the signal's metadata, so any widget reading the
'astrology' signal source downstream — not just System.tsx — can see the
alignment. WIDGET_DEPENDENCY_MAP.astrology changed from `[]` to `['log']`:
this is the actual synchronization-with-Logs contract the codebase already
tracks for every widget (SystemProgressWidget's WIDGET_DEPENDENCY_MAP audit
trail, getWidgetTier, cascade-flush ordering all read this map). Astrology
was the one Tier-0 leaf explicitly commented "no upstream deps" as of the
2026-07-27 audit; it now has one, documented with the same audit-comment
convention used elsewhere in that map.

About.tsx — one new subsection under the existing Astrology Widget writeup,
"Personal Peak Hour," explaining the feature is behavioral (derived from the
user's own Log timestamps) and not astrological, matching the section's
existing "no horoscope predictions" framing.

SystemProgressWidget.tsx — one new SESSION_REPORTS entry (2026-09-03) in the
same array/format as prior entries, describing exactly what was built this
session. No new P-pattern number, archetype, or scheduled job was invented —
