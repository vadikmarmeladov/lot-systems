NOTES — WHAT CHANGED
--------------------------------------------------------------------------------
CalendarWidget.tsx
  - CalendarEntry gains an optional `time` (HH:MM) field alongside date/text/type.
  - New native <input type="time"> beside the existing text field in the entry
    form; entries persist `time` in calendar_entry log metadata (backward
    compatible — undated/untimed old entries render exactly as before).
  - Entries and the upcoming list now sort by date+time, not date alone.
  - New `nextTimedEntry` memo finds the nearest future timed entry; a 60s
    interval (armed only while one exists) refreshes a `now` state so the
    "NEXT: <time> · T-MINUS XH MM" readout stays live without a hidden always-on
    timer.
  - `formatCountdown()` renders T-MINUS in D/H or H/M or M granularity.

Logs.tsx (CAL: handler)
  - Now prints TIME alongside DATE when present, and a SCHEDULED/ELAPSED status
    line computed against wall-clock, in the same uppercase/tabular-nums/opacity-
    layer idiom already used by every other Log block (BIO, QOS, ASM, etc.) — no
    new visual language introduced.

CalendarAlertToast.tsx (new)
  - Polls the shared useLogs() cache every 30s (no extra network calls; the query
    is already fetched by System/Logs) for calendar_entry logs whose time falls
    within a 15-min lookahead / 2-min grace window of "now".
  - Fires one alert at a time: bracketed "// SCHEDULED EVENT — ARMED|NOW //"
    header with a `.blink`-animated marker (reusing the repo's existing soft-blink
    CSS, not a new animation), entry-type sector code (NOTE/TASK/CALL), time, and
    entry text. Auto-hides after 8s via the same fadeInUp/fadeOut keyframe pair
    EvolutionMilestoneToast already uses (defensively re-injected so this
    component also works if that one isn't mounted).
  - Fired alerts are id-keyed into localStorage (`calendar_alerts_fired`, capped
    at 200 ids) so a page refresh never re-fires a notification already shown.
  - Wired into System.tsx next to <CalendarWidget /> inside the existing
    "Calendar" WidgetErrorBoundary — no new boundary needed.

intentionEngine.ts
  - `recordCalendarSignal(entryType, date)` -> `recordCalendarSignal(entryType,
    date, time?)`; the QIE calendar_entry signal now carries `time` when set.
    Sole caller (CalendarWidget) updated; no other call sites exist.

Scope note: date-only entries (no time set) are unaffected end-to-end — no
countdown, no toast, exactly today's existing behavior. Time is additive, not
required.
