05a // CHANGE DETAIL
--------------------------------------------------------------------------------
FIX   /story (POST /api/story) filtered journal entries on event === 'log_entry'
      || 'journal' — event names that are never written anywhere in this
      codebase. Real journal entries write event: 'note' (Log model default).
      Self-care filter had the matching bug: 'memory_answer' / 'self_care_
      checkin' / 'energy_checkin' instead of the real 'answer' / 'self_care_
      complete' / 'self_care_completed'. Net effect since the route shipped:
      every /story generation ran with empty RECENT LOG ENTRIES and empty
      SELF-CARE DATA blocks — mood data only. Same failure shape as the
      standing Backend Whitelist Hygiene doctrine clause. Both filters
      corrected to the real event names.

WIRE  Two LogTrigger rules were detected by logTriggers.ts but had no dispatch
      branch in Logs.tsx — typing /sil or a heavy exclamation mark did nothing:
        /sil, /silence-check -> now reads the QIE's own 'signal-silence'
          pattern (confidence, suggested timing, reason) from
          recognizedPatterns, rendered as SIL-CHECK:. Distinct from /silent,
          which shows generic time-since-last-signal.
        ❗ / ‼️ -> now reads UserState.needsSupport (critical/moderate/low/
          none) and returns a non-clinical, self-care-toned response line,
          rendered as SUPPORT:. Consistent with the existing Trauma-Informed
          Protocol doctrine (observational, non-diagnostic, field-medic tone).
      /system help text and logTriggers.ts RULES/type updated to list both
      correctly (no invisible commands, no documented-but-dead commands).

ADD   /help added as a keyword alias for /system (system-help trigger) —
      discoverability parity with the command's own stated purpose.

ADD   Arcade hook — 3 new badges tied to Log-terminal command usage (BadgeType
      + BADGES in badges.ts, category 'pattern', consistent field shape with
      existing entries):
        terminal_initiate (common)   — first slash-command of any kind
        qi_analyst        (uncommon) — a /qi request sent
        story_weaver      (uncommon) — a /story request sent
      awardBadge() calls wired into the Logs.tsx dispatch effect at the
      relevant trigger branches. All 3 IDs added to the server's validBadges
      allowlist (POST /api/sync-badges, api.ts) so they persist cross-device —
      previously only 3 of ~560 client-defined badges (the day-streak
      milestones) were whitelisted there; this session's 3 additions are
      scoped to the new command-badges only, not a fix for the other ~560.

DOC   docs/technical/LOG-TERMINAL-COMMAND-SYSTEM.md (new) — full command
