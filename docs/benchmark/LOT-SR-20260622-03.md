**Type badges**
- `TASK / CALL / NOTE` shown as uppercase tracking-widest labels beside each entry
- Both in the open selected-date view and in the upcoming list

**Alert system — architecture**
```
checkAlerts() runs:
  1. On mount (after entries load)
  2. Every 60 seconds (setInterval)
  3. Cleared on unmount or entries change

Dedup key: lot_cal_alert_{alertType}_{targetDate}_{todayDate}
  — alertType: 'today' | 'tomorrow'
  — targetDate: YYYY-MM-DD of the event
  — todayDate: YYYY-MM-DD of today (key expires naturally next day)

Fires: batched calendar_alert log entry via createLog()
  — deferred via setTimeout(0) per ASYNC SIGNAL RECORDING doctrine
  — onSuccess invalidates ['/api/logs'] to surface in Log feed
```

**Alert metadata schema**
```typescript
{
  alertType: 'today' | 'tomorrow',
  date: 'YYYY-MM-DD',          // target event date
  count: number,               // events on that date
  entries: Array<{
    date: string,
    text: string,
    entryType: string,
  }>
}
```

**Log text (COCKPIT-RULE body)**
```
CAL-ALERT: TODAY | 2 EVENTS | TASK team standup · CALL client call
CAL-ALERT: TOMORROW | 1 EVENT | NOTE dentist appointment
```

**Upcoming list visual hierarchy**

**Signal recording fix**

  (was synchronous in onSuccess callback — now correctly deferred)

## 05 — ALERT DEDUPLICATION MECHANISM

```
Key format: lot_cal_alert_{alertType}_{targetDate}_{todayDate}

Example:
  lot_cal_alert_today_2026-06-22_2026-06-22    → fires once on 22 Jun for today's events
  lot_cal_alert_tomorrow_2026-06-23_2026-06-22 → fires once on 22 Jun for next day's events
  lot_cal_alert_today_2026-06-23_2026-06-23    → fires on 23 Jun when that day arrives

Old keys naturally unreachable the next day (todayDate portion changes).
No cleanup needed — localStorage remains bounded by active event count × 2.
```
