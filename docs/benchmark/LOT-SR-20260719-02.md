DETAIL:
  LogContext gains moonPhase / moonIllumination / westernZodiac
  (src/shared/types/index.ts, src/server/utils/logs.ts) — computed from
  #shared/utils/astrology (getMoonPhase, getWesternZodiac), pure and
  dependency-free, no new package, no migration (JSONB column already open-
  ended). getLogContext() is called on every Log create/update, so every
  Journal entry and every command invocation now carries sky (existing
  weatherDescription) + astrology alongside weather/time/location — this is
  the "click by click creates a context snapshot" requirement closing for the
  astrology axis specifically.

  Logs.tsx contextText overlay renders the moon emoji + zodiac sign
  alongside temperature/humidity/city on hover, so the added context is
  operator-visible, not just stored.

  /story gains an optional period argument: `/story`, `/story day`,
  `/story week`, `/story month`, `/story year`. Client parses the period from
  the typed command (logTriggers.ts already matched bare `/story` as a
  trigger — no change needed there since the regex is word-boundary, not
  exact-match), strips it from the saved log text, and passes it to
  useStoryGeneration. Server (/api/story) maps period -> {lookback window,
  query limit, per-category sample depth, target word count} via a
  PERIOD_CONFIG table (day: 1d/200/5/80-150w, week: 7d/300/10/120-200w,
  month: 30d/500/20/150-250w, year: 365d/800/30/180-300w), filters the Log
  query by createdAt >= now-N-days when a period is given (QUERY-BATCHING
  doctrine: no unbounded findAll), and rewrites the AI system prompt to name
  the period explicitly ("write a compressed story of their week/month/
  year..."). Response and the persisted `generated_story` log both record
  `period` so downstream rendering/analytics can distinguish an ad-hoc story
  from a scheduled-scale one. Usership gate on /story is unchanged (existing
  monetization boundary, out of scope for this session).

  /system help text updated to list `/story day|week|month|year` explicitly.

  docs/technical/WIDGETS.md: new "Arcade" section naming the existing
  Badge + Evolution + Narrative systems as the product's gamified layer, per
  S-2's explicit request to note this framing. No code changes — this is
  documentation of what already ships, marked PROVISIONAL pending the term's
  recurrence (LEXICON minting rule: 3+ session reports).
