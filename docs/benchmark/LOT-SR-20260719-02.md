05 // ROUTINES IMPLEMENTED (this session)
--------------------------------------------------------------------------------
R1 TIME-ON-ENTRY    CalendarEntry gained an optional `time` (HH:mm) field,
                    sourced from log.metadata.time. Add-entry form gained an
                    <input type="time"> alongside the existing text field;
                    both the "on this date" list and "upcoming" list now show
                    the time (tabular-nums, dim) ahead of the entry text.
                    Entries within a day now sort text asc then time asc.
R2 CAL [DUE] ALERT  New useEffect polls today's timed entries every 30s
                    (gated on !document.hidden, matching the codebase's
                    existing off-tab-throttle convention) plus a
                    visibilitychange listener to catch a due entry missed
                    while backgrounded. A 5-minute catch window absorbs
                    background-tab timer throttling. On first crossing of an
                    entry's due time: (a) shows a fixed-position military-
                    style toast — "CAL [DUE] HH:MM" header, uppercase
                    tracking-wide "type: text" body, 8s auto-dismiss,
                    fadeInUp/fadeOut keyframes scoped under a
                    cal-due-toast-style <style> tag — and (b) writes a
                    `calendar_alert` Log entry (text "[CAL ALERT] type: text
                    — DUE HH:MM", metadata {date,time,entryType,text}).
R3 ALERT DEDUP      Fired keys (`date T time : type : text`) are recorded in
                    a Set persisted to localStorage (calendar_notified_alerts,
                    capped 200 keys) so a page reload or widget remount never
                    re-fires the same due alert. Mirrors the seen-set pattern
                    EvolutionMilestoneToast.tsx already uses for milestone
                    dedup — no new architecture, same convention reapplied.
R4 LOG WIRING       `calendar_alert` added to the server's displayableEvents
                    allowlist (api.ts) so alerts surface in the Log stream,
                    not just as toasts. Logs.tsx gained a `calendar_alert`
                    render branch — "CAL [DUE]:" Block, uppercase entry type,
                    date+time line — and the existing `calendar_entry`
                    branch now also prints the time when present.
