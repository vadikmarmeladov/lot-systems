ASTROLOGY + SKY IN EVERY LOG SNAPSHOT (logs.ts, shared/types/index.ts)
  getLogContext() already captured weather (temperature/humidity/description,
  i.e. "sky"), country/city/timeZone, and a formatted local timestamp on every
  Log row — the environment-context snapshot S-2 described was already real,
  just missing the astrology dimension. src/shared/utils/astrology.ts already
  existed (Western zodiac + lunar phase math, pure date functions, no network
  calls) but was only wired into unrelated widgets (System.tsx, RecipeWidget).
  getLogContext() now also computes zodiacSign, moonPhase, and
  moonIllumination from the user's local date and attaches them to every log's
  `context` JSONB column — so every click that creates a log entry now carries
  a full environmental snapshot: weather, time, humidity, sky, location, and
  astrology, matching the S-2 directive line for line. LogContext's type
  gained the three new optional fields; the existing `[key: string]: any`
  index signature meant nothing downstream broke.

/STORY BUG FIX — THE OPERATOR'S OWN WORDS WERE NEVER READ (api.ts)
  The /story route's recentEntries filter checked
  `l.event === 'log_entry' || l.event === 'journal'`. Neither value is ever
  written by any code path in this repository — POST /logs defaults new
  entries to `event: 'note'` (api.ts, confirmed by grep across the whole
  server tree). The route's own header comment claims it "reads last 200 logs
  ... extracts recent entries" — it never did, silently, since the feature
  shipped 2026-06-22 (SR-20260622-01). Every /story response has been built
  from moods and self-care answers only, missing the actual journal text the
  operator writes. This is the same failure shape already named in
  LOT-DOCTRINE.md's Widget→Memory Compression Loop clause ("if the case is
  absent, the log entry ... becomes invisible to the AI ... silent erasure, no
  error") — confirmed here in a second, independent subsystem. Filter now
  matches `'note'` (kept `'log_entry'`/`'journal'` for forward compatibility
  with any future event-naming change).

/STORY PERIOD COMPRESSION — day / week / month / year (api.ts, Logs.tsx,
queries.ts, logTriggers.ts unchanged)
  This is the concrete implementation of the S-2 directive: "the machine ...
  creates a compressed story of your day/week/month/year." Previously /story
  always pulled the last 200 logs with no time boundary and asked for a fixed
  100-200 word narrative regardless of scope. Added a STORY_PERIODS table
  (day/week/month/year → lookback window, sample size, target word count,
  completion token budget) in the /story route. The client now parses an
  optional trailing word after /story (`/story week`, `/story month`,
  `/story year`; bare `/story` still defaults to `day`, preserving existing
  behavior for anyone already using it). The server filters Log rows to
  `createdAt >= now - period.days`, scales how many mood/self-care/journal
  samples feed the prompt, and scales the AI's target length and max
  completion tokens with the period so a year-story isn't squeezed into the
  same 200-word box as a day-story. The response and the persisted
  generated_story log now both record which period was requested.

/SYSTEM HELP UPDATED (Logs.tsx)
  Added the new `/story [period]` syntax to the command directory (previously
  documented as bare `/story`) and widened the column so multi-word syntax
  reads cleanly. Added a live ARCADE line reading earned/total badge count
  ("every entry scores") — the RPG/Arcade badge system already exists at
  significant scale (docs/badges/, 424+ badges across 26 codex revisions,
  src/client/utils/badges.ts) and was already read by /scan; /system now
  surfaces it too so the operator sees the gamified layer from the same
  screen that documents the Log commands, per the S-2 note to keep the
  Arcade evolution visible alongside the self-care core.
