## SYSTEM DELIVERED

**LOT® Mail** — internal messaging wired into three modules: Log (compose),
Sync (inbox), Cohort (connection action).

1. **`/email` command in Log** — trigger `/email to [Name] [body]`, also
   `/mail`, emoji `✉️ ✉ 📧`. Folded into the existing `logTriggers.ts`
   `RULES` table (the established slash-command convention) rather than
   left as an ad hoc regex. Opens an inline compose panel; blank body if
   omitted. `/system` help screen updated with the new command.
2. **Sync — Chat | Mail tabs** — new tab strip; unread badge; switching to
   Mail clears the counter. Preserved this branch's newer `sseMessages` +
   `fetchedMessages` merge (superseding the June-12 branch's older
   `messages` state, which predated the "filter empty chat messages"
   hardening shipped since).
3. **EmailInbox** — newest-first, read/unread opacity, click to expand +
   mark read, relative timestamps. Unmodified from the original build.
4. **Real-time delivery** — `POST /api/mail` → `LotMail.create` →
   `sync.emit('lot_mail', ...)` → SSE handler filters to `toUserId` only
   (verified: `api.ts:388-393`, same pattern as the existing 1:1
   `direct_message` event).
5. **Cohort → Mail** — `ChatCatalystWidget` gains a `✉ Mail` button beside
   the existing cohort-connect action; pre-fills `/email to [Name]` in Log
   and records a `connection_accepted` signal (`type: 'email'`) for QIE.

**Recipient resolution:** first/last-name case-insensitive lookup across all
users (`Op.iLike`), 404 with hint `No user named "X" in LOT Community` if
absent, blocks self-send. Not cohort-restricted — any LOT Community member
can be mailed by name, matching the "simplest" mandate; the Cohort widget is
one entry point, not a gate.

**Bug fixed in transit:** the carried-over `ChatCatalystWidget.handleEmail`
called `stores.goTo('log')` — no such route exists (`Routes` only has
`logs`). Silent no-op at runtime, caught by `tsc --noEmit` during this
session's verification, not by the original build (esbuild strips types).
Fixed to `stores.goTo('logs')` and confirmed against `app.tsx`'s route table.
