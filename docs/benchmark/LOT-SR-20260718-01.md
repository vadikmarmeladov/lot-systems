WHAT WAS BUILT (CalendarWidget.tsx)

  Time-of-day scheduling
    Entry form gained a `time` input (type="time") alongside the existing
    text field. Stored in calendar_entry log metadata as `time: "HH:mm"`.
    Entries within the same date now sort by time; both the day-detail list
    and the upcoming-entries list render it inline (`14:00 Write report`).

  Planned duration (task entries only)
    A `min` number input appears when entryType === 'task'. Stored as
    `plannedMinutes`. Rendered via a shared formatDuration() helper
    (`45m`, `1h30m`) in both list views.

  Live time tracking (Start / Stop)
    Task entries with a logId get a Start control. Starting writes
    { entryKey: logId, startedAt: Date.now() } to React state AND
    localStorage (key lot_calendar_tracker) so an in-progress timer survives
    a reload. A 1s interval ticks a live "elapsed" readout while tracking.
    Stopping computes actualMinutes = round((now - startedAt) / 60000),
    clears the tracker, and fires the Log write below. Only one tracker can
    be active at a time (Start is disabled while another task is tracking) —
    deliberately simple, matches the widget's single-focus minimalist style.

  calendar_time_logged — new Log event
    On Stop, createLog() posts event: 'calendar_time_logged' with
    { date, text, entryType, actualMinutes, plannedMinutes?, varianceMinutes? }
    and a military-formatted text field:
    "[TIME-LOG] task: Write report — 42m tracked (planned 45m, -3m)"
    recordCalendarSignal(entry.type, entry.date) is called on both
    creation AND completion — reuses the existing QIE signal helper from
    SR v11 (2026-04-29) rather than minting a new signal name, so Pattern 26
    (calendar-gap) and the Temporal Planner module keep working unchanged.

LOG HANDLERS (Logs.tsx — COCKPIT-RULE)
  CAL: (enriched)     entryType | SCHED: {date} {time} | PLAN: {duration}
  TIME-LOG: (new)     entryType | {date} | TRACKED: {duration} | PLANNED:
                       {duration} | VARIANCE: {+/-Nm}
  Both follow the existing label/value tabular-nums row pattern used by
  BPEAK:, QOS-COHR:, ARCH-SHIFT: — no new visual language introduced.
  Total handlers: 106+ (unchanged count from SR-20260703-01 baseline;
  TIME-LOG: is additive to CAL:'s existing slot, not a new tracked total

  a SELF-ASSEMBLY-class concern, untouched here).
