QIE/MEMORY/STORY ARCHITECTURE: two structurally separate pipelines that only
partially overlap. QIE lives client-side in intentionEngine.ts — any widget
calling recordSignal() appends to a localStorage signal array that drives
analyzeIntentions()/getUserState()/selfAssembly/chakraErgonomics, all
zero-server-call consumers of that local array. Roughly every 10th signal,
syncToServer() POSTs to /api/quantum-intent/sync, which bulk-inserts
event:'quantum_intent_signal' Log rows — but GET /api/logs explicitly
excludes that event type from the user-visible feed, and
generateMemoryStory()/generateUserSummary() (story-generator.ts) filter
strictly to event==='answer'. So QIE writes never reach the user's own log or
the narrative Story.

WIDGET-TIER SPLIT (38 total):

                  synthesis), CalendarWidget (calendar_entry), PlannerWidget
                  (plan_set), RecipeWidget (note), ContextualPromptsWidget
                  (raw axios.post /api/logs, note).
  QIE-ONLY (19) — recordSignal reaches the server as opaque analytics rows,
                  invisible to the user's own log and to Story: Chakra-

                  read-only QIE-state consumers (ArchitectWidget, Integrity-

  ORPHANED (14) — no logging path of any kind: AIFeedbackWidget, Angel-

CONTEXT SYNC (weather/time/users-online): centralized and consistent.

05b // FIXES APPLIED (smallest-correct-fix, in scope of this scan)
--------------------------------------------------------------------------------
F1 RENDER ISOLATION   Logs.tsx:2338 called recordBadgeSignal() unconditionally
                      inside the pastLogIds.map() render body for every
                      badge_unlock log on every render — an intentionEngine
                      atom write during render, the exact bug class the
                      2026-07-19 System.tsx fix closed. Moved to a useEffect
                      keyed on [pastLogIds, logById], guarded by a
                      Set<logId> ref so each badge signals exactly once.
F2 QUERY BATCHING     /api/chat-catalysts User.findAll had no limit/order
                      (api.ts:3758), unlike its near-identical sibling
                      /api/cohorts (limit 200, order lastSeenAt DESC,
                      written 20 lines away). Applied the same cap.
F3 CLICK GUARD        MemoryWidget.tsx onAnswer had no re-entry guard —
                      answer buttons stay clickable through the full
                      1.5s+ dismiss animation, so a second click before
                      the network round-trip resolves double-fires
                      createMemory for the same question with a different
                      option. Added `if (clickedButtonIndex !== null)
                      return` and added clickedButtonIndex to the
                      useCallback deps.
F4 BOUNDARY COVERAGE  TimeWidget and QuantumRandomWidget were the only two
                      widgets in System.tsx rendered bare (not inside a
                      WidgetErrorBoundary) — a crash in either would blank
                      the entire app via AppErrorBoundary rather than just
                      its slot. Wrapped both render sites (System.tsx:444,
                      616-617) in named WidgetErrorBoundary.

NOT FIXED (recorded, not acted — needs S-2 scope decision):
  - IntentionsWidget: intention text is never persisted server-side, only
    the QIE signal. May be deliberate (privacy); flagged not changed.
  - QuantumSignWidget: action buttons write only to localStorage despite
    the "Quantum" name — no recordSignal, no server write.
  - SystemProgressWidget: runs a second, parallel feedback-logging pipeline
    (/api/system/submit-feedback) disjoint from /api/logs and QIE.
  - Coarse WidgetErrorBoundary grouping (up to 6 widgets per boundary, e.g.
    "Bioethics") — functionally safe, but a crash in one blanks all six.
  - No unified platform-wide widget-usage log (see finding above).
