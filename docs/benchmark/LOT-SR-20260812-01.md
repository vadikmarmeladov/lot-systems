DESIGN — LOT MAIL v1
--------------------------------------------------------------------------------
Zero new Sequelize model, zero new migration, zero new server route. LOT Mail
is a formatting convention on top of the existing chat_messages pipeline:

  /email to <Name>   Log-text trigger, matched by parseEmailCommand()
                      (src/client/utils/logTriggers.ts) via
                      /\/email\s+to\s+([A-Za-z][\w'-]*)/i. Recipient = the
                      captured name; body = the rest of the log entry, same
                      "whole entry is the payload" convention as /prayer,
                      /story.
  Send              On completion, Logs.tsx posts an envelope message —
                      "✉️ TO: <Name> — <body>" — through the same
                      useCreateChatMessage() mutation Sync itself uses. Same
                      /api/chat-messages route, same Usership/Onyx/Legacy/
                      R&D/Admin gate, same 'chat_message' SSE broadcast.
  Sync appearance   Sync.tsx pattern-matches the envelope prefix and renders
                      it as a "✉️ MAIL → <Name>" tag + body instead of raw
                      text — the only Sync-side change.
  Cohort Dating     CohortConnectWidget's "Send message" action (previously
                      just stores.goTo('sync')) now seeds the primary Log via
                      a new stores.pendingLogSeed atom with "<FirstName>, "
                      and routes to /log — one click from a cohort match to
                      a mid-composed LOT Mail. The seed is a greeting only,
                      never the "/email to <Name>" phrase itself, by design.

KEY DECISION — the fire-once bug avoided: the existing trigger system
(detectNewTriggers) fires the instant a bare keyword like "/qi" or "/email"
first appears, before any trailing argument is typed — confirmed this is
already true of shipped /qi. Gating "/email to <Name>" on that same
freshness check would have silently swallowed most real sends (argument not
present yet at the one moment the trigger counts as "fresh"). LOT Mail
checks parseEmailCommand() unconditionally on every keystroke instead, with
its own ref-based one-shot guard (armed off when the phrase is edited away)
— correct regardless of typing order, and does not touch /qi's existing
behavior.

Client-side gate only mirrors Sync's own audience — Usership, Onyx, Legacy,
R&D, Admin. A user without access gets a MAIL FAILED banner (403 from the
same server check Sync already enforces), not a false "Sent" confirmation.
