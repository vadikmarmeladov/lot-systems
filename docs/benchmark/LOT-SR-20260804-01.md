ENGINEERING DETAIL —
  CalendarWidget.tsx:
    - daysUntil(date) / formatCountdown(delta): local-day-granular countdown,
      dayjs().startOf('day').diff(...,'day') — avoids the classic off-by-one
      from comparing raw timestamps across a DST/midnight boundary.
    - upcoming-entries row now renders a T-Nd / TODAY / OVERDUE +Nd badge
      per entry (tabular-nums, uppercase tracking-widest — matches existing
      Log tactical typography, no new colors, minimalist UI preserved).
    - New effect scans all entries once per logs/entries change; for any
      entry whose countdown is exactly +1 (T-1 heads-up), 0 (due today), or
      -1 (first day overdue), fires a single 'calendar_reminder' Log event
      via the existing useCreateLog mutation (same pattern already used for
      calendar_entry creation).
    - Dedup: a memoized Set of already-fired `date|text|status` keys is
      read back from existing calendar_reminder logs, plus a same-session
      in-flight ref, so a reminder can never double-fire — including across
      remounts, since the server-side log itself is the durable dedup record.
    - Deliberately narrow trigger window (exact day only, not "any day at or
      past threshold") — see D-002: prevents a first-deploy backfill flood
      for entries that were already overdue before this code shipped.
  Logs.tsx:
    - calendar_entry (CAL:) block now also renders the entry text (previously
      showed only entryType + date — the note/task/call content itself was
      silently dropped from the Log view).
    - New calendar_reminder (CAL-ALERT:) block: status headline (DUE TODAY /
      OVERDUE / T-MINUS 1D), entry type, entry text, date, and a tabular-nums
      D-DAY / T-Nd / OVERDUE +Nd line — styled to match the existing tactical
      Log vocabulary (uppercase tracking-widest headers, opacity-tiered
      hierarchy) rather than a consumer-app toast.
