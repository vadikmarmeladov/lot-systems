03 // ARCHITECTURE
--------------------------------------------------------------------------------

DESIGN PRINCIPLES:
  · Simplest possible — no new routes, no new pages, all inline
  · LOT® style — military terminal aesthetic, block labels, opacity layers
  · SSE delivery — real-time, consistent with existing DM and chat_message patterns
  · Trigger system — /email command follows the same pattern as /qi, /prayer, /assembly
  · Privacy-first — SSE events only reach sender + receiver (server-side filter)

STACK LAYERS IMPLEMENTED:

  DATABASE
    Table:   lot_mail
    Columns: id (UUID), senderId, receiverId, message (TEXT), readAt (nullable),
             createdAt, updatedAt
    Indexes: (receiverId, createdAt), (senderId, createdAt)
    Cascade: ON DELETE CASCADE from users

  SERVER MODEL
    File:    src/server/models/lot-mail.ts
    Class:   LotMail extends Model<LotMailModel, LotMailCreateFields>
    Pattern: Identical to DirectMessage model

  SHARED TYPES
    Added to src/shared/types/index.ts:
    · LotMail — full model type
    · LotMailRecord — with senderName, receiverName, isMine
    · LotMailSyncPayload — SSE event payload
    · SyncEvents.lot_mail — typed SSE event channel

  SHARED CONSTANTS
    Added:   MAX_LOT_MAIL_LENGTH = 1000

  SERVER ROUTES (src/server/routes/api.ts)
    GET  /api/lot-mail/inbox
         Returns: { items: LotMailInboxItem[], unread: number }
         Auth: required — returns receiver's inbox only

    POST /api/lot-mail/send
         Body: { recipientName: string, message: string }
         Resolves: firstName match (case-insensitive) via Op.iLike
         Emits: lot_mail SSE event to sender + receiver
         Logs: lot_mail_sent (sender), lot_mail_received (receiver)

    PUT  /api/lot-mail/:id/read
         Marks mail as read (sets readAt timestamp)

    SSE HANDLER (case 'lot_mail'):
         Writes to wire only if data.receiverId === req.user.id
                            OR data.senderId === req.user.id
         — private delivery, not broadcast

  CLIENT QUERIES (src/client/queries.ts)
    · LotMailInboxItem type (exported)
    · useLotMailInbox — GET inbox, staleTime 30s
    · useSendLotMail — POST send
    · useMarkLotMailRead — PUT mark read

  LOG TRIGGERS (src/client/utils/logTriggers.ts)
    Trigger:  'email-compose'
    Emojis:   ✉  ✉️
    Keywords: email  mail
    Pattern:  /email to <name> — fires when typed in Log editor

  LOG COMPONENT (src/client/components/Logs.tsx)
    Trigger handler in NoteEditor:
      Parses: /(?:email|mail)\s+to\s+([^\n,]+)/i
      Opens:  emailCompose panel (inline block below editor)
      Shows:  MAIL [COMPOSE]: TO: <name> + message input + Send/Cancel

    Compose UI state:
      emailCompose    — { recipientName } or null
      emailBody       — message text
      emailSent       — { receiverName, message } after success
      emailError      — error string on failure
      emailSending    — loading flag

    Log event blocks:
      lot_mail_sent     → MAIL [OUT]: TO: <name> / message preview
      lot_mail_received → MAIL [IN]: FROM: <name> / message preview

  SYNC COMPONENT (src/client/components/Sync.tsx)
    Added:  mailNotifications state (SyncNotification[])
    Listens: sync.listen('lot_mail', ...) — appends new notifications
    Renders: MAIL notification band above chat messages
             Shows: MAIL · <sender> → <receiver> · <message preview 80 chars>

04 // USER FLOW
--------------------------------------------------------------------------------

COMPOSE FLOW:
  1. User opens /log (Log view)
  2. Types in primary log editor: /email to Hitomi
  3. Trigger 'email-compose' fires on next keystroke boundary
  4. Inline MAIL [COMPOSE]: block appears below editor
     · Shows "TO: Hitomi"
     · ResizibleGhostInput for message body
     · Send / Cancel buttons
  5. User types message, clicks Send
  6. POST /api/lot-mail/send { recipientName: 'Hitomi', message: '...' }
  7. Server resolves firstName iLike 'Hitomi'
  8. LotMail record created in DB
  9. SSE event lot_mail emitted
  10. Log entries created: lot_mail_sent (sender) + lot_mail_received (receiver)
  11. Compose panel replaced by MAIL [SENT]: confirmation block

RECEIVE FLOW:
  1. Recipient is on any page (SSE connected)
  2. lot_mail event arrives via SSE
  3. If on /sync — notification appears at top of Sync feed:
     MAIL  <sender> → <recipient>  ·  <preview>
  4. lot_mail_received entry visible in recipient's /log feed

SYNC INTEGRATION:
  · Mail notifications appear as a band above chat messages in Sync
  · Styled with MAIL label + sender → receiver · preview
  · Opacity 60% to match LOT® terminal aesthetic
  · Not clickable in V1 (expandable in V2)

COMMUNITY / COHORT INTEGRATION:
  · Recipient lookup uses the User table (all LOT operators)
  · firstName resolution = discoverable across the community
  · Future: can be filtered to cohort members only
