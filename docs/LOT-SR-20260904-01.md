## 2. Errors & Warnings — Component Audit

The following issues were identified in the health-check subsystem and adjacent documentation.
All have been remediated in this session on branch `claude/inspiring-volta-e2itv2`.

### 2a. Story AI check was missing from runtime (HIGH)

**File:** `src/server/routes/public-api.ts` · `performHealthChecks()`

The original design specifies **9 health checks**. The runtime was only running **8** because
the Claude API key verification (Story AI) was merged inside `checkMemory()`. This meant a
misconfigured `ANTHROPIC_API_KEY` would surface as a "Memory Engine" failure rather than
isolating Story AI as the culprit.

**Fix:** Extracted `checkStoryAI()` as a standalone check and added it to `performHealthChecks()`.
The function verifies `ANTHROPIC_API_KEY` / `config.anthropic.apiKey` and returns
`name: 'Story AI'` — consistent, isolated, easy to triage.

### 2b. Inconsistent check names (MEDIUM)

**File:** `src/server/routes/public-api.ts`

Three checks returned names that didn't match the documented component identifiers:

| Function | Old name | Corrected name |
|---|---|---|
| `checkDatabase()` | `'Database stack'` | `'Database stack check'` |
| `checkWeatherAPI()` | `'Engine stack'` | `'Engine stack check'` |
| `checkSystems()` | `'Systems'` | `'Systems check'` |

**Fix:** All three name strings updated to match documented spec and status-page display labels.

### 2c. Outdated Claude model in `/api/public/test-anthropic-key` (MEDIUM)

**File:** `src/server/routes/public-api.ts` · line ~705

The diagnostic test endpoint was hard-coded to `claude-3-5-sonnet-20241022`, a retired model
that costs more and performs the same "Respond with just OK" ping as a cheaper model.

**Fix:** Updated to `claude-haiku-4-5-20251001` (Haiku 4.5) — the lightest current-generation
Claude model, appropriate for a connectivity test.

### 2d. Stale OpenAI reference in deployment docs (LOW)

**File:** `docs/deployment/STATUS-PAGE.md` — troubleshooting table

The troubleshooting table read:
> Story AI stack check failed | Missing API key | Set OPENAI_API_KEY

This was never updated when Story AI was migrated from OpenAI to Claude (Anthropic).

**Fix:** Updated to `Set ANTHROPIC_API_KEY`. Also corrected the component table (9 rows with
accurate descriptions of what each check actually verifies).

## 3. Performance Anomalies

No runtime performance data is accessible from this environment (no live telemetry stream).
Observations based on code review:

- **Status cache TTL:** 2 minutes — appropriate for DigitalOcean cost-efficiency.
- **Health checks run in parallel** via `Promise.all()` — correct pattern; one slow check
  (e.g. Weather API) does not block others.
- **Analytics cache TTL:** 1 minute — reasonable for a public analytics endpoint.
- **Weather API** is hit on every Engine stack check cache miss. If the weather service is
  slow or unavailable, the Engine stack check will report an error even when the app itself
  is healthy. Consider separating weather from the bundle-existence check for more granular
  fault isolation in a future pass.
