## 5. COMPONENT QUALITY PASS — StatusPage.tsx

### Problem
StatusPage was using faded accent (`text-acc/60`) for error states — visually indistinct from
"dimmed/secondary" text. No semantic color separation between OK, error, and unknown. No
accessibility live region. Loading copy was generic ("Loading..."). Status labels read "Ok" —
not consistent with the LOT engineering voice.

### Changes applied

| Area | Before | After |
|------|--------|-------|
| Error status color | `text-acc/60` (faded) | `text-red` (#EE5959) |
| OK status color | `text-acc` | `text-green` (#5CB85C) |
| Unknown status color | — | `text-acc/60` |
| Overall status banner | plain text | `text-green` / `text-yellow-dark` / `text-red` |
| Error messages (check.message) | `text-acc/60` | `text-red` |
| Fetch error display | `text-acc/80` | `text-red` |
| Slow check indicator | none | `text-yellow-dark` when duration > 500ms |
| Memory prompt available | `text-acc` / `text-acc/60` | `text-green` / `text-acc/60` |
| Status labels | "Ok" | "Operational" |
| Loading copy | "Loading..." | "Checking systems..." |
| Footer copy | "Status checks cached for 2 minutes" | "Auto-refreshes every 2 minutes" |
| Cache age | shown inline with last-updated | moved to footer for clarity |
| Accessibility | none | `aria-live="polite"` `aria-atomic="true"` on live region |

### Design rationale
LOT design system defines:
- `text-green` → #5CB85C (assembly operational / success states)
- `text-red` → #EE5959 (error / alert states)
- `text-yellow-dark` → #f0e46e-adjacent (warning band)

These are the same semantics used in `Tag.tsx` (fill red for suspended), `SystemProgressWidget.tsx`
(text-green for assembled state). StatusPage was the only public surface not using semantic status
colors — now corrected.
