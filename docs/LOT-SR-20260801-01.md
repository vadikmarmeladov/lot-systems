WHAT THIS SESSION ADDED/FIXED:
  1. /story <day|week|month|year> — the command previously only compressed
     "recent" data with no real time window. Server route now filters logs
     by an actual date range per grain (1/7/30/365 days), scales entry caps
     and target story length per grain, and stores `timeframe` +
     `entriesCompressed` in the log metadata. /system help text updated.
  2. BUG FIX (correctness): /story's log filter checked for
     `event === 'log_entry' || event === 'journal'` — but POST/PUT /api/logs
     write real typed Journal entries under `event: 'note'` (confirmed via
     the PUT /logs/:id guard `if (log.event !== 'note') return log`). The
     filter never matched a single real journal entry — /story was silently
     compressing mood/self-care data only, never the user's own words. Fixed
     in both the /story route and the new journal-spike detector.
  3. src/server/utils/journal-spike.ts — passive follow-up detector. Pure,
     no AI call: flags a word-count spike (>=2.5x rolling average, either
     direction) or a silence-then-burst (>=3 day gap then a new entry).
     Deliberately shape-only, not sentiment/NLP — LOT does not read journal
     content to score it. Wired into GET /api/contextual-prompts (new
     PatternInsight type 'journal-spike') and into
     src/server/utils/contextual-prompts.ts's prompt generator (3 new
     compassionate, non-prescriptive prompt variants: length-up,
     length-down, welcome-back).
  4. Click-to-snapshot: POST /api/context-snapshot (new route) creates a
     Log with event `context_snapshot`, empty text, and a full
     getLogContext() environment bundle — no photo, no sound, the reading
     IS the record. Wired to the astrology/weather line in System.tsx
     (60s client-side cooldown to prevent click-spam) via new
     useContextSnapshot() query hook. New Logs.tsx render case ("MOMENT:")
     displays these distinctly from the automated daily `system_snapshot`
     job output. Added 'context_snapshot' to the /api/logs displayableEvents
     whitelist so it actually surfaces in the feed.
  5. Arcade (gamified evolution layer) — SCAFFOLD ONLY per doctrine's
     honesty rule. src/client/components/ArcadeWidget.tsx reads existing
     $evolutionState + badges.ts (zero new scoring logic) and renders a
     cabinet/high-scores view. NOT wired into System.tsx's live widget
     stack — that's a placement + framing decision needing design
     sign-off, documented as the explicit next step in
     docs/technical/ARCADE-EVOLUTION-LAYER.md, marked PROVISIONAL.
  6. INFRA FIX: .gitignore line 50 was a bare `server/` pattern — unanchored
     gitignore patterns match any directory of that name at any depth, so it
     was silently blackholing every new file under src/server/** (confirmed:
     src/server/utils/journal-spike.ts did not appear in `git status` until
     fixed). No top-level server/ build dir has existed since the
     dist/server/ layout landed. Anchored to `/server/` — dist/ (line 2)
     already covers real compiled output. This was a live landmine for any
     future new file under src/server/utils, src/server/routes, etc.
