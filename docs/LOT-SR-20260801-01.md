05 // WHAT WAS BUILT
--------------------------------------------------------------------------------
Survey (docs/benchmark + docs/assembly/LOT-LEDGER.md + prior SRs) found the
Calendar widget's only history was the gamified date-easter-egg badge system
and a QIE signal hook (recordCalendarSignal) — the actual scheduling feature
had never been extended past its original note/task/call log-backed form:
no edit, no delete, no time-of-day, no time tracking, no reminders. Closed
all four, plus one ownership gap found while touching the shared PUT route:

R1 EDIT / DELETE     PUT /api/logs/:id extended: calendar_entry logs now
                     accept metadata merges (previously hard-gated to
                     event==='note' only, so calendar edits were silent
                     no-ops). Delete is a soft metadata.deleted flag, not a
                     DB row delete — consistent with this codebase's
                     append-only Log model; parseCalendarEntries() filters
                     deleted entries out of every consumer.
R2 OWNERSHIP GATE    Same route: findByPk(id) had no req.user.id check at
                     all — any authenticated user could edit/delete any
                     other user's log by guessing/enumerating its UUID.
                     Added `log.userId !== req.user.id -> notFound()`
                     (not forbidden — avoids confirming the ID exists).
                     Applies to the note-editing path too, not just the new
                     calendar path. PROVISIONAL candidate, see 06.
R3 TIME-OF-DAY       Entries carry an optional metadata.time (HH:mm). Date-
                     only entries remain valid (all-day); notifications and
                     overdue math both branch on its presence.
R4 TIME TRACKING     Start/Stop per task/call entry. Start writes
                     metadata.trackingStartedAt (ISO); Stop computes elapsed
                     minutes, folds into metadata.totalTrackedMinutes, clears
                     trackingStartedAt, and — the "logs into Log" half of the
                     directive — writes a new calendar_time_logged event
                     with the delta and running total. Live elapsed display
                     ticks client-side (1s interval, mounted only while an
                     entry is actively tracking; unmounts otherwise).
R5 NOTIFICATIONS     New CalendarNotifications.tsx: terminal-grid-style toast
                     — uppercase bracket tag "[SCHEDULE // DUE]" /
                     "[SCHEDULE // OVERDUE]" over the entry line, monochrome
                     border-acc/20 on --base-color (zero new colors/icons —
                     matches EvolutionMilestoneToast, the one prior toast
                     precedent). Fires once per entry per tier per day
                     (localStorage dedup keyed entryId:tier:date) — reload-
                     safe, no repeat spam. 30s scan, gated on
                     !document.hidden && isRouteActive('system') — same
                     visibility guard as every existing polling widget.
R6 SHARED PARSER     New src/client/utils/calendar.ts factors entry
                     parsing/status logic (parseCalendarEntries, isOverdue,
                     isDueSoon, formatTrackedMinutes, formatElapsed) out of
                     the widget so CalendarWidget and CalendarNotifications
                     can't drift on what counts as due/overdue.
