WHAT CHANGED, IN DETAIL —

POST /story (src/server/routes/api.ts):
  - Body now accepts optional `scope: 'day' | 'week' | 'month' | 'year'`.
    Typing `/story week` (etc.) in the Log now filters the log query to
    that window (`createdAt >= now - N days`) instead of an unbounded
    "last 200 rows" tail, and raises the sample size pulled into the
    prompt (10 / 15 / 20 items for day-or-bare / week / month-or-year) so a
    year genuinely compresses more source material than a day.
  - Fixed the three broken event-name filters (see block 04, fix #2).
  - System prompt now explicitly names the requested period and instructs
    the model to "synthesize the ARC across the whole period" rather than
    describe only the latest entry, when a scope is present.
  - Response now returns `scope` alongside `story`/`logId`; the generated
    log's metadata records `scope` for future querying.

useStoryGeneration (src/client/queries.ts):
  - Added `scope?: 'day' | 'week' | 'month' | 'year'` to both the request
    body type and the response type.

story-mode trigger handling (src/client/components/Logs.tsx):
  - Parses an optional `day|week|month|year` argument out of the log text
    after `/story` and forwards it as `scope`.
  - Added `storyScope` state; the rendered story block's label now reads
    "📖 WEEK" / "📖 MONTH" / etc. when a scope was used, "📖" otherwise.

/system help screen (src/client/components/Logs.tsx):
  - Documents the new `/story [day|week|month|year]` usage alongside the
    existing bare `/story`.

logTriggers.ts:
  - Updated the `story-mode` LogTrigger doc-comment to reflect the scope
    argument. Trigger DETECTION itself needed no change — the existing
    regex `(^|\s)\/story(\s|$|[^a-z0-9_])` already matches `/story week`
    since it only anchors on what follows `/story` being whitespace,
    end-of-string, or a non-word character.
