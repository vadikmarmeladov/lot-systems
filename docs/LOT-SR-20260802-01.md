## 06 // WHAT WAS BUILT

**Data model.** `EmailMessage` (table `email_messages`): `senderId`,
`recipientId`, `recipientName` (resolved display name at send time),
`body`, `read`, timestamps. Indexed like `DirectMessage` on
`(recipientId, createdAt)` and `(senderId, recipientId, createdAt)`.

**Compose (Log).** `/email to <Name> <message>` is a new `LogTrigger`
(`email-compose`) detected by the existing pure trigger-scanner
(`logTriggers.ts`), dispatched in `Logs.tsx`'s existing trigger loop
alongside `/qi`, `/prayer`, `/story`, etc. If no message follows the name,
the rest of the log entry (minus the command) is used as the body. Result
renders in an `EMAIL:` block, matching the visual language of every other
slash-command result panel already in Logs.

**Recipient resolution (LOT Community / Cohort Dating).**
`resolveEmailRecipient()` in `api.ts` matches first name (case-insensitive
prefix) against LOT Community members. If exactly one match, done. If
several people share a first name, it disambiguates through the same
`analyzeUserPatterns` + `findCohortMatches` pipeline that powers
`GET /api/cohorts` (Cohort-Connect) — the highest-similarity cohort match
among the namesakes wins, falling back to the most recently active
namesake if the sender doesn't have enough log history yet (`< 10` entries)
for cohort analysis. This is the literal integration with Cohort Dating
through LOT Community: the email doesn't just fan out to a directory match,
it prefers the person the sender's behavioral cohort graph says they're
actually aligned with.

**Delivery (Sync / LOT Chat).** `POST /api/email-messages` creates the row
and `sync.emit('email_message', ...)`. The existing `GET /api/sync` SSE
switch (`api.ts`, the handler already serving `chat_message`,
`chat_message_like`, `settings_updated`) gained a `case 'email_message'`
that forwards only to the sender and recipient — mirroring how
`chat_message_like` is already scoped. `Sync.tsx` (the component that *is*
LOT Chat) merges SSE-delivered email with `GET /api/email-messages` the
same way it already merges live chat messages, and renders a compact
"LOT Email" panel above the chat composer.

**Known gap inherited, not introduced.** `sync.emit('direct_message', ...)`
(`api.ts`, pre-existing direct-message feature) has **no** matching
`case 'direct_message'` in the SSE switch, so 1:1 direct messages are
silently never pushed live despite `DirectMessageThread.tsx` listening for
them. This predates this session and was left alone — LOT Email's own
`case 'email_message'` was added correctly and doesn't share this bug, but
a future ENGINEERING session should fix `direct_message` too.

**Access note.** The Sync tab (and therefore the LOT Email panel inside it)
is gated to Admin / R&D / Usership / Onyx / Legacy tags
(`CHAT_ALLOWED_TAGS` in `Sync.tsx`, pre-existing gate, unchanged). A user
outside those tags can still send `/email` from Log (the send-side API
isn't gated) but won't see their own Sync-side inbox view until they have
one of those tags. This is an existing constraint of what "Sync" is in
this codebase today, not a new limitation introduced by Email — noted
honestly rather than silently worked around.
