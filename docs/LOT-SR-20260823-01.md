### What changed this session, concretely (on top of the cherry-picked base)

**`CalendarWidget.tsx`** — live clock + T-MINUS countdown:
- Reused the existing `<Clock format="HH:mm:ss" interval={1000} />` UI
  primitive (already used elsewhere in the app — no new component) to show
  a running terminal clock next to the month header whenever the calendar
  panel is open.
- Added `nextDueToday` — the earliest still-armed (`time >= now`, not yet in
  `alertedKeys`) entry scheduled for today — and a `T-MINUS HH:MM:SS ::
  <type> — <text>` readout above the month grid, ticking down live via a
  `nowTick` state.
- The per-second ticking interval is gated on `isCalendarOpen &&
  nextDueToday` — it does not run at all while the panel is collapsed or
  nothing is armed, so the widget carries zero added per-second render cost
  on `System.tsx` in the common case (collapsed, nothing due). This follows
  the same discipline as prior sessions' widget-lag fixes (staleTime,
  polling intervals) recorded in `docs/assembly/LOT-DOCTRINE.md`'s sibling
  reports.

**`CalendarWidget.tsx` + `Logs.tsx`** — the "stylish military-grade" pass on
the alert itself:
- In-widget banner: bracket motif (`[ ALERT :: <TYPE> DUE ]`), a blinking
  status dot reusing the existing `.blink` CSS class (`soft-blink` keyframe,
  already defined in `index.css` for other widgets — no new animation
  added), monospace/uppercase/tracking-widest typography, and a `FIRED
  HH:mm:ss` timestamp now actually rendered (previously computed and stored
  in `metadata.firedAt` but never displayed in the banner).
- `Logs.tsx`'s `ALERT:` block: the `FIRED` field was previously a static
  label with no value next to it — fixed to render
  `dayjs(metadata.firedAt).format('HH:mm:ss')`, and the type label wrapped
  in the same `[ ... ]` bracket convention as the in-widget banner, so the
  Log record and the live notification read as the same visual language.
- Deliberately still did not introduce a new toast/overlay system or the
  browser `Notification` API — same reasoning as yesterday's report: this
  codebase's established "military-grade" idiom is the terse
  `Block label="XXX:"` field-manual convention, and this session sharpened
  that idiom rather than replacing it with a different one.

**No changes to `intentionEngine.ts`** this session — `recordCalendarAlertSignal`
(cherry-picked) already covers today's additions; no new signal type was
needed for a purely presentational pass.
