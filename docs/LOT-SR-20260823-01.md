**Root Cause:** The `doctl apps create-deployment` call returns HTTP 403 from DigitalOcean:

```
Error: POST https://api.digitalocean.com/v2/apps/3e161c0a-eebd-4970-aff3-b576cef3d370/deployments:
403 (request "4f317b5c-194f-4dde-acb0-9304827a4c9b") forbidden
```

The `doctl auth init` step succeeds (token is valid and authenticates), but the token lacks the **`app:create:deployment`** scope required to trigger a new deployment. This points to one of:

1. **Token expiry / rotation** — `DIGITALOCEAN_ACCESS_TOKEN` was regenerated with narrower scopes after the Aug 2 successful run
2. **DigitalOcean API scope change** — DO may have tightened App Platform deployment scopes in a recent API update
3. **Team permission change** — the token owner's DO account/team permissions were modified

**Impact:** Production app on DigitalOcean App Platform has not received a scheduled force-rebuild since **Aug 2, 2026**. Any dependency security patches, env var changes, or layer cache invalidations requiring a rebuild are not propagating.

**Action Required:**
1. Go to [DigitalOcean API Tokens](https://cloud.digitalocean.com/account/api/tokens) and verify the token assigned to `DIGITALOCEAN_ACCESS_TOKEN` has the `app` write scope
2. If expired or narrowed, generate a new token with full `app` scopes
3. Update the `DIGITALOCEAN_ACCESS_TOKEN` secret in [GitHub repository secrets](https://github.com/LOT-Systems/LOT-Computer/settings/secrets/actions)
4. Trigger the workflow manually via `workflow_dispatch` to verify the fix

## 5. Component Quality Review

### StatusPage.tsx — Improvements Applied This Session

The status page component had incorrect color semantics for a health-check UI:

| Issue | Before | After |
|---|---|---|
| OK status color | `text-acc` (accent — same as body text) | `text-green` (#5CB85C) |
| Error status color | `text-acc/60` (dimmed — less visible than ok) | `text-red` (#EE5959) |
| Status indicator | `✓` / `✕` text characters | Colored dot (8px filled circle) |
| Error message color | `text-acc/60` (always same dim tone) | `text-red/80` for errors, `text-acc/60` for info |
| Overall status display | Plain string | Dot + colored label (green/yellow-darker/red) |
| key prop in .map() | `index` (unstable) | `check.name` (stable, unique) |
| Memory status icons | `✓` / `✕` text characters | Dot system (consistent with checks) |
| Accessibility | No live region | `aria-live="polite"` on status container |

**Files changed:** `src/client/components/StatusPage.tsx`

These changes use only the existing Tailwind tokens (`green`, `red`, `yellow-darker`) already defined in `tailwind.config.js` — no config changes required.

### StatusPage Design Assessment — Alignment With Top-Tier Practice

The LOT Systems design system (minimal, text-forward, `acc` color tokens, 8px spacing grid) is intentional and distinctive. The improvements this session preserve that character while fixing functional issues:

- **Semantic color**: Status UIs must make state legible at a glance — green/red dots are industry standard (Atlassian Status Page, Cloudflare, GitHub Actions)
- **Stable keys**: React reconciliation correctness
- **aria-live**: Screen-reader users need to hear status updates without page reload
- **`overallBanner` helper**: Consolidates the overall-status logic into one readable place; the `degraded` state now gets the yellow color it deserves
