## GAP FOUND — SECTION 01 SIGNAL CLASS UNDRAMATIZED

v0.1's Section 01 named three trigger signal classes: badge unlock, memory
question ready, cohort resonance ping. Section 07's only use case (THE DESK
MIGRATION) covered the first two. "Cohort resonance ping" had a named
firmware trigger and no consumer scenario, and no priority rule governing
how it should behave relative to the operator's own signals. Both gaps are
closed this cycle — Section 09 (new) gives it a locked LOW-priority queue
position, and Section 07's new entry gives it a use case.

## DECISIONS LOCKED THIS CYCLE

```
1. Single edge-of-flight ToF sensor for v.0, not an array — v.0's motion
   envelope (in-place hop, forward-biased only) does not need multi-
   directional coverage yet; that's explicitly deferred to v.2 (Section 06,
   already on record) rather than over-built now.
2. No runtime/battery-life number promised for v.0 — cell capacity is
   whatever the <120g mass budget leaves over after shell + actuator +
   driver mass are fixed. Runtime tuning is named a v.1 output, not a v.0
   input requirement, to avoid a spec commitment the mass budget can't
   currently back.
3. Cohort pings are lowest priority in the firmware queue and are DROPPED,
   not delayed, if a higher-priority signal (the operator's own badge/
   memory event) arrives while one is queued. A stranger's resonance late
   and out of order with the operator's own news was judged worse than a
   dropped ping.
4. Radio link is short-range (BLE-class) to the operator's own session
   device, not a direct internet connection — keeps the cube's power draw
   and attack surface minimal; the session device is the signal relay, the
   charging pad remains the power source (Section 02, unchanged).
```
