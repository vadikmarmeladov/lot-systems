# QI·46 CORPUS — PHASE 0 STATE

Spec: `docs/corporate/LOT_QI46_ENGINE.md`, Section IV, Phase 0 — Corpus Assembly.

This directory is Layer 0 tooling and output, mapped from the spec's literal
`/corpus/` paths onto this repo's existing `docs/assembly/` self-assembly
folder (no competing top-level folder was created).

## What is here

- `schema/tagging-schema.json` — the Step 0.2 tagging schema, machine-readable.
- `lot-qi-46-v0.jsonl` — Step 0.3 output. One `{prompt, completion, tags}`
  record per source document, generated by `scripts/corpus/build-corpus.ts`.
- `corpus-manifest.json` — per-file breakdown, source/type counts, and the
  gap list below.

## What this build actually covers — and what it does not

`scripts/corpus/build-corpus.ts` only reads markdown/text files already
committed to this repository: LOT® white papers, vision docs, and brand-voice
specs under `docs/corporate/` and `docs/technical/`. That covers three of the
six Layer 0 sources the spec describes: **institute**, **brand**,
**bioelectric**.

It does **not** cover, and did not attempt to fabricate:

| Source | Why it's not here |
|---|---|
| `platform` | Subscriber journal entries and session logs live in the production PostgreSQL database. Not present in this repo; no DB access in this session. |
| `consumable` | Consumable feedback records (sock/toothbrush/Quantum Cube ratings) are subscriber-submitted production data. Not present in this repo. |
| `cosmo` | COSMO® event logs (detection → FAX → record) are runtime-generated production records. Not present in this repo. |

No placeholder or synthetic data was written for these three sources. They
are recorded as open gaps in `corpus-manifest.json` under `"gaps"`.

## Current corpus size vs. Checkpoint 0

The spec's Checkpoint 0 gate (Section IV) requires `Corpus size > 10,000
training pairs`. This build produced **14** training pairs from 14 real
source documents (~38,400 words). That is a real, honest count from real
files — and it is nowhere near the gate threshold, because the three
subscriber-data sources above are entirely absent from this build.

**Checkpoint 0 result: HOLD.** See the Phase 0 assembly log for the full gate
checklist and the reasoning. This is not a failure of this session's tooling
— it is the correct, expected outcome of running Phase 0 corpus assembly
from a code repository that does not contain production subscriber data.

## Every record is `cosmo_cleared: false`

No document in this corpus has been through a human (S-2) review pass yet.
The tagging schema defaults every emitted record to `cosmo_cleared: false`.
Per Step 0.2 of the spec, documents with `cosmo_cleared: false` are flagged
for Vadik review before inclusion in any actual fine-tuning run — none of
this corpus is training-ready until that review happens.

## Regenerating

```
npx tsx scripts/corpus/build-corpus.ts
```

Reads `docs/corporate/*.md` and `docs/technical/*.{md,txt}`, applies the
include-filter and tagging heuristics in the script, and rewrites
`lot-qi-46-v0.jsonl` and `corpus-manifest.json` in place.
