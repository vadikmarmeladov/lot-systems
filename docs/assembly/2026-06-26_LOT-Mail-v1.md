WHAT WAS BUILT
================================================================================

LOT Mail is a pure internal messaging system — no SMTP, no third-party relay.
Operators send mail to community members by name, from the Log, in one line.
The receiver sees it in Sync (unread badge) and reads it in the new Mail page.

COMMAND SYNTAX (in Log)
  /email to [Name] [message]
  Example: /email to Hitomi Good morning.

ARCHITECTURE
================================================================================

FLOW — SENDING
  1. Operator types /email to Hitomi Good morning in Log
  2. logTriggers.ts detects email-send trigger via /email keyword
  3. NoteEditor effect fires: parses recipientName=Hitomi, body=Good morning
  4. useSendLotEmail mutation fires: POST /api/lot-emails
  5. Server: finds User WHERE firstName ILIKE 'hitomi'
  6. Creates lot_email record in database
  7. sync.emit('lot_email', payload) — all connected SSE streams get it
  8. SSE switch case 'lot_email': filters to sender/receiver only — others skip
  9. Log entry created: lot_email_sent (sender) + lot_email_received (receiver)
  10. Response: { id, recipientName, createdAt }
  11. NoteEditor shows: MAIL SENT TO HITOMI in MAIL: block

FLOW — RECEIVING
  1. Receiver's SSE stream receives lot_email event
  2. app.tsx sync.listen('lot_email'): increments unreadMailCount store
  3. Layout NavButton Mail shows unread count badge
  4. Receiver navigates to /mail → unreadMailCount resets to 0
  5. Mail component loads inbox via GET /api/lot-emails/inbox
  6. Click an email → PUT /api/lot-emails/:id/read → readAt set

SYNC INTEGRATION
  — New mail appears in Sync implicitly: the unread badge on the Mail nav
    button is visible from any page including Sync
  — The lot_email SSE event is broadcast through the existing /api/sync stream
    that Sync.tsx and all pages already subscribe to via listenSSE in app.tsx

COHORT / COMMUNITY INTEGRATION
  — Recipients are matched by firstName (case-insensitive) from the Users table
  — All LOT community members (any user) can receive mail
  — Log events (lot_email_sent / lot_email_received) integrate with the
    existing Logs view: past-log section renders MAIL: blocks showing

  — Future: extend to Cohort Dating — send introductory mail to matched cohort

================================================================================
DESIGN DECISIONS
================================================================================

  Simplest possible        No threads, no attachments, no reply-to.
                           One command. One inbox. One tap to read.

  Name-based addressing    /email to Hitomi — no ID lookup, no @ notation.
                           Matches the personal, human feel of LOT.

  SSE-native delivery      Reuses existing /api/sync stream. No new WebSocket,
                           no polling. Receiver sees mail the instant it lands.

  Log-native sending       The /email command lives in the Log, alongside /qi,
                           /prayer, /scan. Fits the LOT operator mental model.

  Internal only            No SMTP. No external mail relay. Pure LOT network.
                           Privacy-first: messages never leave the system.

DATABASE
================================================================================

TABLE: lot_emails
  id          UUID PRIMARY KEY
  senderId    UUID FK users.id CASCADE DELETE
  receiverId  UUID FK users.id CASCADE DELETE
  subject     VARCHAR(300) NULLABLE
  body        TEXT NOT NULL
  readAt      TIMESTAMP NULLABLE
  createdAt   TIMESTAMP
  updatedAt   TIMESTAMP

INDEXES:
  (receiverId, createdAt) — inbox query
  (senderId, createdAt)   — sent query

================================================================================
API SURFACE
================================================================================

  GET  /api/lot-emails/inbox       — Returns received emails with senderName
  GET  /api/lot-emails/sent        — Returns sent emails with receiverName
  POST /api/lot-emails             — Send mail {recipientName, body, subject?}
  PUT  /api/lot-emails/:id/read    — Mark email read (receiver only)

All routes are authenticated (require valid session cookie).
