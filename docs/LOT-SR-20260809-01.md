## DESIGN

```
LOT Email is not a new subsystem — it is a naming layer over three systems that
already existed and already worked:

  1. Cohort Dating (useCohorts / CohortConnectWidget) resolves a first name
     typed after "/email to" to a real cohort match's user id.
  2. Direct Messages (useSendDirectMessage → POST /api/direct-messages) sends
     the log body as the email payload. No new table, no new endpoint.
  3. Sync (LOT Chat) gains a live "Email:" block that listens to the exact same
     'direct_message' SSE broadcast Direct Messages already emit, filtered to
     the current user as sender or receiver.

Zero new backend endpoints. Zero schema migrations. One enrichment to an
existing SSE payload (receiverName, symmetric with the existing senderName)
so a single broadcast event renders correctly on both sides of the
conversation without a second round-trip.
```

## USAGE

```
1. Operator types in Log:  /email to Hitomi Let's sync tomorrow at 9.
2. logTriggers detects the 'email-mode' keyword the instant it appears.
3. NoteEditor resolves "Hitomi" against the operator's live Cohort Dating
   matches (LOT Community). No match with that first name → inline
   EMAIL FAILED — NO COHORT MATCH NAMED "HITOMI" block, nothing sent.
4. Match found → the log body ("Let's sync tomorrow at 9.") is sent as a
   Direct Message to that cohort member. Log shows:
     TO              HITOMI
     STATUS          SENT · VIA LOT COMMUNITY
     ROUTED          SYNC
5. The same event lands in Sync for both parties in real time:
     → Hitomi   Let's sync tomorrow at 9.        (operator's Sync)
     ← [Sender] Let's sync tomorrow at 9.         (Hitomi's Sync)
```
