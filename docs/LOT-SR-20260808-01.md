   internally invoking analyzeIntentions() (125-pattern scan) synchronously
   on every logs reference change.
2. intentionEngine.ts:258+ analyzeIntentions() runs dozens of .filter()
   passes over the full signal array — O(n × patterns); deferHeavy at most
   call sites, but not at #1 above.
3. SystemProgressWidget.tsx:1554-1564 — recomputeAssembly() +
   analyzeIntentions() both run on every mount and every 60s tick.
4. MicroGameWidget.tsx:832-842 — playMoveSound/playRotateSound/
   playDropSound fire synchronously inside keydown handlers; AudioContext
   resume could add input latency.
5. PatternRecognitionWidget.tsx:55-57 — comment documents a previously
   fixed footgun (JSON.parse(localStorage) on every recordSignal); other
   mounted-but-hidden widgets were not individually re-audited for the same
   pattern this session.
6. System.tsx:200 — astrologyTick interval gated only by !document.hidden,
   unlike SystemProgressWidget's stronger !isRouteActive('system') gate —
   can still tick while user is on a different in-app tab.
7. MonthlyPulseWidget.tsx:45-59 — synchronous localStorage reads in the
   render path; cheap today, a pattern to watch if reused elsewhere.
8. No React.memo on any of the ~50 widgets rendered in System.tsx — all
   re-render on every System.tsx state change (logs, quantumState,
   astrologyTick) since none are split into memoized boundaries.

None of these were touched this session — surfaced for a follow-up
ENGINEERING benchmark, since fixing render-path hot loops without a live
